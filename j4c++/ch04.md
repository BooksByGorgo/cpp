# Control Flow

If you can write a `for` loop and an `if` statement in C++, you already know most of Java's control flow.
Java's basic control structures came from C, and so did C++'s, so the syntax is nearly identical.
The important differences are a tightened `boolean` requirement (no more `if (x)` where `x` is an `int`) and a significantly upgraded `switch` that goes well beyond what C++ offers.
This chapter covers all of it, including the labeled `break` and `continue` that replace the `goto` Java deliberately left out.

## `if`, `while`, `do-while`, and `for`

\index{if}
\index{while}
\index{do-while}
\index{for}

The syntax is the same as C++.
The one important difference: **the condition must be `boolean`**.
Java's compiler rejects any condition that is not of type `boolean` or `Boolean`.

```java
int x = 1;
if (x)      { } // compile error: int is not boolean
if (x != 0) { } // fine
```

This eliminates an entire class of C++ bugs where an assignment sneaks into a condition:

```java
if (x = 5) { }  // compile error in Java -- assignment is int, not boolean
```

In C++ that would compile and always be true, a classic typo.
In Java the compiler stops you cold.

Everything else works exactly as you expect:

```java
// under the bridge, downtown    -- Red Hot Chili Peppers (1992)
String[] words = {"under", "the", "bridge", "downtown"};

// classic for loop
for (int i = 0; i < words.length; i++) {
    System.out.println(words[i]);
}

// while loop
int i = 0;
while (i < words.length) {
    System.out.println(words[i++]);
}

// do-while
int j = 0;
do {
    System.out.println(words[j++]);
} while (j < words.length);
```

### For-Each

\index{for-each}
\index{enhanced for}

Java's **enhanced for loop** (for-each) iterates over arrays and any class that implements `Iterable<T>`:

```java
for (String word : words) {
    System.out.println(word);
}
```

This is equivalent to C++ range-based `for`:

```cpp
// C++
for (const auto& word : words) {
    std::cout << word << "\n";
}
```

You cannot get the index inside an enhanced for without maintaining a counter yourself.
When you need the index, use the classic indexed `for`.

::: {.tip}
**Tip:** Prefer the enhanced for loop when you only need the elements, not the indices.
It is cleaner, avoids off-by-one errors, and works uniformly on arrays, `List`, `Set`, and any other `Iterable`.
:::

## `break` and `continue`

\index{break}
\index{continue}

`break` and `continue` work identically to C++.
`break` exits the innermost enclosing loop or `switch`.
`continue` skips the rest of the current loop body and moves to the next iteration.

### Labeled `break` and `continue`

\index{break!labeled}
\index{continue!labeled}
\index{label}

Java has no `goto`.
It is a reserved word that the compiler will reject --- it exists purely to prevent you from using it as an identifier.
The use cases where C programmers reach for `goto` (breaking out of nested loops, for example) are served by **labeled `break`** and **labeled `continue`**.

A label is an identifier followed by a colon, placed before the statement it names.

```java
outer:
for (int row = 0; row < 4; row++) {
    for (int col = 0; col < 4; col++) {
        if (row == 2 && col == 2) {
            break outer;    // exits both loops, not just the inner one
        }
        System.out.printf("[%d,%d] ", row, col);
    }
}
System.out.println("\ndone");
```

Output:

```
[0,0] [0,1] [0,2] [0,3] [1,0] [1,1] [1,2] [1,3] [2,0] [2,1]
done
```

`continue outer` would skip the rest of the inner loop body and jump to the next iteration of the outer loop.

::: {.tip}
**Tip:** Labeled `break` is not `goto`.
The label must name an enclosing statement --- you cannot jump to an arbitrary location in the code.
Think of it as a named "break this specific loop" rather than a free-form jump.
:::

## `switch` Statements

\index{switch statement}

Java's traditional `switch` statement looks and behaves exactly like C++'s --- including fall-through.

```java
int month = 4;
switch (month) {
    case 1:
    case 3:
    case 5:
    case 7:
    case 8:
    case 10:
    case 12:
        System.out.println("31 days");
        break;
    case 4:
    case 6:
    case 9:
    case 11:
        System.out.println("30 days");
        break;
    case 2:
        System.out.println("28 or 29 days");
        break;
    default:
        System.out.println("invalid month");
}
```

Java extends the set of types you can switch on beyond what C++ allows:

- `byte`, `short`, `int`, `char` (and their wrapper classes since Java 5)
- `String` (Java 7+)
- `enum` types

You cannot switch on `long`, `float`, or `double`.

::: {.tip}
**Trap:** Fall-through is the default in both Java and C++ `switch` statements.
A missing `break` is a silent bug.
If you intend to fall through, add a `// fallthrough` comment so it is clear it is deliberate.
:::

## `switch` Expressions (Java 14+)

\index{switch expression}
\index{yield}

Java 14 introduced **switch expressions**, a substantial improvement over the traditional statement.
A switch expression can **return a value** and uses `->` arrow arms that **do not fall through**.

```java
int month = 4;
int days = switch (month) {
    case 1, 3, 5, 7, 8, 10, 12 -> 31;
    case 4, 6, 9, 11            -> 30;
    case 2                      -> 28; // ignoring leap years for brevity
    default -> throw new IllegalArgumentException("Invalid month: " + month);
};
System.out.println(days); // 30
```

The arrow `->` separates the case label from the result.
No `break` needed.
Multiple labels are comma-separated.

### `yield` for Block Arms

\index{yield}

When an arm needs more than one statement, use a block with `yield` to produce the value:

```java
String season = switch (month) {
    case 12, 1, 2 -> "Winter";
    case 3, 4, 5  -> "Spring";
    case 6, 7, 8  -> "Summer";
    case 9, 10, 11 -> {
        System.out.println("Autumn arm reached");
        yield "Autumn";       // like return, but for switch expressions
    }
    default -> throw new IllegalArgumentException("month: " + month);
};
```

`yield` is to a switch expression what `return` is to a method.
You cannot use `return` inside a switch expression arm; you must use `yield`.

### Before and After: Traditional vs Expression

Here is the same logic written both ways, to make the improvement concrete.

**Traditional statement (before Java 14):**

```java
String rating;
int score = 87;
switch (score / 10) {
    case 10:
    case 9:
        rating = "A";
        break;
    case 8:
        rating = "B";
        break;
    case 7:
        rating = "C";
        break;
    default:
        rating = "F";
        break;
}
```

**Switch expression (Java 14+):**

```java
int score = 87;
String rating = switch (score / 10) {
    case 10, 9 -> "A";
    case 8     -> "B";
    case 7     -> "C";
    default    -> "F";
};
```

The expression form is shorter, has no fall-through risk, and makes `rating` effectively final (it must be assigned exactly once).
The compiler also enforces **exhaustiveness**: if the switch does not cover every possible input (or include a `default`), it will not compile.

::: {.tip}
**Tip:** Prefer `switch` expressions over `switch` statements whenever you are computing a value.
The arrow syntax eliminates fall-through bugs, and the compiler's exhaustiveness check catches missing cases at compile time.
:::

::: {.tip}
**Wut:** Pattern matching in `switch` --- matching on types, not just values --- is available starting in Java 21.
We will cover it in Ch 17 alongside sealed classes.
:::

## Key Points

- `if`, `while`, `do-while`, and `for` are syntactically identical to C++, with one key difference: **the condition must be of type `boolean`**; there is no implicit conversion from `int`.
- The enhanced for-each loop (`for (Type item : collection)`) works on arrays and any `Iterable<T>`.
- `break` and `continue` work as in C++; **labeled** versions (`break label;`, `continue label;`) provide the "break out of nested loops" pattern that replaces `goto`.
- Java has no `goto` --- it is a reserved word that cannot be used.
- Traditional `switch` statements support `int`, `char`, `String`, and `enum`; fall-through is the default just as in C++.
- **Switch expressions** (Java 14+) return a value, use comma-separated labels, arrow `->` arms that do not fall through, and `yield` for block arms.
- Switch expressions are exhaustiveness-checked by the compiler --- a missing `default` on a non-`enum` switch is a compile error.
- Pattern matching in `switch` is covered in Ch 17.
