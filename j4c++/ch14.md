# The Stream API

Chapter 13 introduced lambdas and the functional interfaces that give them types.
Now you have the tools to use the Stream API, which puts those interfaces to work at scale.
A stream lets you express a multi-step data transformation as a readable pipeline of operations --- filter, map, sort, collect --- without writing a single loop.
If you have used C++20 ranges, you will recognize the pipeline model.
If you are coming from `std::transform` and `std::copy_if`, streams are the same idea packaged into a chainable API.

## The Pipeline Model

\index{stream}
\index{stream!pipeline}

Every stream pipeline has three parts:

1. **Source** --- where the data comes from (a collection, an array, a generator, etc.)
2. **Intermediate operations** --- lazy transformations that return a new stream
3. **Terminal operation** --- triggers execution and produces a result

```java
List<String> songs = List.of("Good Riddance", "Basket Case", "When I Come Around",
                              "Brain Stew", "Minority");

long count = songs.stream()                     // 1. source
    .filter(s -> s.length() > 10)              // 2. intermediate -- lazy
    .map(String::toUpperCase)                  // 2. intermediate -- lazy
    .count();                                  // 3. terminal -- triggers execution

System.out.println(count);   // 3
```

The intermediate operations do **nothing** until a terminal operation is reached.
The JVM builds the pipeline and then evaluates it in one pass over the data --- it does not create a full intermediate list between each step.
This is the same lazy evaluation model as C++20 ranges (`std::views::filter | std::views::transform`).

::: {.tip}
**Trap:** A stream can only be consumed once.
After a terminal operation runs, the stream is exhausted.
Calling any method on an exhausted stream throws `IllegalStateException`.
This differs from C++ ranges, which are reusable because they are views over the underlying data.

```java
Stream<String> s = songs.stream().filter(x -> x.length() > 5);
s.count();   // OK -- terminal op consumes the stream
s.count();   // IllegalStateException -- stream already consumed
```
:::

## Creating Streams

\index{stream!sources}

`Collection.stream()` is the most common source, but streams can come from many places.

```java
// from a Collection
List<String> list = List.of("Good Riddance", "Time of Your Life");
Stream<String> fromList = list.stream();

// from an array
String[] arr = {"Good Riddance", "Basket Case"};
Stream<String> fromArray = Arrays.stream(arr);

// from explicit values
Stream<String> fromOf = Stream.of("Good Riddance", "Minority");

// infinite stream -- generates values on demand
Stream<String> gen = Stream.generate(() -> "hey ho");   // infinite!

// infinite stream with a seed and a step function
Stream<Integer> years = Stream.iterate(1991, y -> y + 1); // 1991, 1992, ...

// integer range (no boxing)
IntStream range = IntStream.range(0, 10);           // 0..9
IntStream rangeClosed = IntStream.rangeClosed(1, 5); // 1..5

// lines of a text file
// Stream<String> lines = Files.lines(Path.of("lyrics.txt"));
```

::: {.tip}
**Trap:** `Stream.generate` and `Stream.iterate` produce infinite streams.
Always pair them with a `limit()` or a two-argument `Stream.iterate` overload that takes a predicate (Java 9+): `Stream.iterate(1991, y -> y <= 1999, y -> y + 1)`.
:::

## Intermediate Operations

\index{stream!intermediate operations}

Intermediate operations are lazy --- they describe *what to do* but do not do it until a terminal operation asks for results.
All of them return a `Stream` (or a primitive stream), so you can chain them.

### `filter`

\index{stream!filter@\texttt{filter()}}

Signature: `Stream<T> filter(Predicate<? super T> predicate)`

Keeps only the elements for which the predicate returns `true`.

```java
List<String> nineties = List.of("Good Riddance", "Waterfalls", "Creep",
                                 "Zombie", "No Scrubs");
nineties.stream()
    .filter(s -> s.startsWith("W"))
    .forEach(System.out::println);
// Waterfalls
```

### `map`

\index{stream!map@\texttt{map()}}

Signature: `<R> Stream<R> map(Function<? super T, ? extends R> mapper)`

Transforms each element from type `T` to type `R`.

```java
nineties.stream()
    .map(String::length)
    .forEach(System.out::println);
// 12  9  5  6  9
```

### `flatMap`

\index{stream!flatMap@\texttt{flatMap()}}

Signature: `<R> Stream<R> flatMap(Function<? super T, ? extends Stream<? extends R>> mapper)`

Maps each element to a stream of results, then flattens all those streams into one.
Use it whenever your mapping function produces a collection or stream for each element.

```java
List<String> lyrics = List.of("Good Riddance", "Time of Your Life");
lyrics.stream()
    .flatMap(line -> Arrays.stream(line.split(" ")))
    .forEach(System.out::println);
// Good  Riddance  Time  of  Your  Life
```

The equivalent in C++ would be a `std::ranges::join` view applied after `std::views::transform`.

### `distinct`, `sorted`, `limit`, `skip`

\index{stream!distinct@\texttt{distinct()}}
\index{stream!sorted@\texttt{sorted()}}
\index{stream!limit@\texttt{limit()}}
\index{stream!skip@\texttt{skip()}}

- `Stream<T> distinct()` --- removes duplicates using `equals`
- `Stream<T> sorted()` --- sorts using natural order (`Comparable`)
- `Stream<T> sorted(Comparator<? super T> comparator)` --- sorts using a comparator
- `Stream<T> limit(long maxSize)` --- truncates the stream to at most `maxSize` elements
- `Stream<T> skip(long n)` --- discards the first `n` elements

```java
Stream.of(1997, 1994, 1997, 1991, 1994)
    .distinct()
    .sorted()
    .forEach(System.out::println);
// 1991  1994  1997
```

### `peek`

\index{stream!peek@\texttt{peek()}}

Signature: `Stream<T> peek(Consumer<? super T> action)`

Applies a consumer to each element as it flows through, without consuming the stream.
Handy for debugging a pipeline without changing it.

```java
nineties.stream()
    .peek(s -> System.out.println("before: " + s))
    .filter(s -> s.length() > 5)
    .peek(s -> System.out.println("after:  " + s))
    .count();
```

::: {.tip}
**Trap:** Do not use `peek` for production side effects --- it is intended for debugging.
Lazy evaluation means `peek` may not be called in the order or frequency you expect if the terminal operation short-circuits.
:::

## Terminal Operations

\index{stream!terminal operations}

Terminal operations trigger the pipeline.
Once one runs, the stream is done.

### `forEach`

\index{stream!forEach@\texttt{forEach()}}

Signature: `void forEach(Consumer<? super T> action)`

Applies the consumer to each element.
This is the most direct replacement for a `for` loop.

```java
nineties.stream()
    .filter(s -> s.length() > 5)
    .forEach(System.out::println);
```

### `collect`

\index{stream!collect@\texttt{collect()}}

Signature: `<R, A> R collect(Collector<? super T, A, R> collector)`

Accumulates elements into a mutable container --- usually a collection.
Collectors are covered in their own section below.

### `count`, `min`, `max`

\index{stream!count@\texttt{count()}}
\index{stream!min@\texttt{min()}}
\index{stream!max@\texttt{max()}}

- `long count()` --- returns the number of elements
- `Optional<T> min(Comparator<? super T> comparator)` --- smallest element, or empty if stream was empty
- `Optional<T> max(Comparator<? super T> comparator)` --- largest element, or empty if stream was empty

`min` and `max` return `Optional<T>` because the stream might be empty.
`Optional` is covered in Chapter 15.

### `findFirst` and `findAny`

\index{stream!findFirst@\texttt{findFirst()}}
\index{stream!findAny@\texttt{findAny()}}

- `Optional<T> findFirst()` --- first element in encounter order
- `Optional<T> findAny()` --- any element (may return different results on parallel streams)

```java
Optional<String> first = nineties.stream()
    .filter(s -> s.startsWith("W"))
    .findFirst();
first.ifPresent(System.out::println);   // Waterfalls
```

### `anyMatch`, `allMatch`, `noneMatch`

\index{stream!anyMatch@\texttt{anyMatch()}}
\index{stream!allMatch@\texttt{allMatch()}}
\index{stream!noneMatch@\texttt{noneMatch()}}

- `boolean anyMatch(Predicate<? super T> predicate)` --- true if any element matches
- `boolean allMatch(Predicate<? super T> predicate)` --- true if all elements match
- `boolean noneMatch(Predicate<? super T> predicate)` --- true if no elements match

All three short-circuit --- they stop as soon as the answer is known.

```java
boolean anyLong = nineties.stream().anyMatch(s -> s.length() > 10);
System.out.println(anyLong);   // true ("Good Riddance" has 12 chars)
```

### `reduce`

\index{stream!reduce@\texttt{reduce()}}

Signature: `T reduce(T identity, BinaryOperator<T> accumulator)`

Folds the elements into a single value.
The identity is the starting value and the neutral element for the operation (0 for addition, 1 for multiplication, `""` for string concatenation).

```java
int totalLength = nineties.stream()
    .mapToInt(String::length)
    .sum();   // primitive stream has sum() directly; see Primitive Streams below

// equivalent with reduce on boxed stream
int total = nineties.stream()
    .map(String::length)
    .reduce(0, Integer::sum);
System.out.println(total);   // 41
```

A one-argument overload `Optional<T> reduce(BinaryOperator<T> accumulator)` exists for when there is no identity value --- it returns `Optional<T>` because the stream might be empty.

### `toList` (Java 16+)

\index{stream!toList@\texttt{toList()}}

Signature: `List<T> toList()`

A convenient shortcut for the common case of collecting into an unmodifiable list.
It is equivalent to `collect(Collectors.toUnmodifiableList())`.

```java
List<String> longTitles = nineties.stream()
    .filter(s -> s.length() > 5)
    .toList();  // unmodifiable List
```

## Collectors

\index{Collectors@\texttt{Collectors}}

The `java.util.stream.Collectors` class provides factory methods for the most common `Collector` implementations.

### Collecting into Collections

```java
import java.util.stream.Collectors;

List<String>  asList  = nineties.stream().collect(Collectors.toList());
Set<String>   asSet   = nineties.stream().collect(Collectors.toSet());
List<String>  asUnmod = nineties.stream().collect(Collectors.toUnmodifiableList());
```

### `joining`

\index{Collectors!joining@\texttt{joining()}}

Signature (most useful overload): `Collector<CharSequence, ?, String> joining(CharSequence delimiter)`

Concatenates strings with a delimiter.
Overloads also accept a prefix and suffix.

```java
String joined = nineties.stream()
    .collect(Collectors.joining(", "));
System.out.println(joined);
// Good Riddance, Waterfalls, Creep, Zombie, No Scrubs
```

### `groupingBy`

\index{Collectors!groupingBy@\texttt{groupingBy()}}

Signature: `Collector<T, ?, Map<K, List<T>>> groupingBy(Function<? super T, ? extends K> classifier)`

Groups elements into a `Map<K, List<T>>` by the value of the classifier function.

```java
Map<Integer, List<String>> byLength = nineties.stream()
    .collect(Collectors.groupingBy(String::length));
byLength.forEach((len, titles) ->
    System.out.println(len + " -> " + titles));
// 5 -> [Creep]
// 6 -> [Zombie]
// 9 -> [Waterfalls, No Scrubs]
// 12 -> [Good Riddance]
```

A second overload accepts a downstream collector to apply within each group:
`groupingBy(classifier, Collectors.counting())` gives you a `Map<K, Long>` of counts instead of lists.

### `toMap`

\index{Collectors!toMap@\texttt{toMap()}}

Signature: `Collector<T, ?, Map<K, U>> toMap(Function<? super T, ? extends K> keyMapper, Function<? super T, ? extends U> valueMapper)`

Builds a `Map` from a stream.

```java
Map<String, Integer> titleToLength = nineties.stream()
    .collect(Collectors.toMap(s -> s, String::length));
```

::: {.tip}
**Trap:** `toMap` throws `IllegalStateException` if two elements produce the same key.
Supply a merge function as the third argument when duplicates are possible:
`Collectors.toMap(keyMapper, valueMapper, (existing, replacement) -> existing)`.
:::

### `counting` and `summingInt`

\index{Collectors!counting@\texttt{counting()}}
\index{Collectors!summingInt@\texttt{summingInt()}}

- `Collector<T, ?, Long> counting()` --- counts elements; useful as a downstream collector in `groupingBy`
- `Collector<T, ?, Integer> summingInt(ToIntFunction<? super T> mapper)` --- sums an int-valued property

```java
Map<Integer, Long> countByLength = nineties.stream()
    .collect(Collectors.groupingBy(String::length, Collectors.counting()));
```

## Primitive Streams

\index{IntStream@\texttt{IntStream}}
\index{LongStream@\texttt{LongStream}}
\index{DoubleStream@\texttt{DoubleStream}}

A `Stream<Integer>` autoboxes every `int` to an `Integer` object.
For numerical work, use `IntStream`, `LongStream`, or `DoubleStream` instead.

```java
int sum = IntStream.rangeClosed(1, 100).sum();      // 5050 -- no boxing
double avg = IntStream.of(90, 95, 88, 92)
    .average()
    .orElse(0.0);
System.out.println(avg);   // 91.25
```

Primitive streams add extra terminal operations that make no sense on object streams: `sum()`, `average()`, `summaryStatistics()`.

Convert between object streams and primitive streams with:
- `Stream<T>.mapToInt(ToIntFunction<T>)` --- object stream to `IntStream`
- `IntStream.mapToObj(IntFunction<R>)` --- `IntStream` to `Stream<R>`
- `IntStream.boxed()` --- `IntStream` to `Stream<Integer>`

## Parallel Streams

\index{parallel stream}
\index{stream!parallel}

Every sequential stream can be made parallel by calling `.parallel()`.
Collections also expose `.parallelStream()` directly.

```java
long count = songs.parallelStream()
    .filter(s -> s.length() > 8)
    .count();
```

Under the hood, parallel streams use the fork-join common pool.
They split the data, process chunks on multiple threads, and merge the results.

When parallel streams help:
- CPU-bound operations on large collections (thousands of elements or more)
- Operations with no shared mutable state

When parallel streams hurt or are wrong:
- Small collections --- the overhead of splitting and merging exceeds the gain
- Operations with ordering requirements --- `findFirst` may behave differently; `forEachOrdered` preserves order but defeats parallelism
- Any shared mutable state --- two threads writing to the same list is a data race, exactly as in C++

::: {.tip}
**Trap:** Shared mutable state in a parallel stream is a data race.
The lambda in `forEach` must be stateless.
Do not accumulate into a non-thread-safe collection from a parallel stream --- use `collect` with a thread-safe `Collector` instead, which is safe because `Collector` manages its own per-thread accumulators.
:::

::: {.tip}
**Tip:** Profile before reaching for parallel streams.
Sequential streams with good algorithms often outperform parallel streams on real-world data sizes.
The JIT compiler is very good at optimizing tight sequential loops.
:::

## A Complete Pipeline Example

```java
import java.util.*;
import java.util.stream.*;

public class StreamDemo {
    record Song(String title, String artist, int year) {}

    public static void main(String[] args) {
        List<Song> songs = List.of(
            new Song("Good Riddance",    "Green Day",  1997),
            new Song("Waterfalls",       "TLC",        1995),
            new Song("Creep",            "Radiohead",  1992),
            new Song("Zombie",           "The Cranberries", 1993),
            new Song("No Scrubs",        "TLC",        1999)
        );

        // group by artist, collect titles
        Map<String, List<String>> byArtist = songs.stream()
            .collect(Collectors.groupingBy(
                Song::artist,
                Collectors.mapping(Song::title, Collectors.toList())
            ));

        byArtist.forEach((artist, titles) ->
            System.out.println(artist + ": " + String.join(", ", titles)));

        // top 3 longest titles
        songs.stream()
            .sorted(Comparator.comparingInt((Song s) -> s.title().length()).reversed())
            .limit(3)
            .map(Song::title)
            .forEach(System.out::println);
    }
}
```

## Key Points

- A stream pipeline has three parts: a **source**, zero or more lazy **intermediate operations**, and one **terminal operation** that triggers execution.
- Streams are **not reusable** --- once consumed by a terminal operation, they are exhausted; attempting to reuse one throws `IllegalStateException`.
- Common sources: `collection.stream()`, `Arrays.stream(array)`, `Stream.of(...)`, `Stream.generate(Supplier)`, `Stream.iterate(seed, fn)`, `IntStream.range(start, end)`.
- Common intermediate operations: `filter`, `map`, `flatMap`, `distinct`, `sorted`, `limit`, `skip`, `peek`.
- Common terminal operations: `collect`, `forEach`, `count`, `findFirst`, `findAny`, `anyMatch`, `allMatch`, `noneMatch`, `reduce`, `toList()`.
- `Collectors` provides ready-made accumulators: `toList()`, `toSet()`, `joining()`, `groupingBy()`, `toMap()`, `counting()`, `summingInt()`.
- Use `IntStream`, `LongStream`, `DoubleStream` for numerical work to avoid autoboxing overhead; they add `sum()`, `average()`, and `summaryStatistics()`.
- Parallel streams split work across the fork-join pool; they help for CPU-bound work on large collections with no shared mutable state, and hurt everywhere else.
