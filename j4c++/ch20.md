# I/O

C++ gives you POSIX `open`/`read`/`write`, `fstream`, and `iostream` --- three different levels of abstraction for the same job.
Java's story is similar: a classic stream hierarchy built in the early days (Java 1.0), a newer character-stream layer added in Java 1.1, and a high-performance NIO layer added in Java 1.4 and extended significantly in Java 7.
All of them are `AutoCloseable`, which means the try-with-resources idiom (covered in Chapter 12) is not just recommended --- it is the correct way to use I/O in Java.
This chapter walks through all three layers and shows the modern idioms that replace most of the boilerplate.

## The I/O Class Hierarchy

\index{I/O!hierarchy}
\index{InputStream@\texttt{InputStream}}
\index{OutputStream@\texttt{OutputStream}}
\index{Reader@\texttt{Reader}}
\index{Writer@\texttt{Writer}}

Java's I/O library is split into two parallel hierarchies that live in `java.io`.

The **byte stream** hierarchy handles raw binary data:

- `InputStream` --- abstract base for reading bytes
- `OutputStream` --- abstract base for writing bytes

The **character stream** hierarchy handles text:

- `Reader` --- abstract base for reading characters
- `Writer` --- abstract base for writing characters

This split maps directly to a problem you have hit in C++: when you use `fread` you get raw bytes; when you use `fstream` with `wchar_t` or `codecvt` you have to manage encoding yourself.
Java's character streams handle encoding transparently --- a `FileReader` decodes bytes from disk into Java `char` values using a specified (or platform-default) charset.

Every class in both hierarchies implements `AutoCloseable`, so they work with try-with-resources.

::: {.tip}
**Trap:** Using the platform-default charset --- which is what you get if you do not specify one --- makes your code behave differently on different machines.
Always specify `StandardCharsets.UTF_8` or whichever encoding your data actually uses.
:::

The following table maps the most common C++ I/O types to their Java equivalents:

| C++ | Java | Notes |
|:---|:---|:---|
| `fread` / `fwrite` | `FileInputStream` / `FileOutputStream` | raw bytes |
| `std::ifstream` | `FileReader` + `BufferedReader` | character text |
| `std::ofstream` | `FileWriter` + `BufferedWriter` | character text |
| `std::ios::binary` | `FileInputStream` / `FileOutputStream` | always binary in Java byte streams |
| `std::filesystem::path` | `java.nio.file.Path` | path manipulation |
| `std::filesystem::*` | `java.nio.file.Files` | filesystem operations |

## Classic Byte Streams

\index{FileInputStream@\texttt{FileInputStream}}
\index{FileOutputStream@\texttt{FileOutputStream}}
\index{BufferedInputStream@\texttt{BufferedInputStream}}
\index{BufferedOutputStream@\texttt{BufferedOutputStream}}

### Reading: `FileInputStream`

`FileInputStream` opens a file for reading raw bytes.
Its two most useful constructors are:

```java
FileInputStream(String name) throws FileNotFoundException
FileInputStream(File file)   throws FileNotFoundException
```

Once open, the primary read methods are:

```java
int read() throws IOException
int read(byte[] buf) throws IOException
int read(byte[] buf, int off, int len) throws IOException
```

`read()` returns the next byte as an `int` in the range 0--255, or `-1` at end of file.
This is identical to POSIX `read(fd, buf, 1)` returning 0 at EOF --- except Java encodes EOF as `-1` instead of a zero-length read.
`read(byte[] buf)` reads up to `buf.length` bytes and returns the number of bytes actually read, or `-1` at EOF.

### Writing: `FileOutputStream`

```java
FileOutputStream(String name)                    throws FileNotFoundException
FileOutputStream(String name, boolean append)    throws FileNotFoundException
FileOutputStream(File file)                      throws FileNotFoundException
FileOutputStream(File file,   boolean append)    throws FileNotFoundException
```

The `append` parameter works exactly like `O_APPEND` in POSIX `open` flags.
The write methods are:

```java
void write(int b)             throws IOException
void write(byte[] buf)        throws IOException
void write(byte[] buf, int off, int len) throws IOException
```

### Wrapping with Buffers

Unbuffered byte streams issue a system call for every read or write, just like calling POSIX `read(fd, buf, 1)` in a loop.
Always wrap with `BufferedInputStream` or `BufferedOutputStream`:

```java
BufferedInputStream(InputStream in)
BufferedInputStream(InputStream in, int size)

BufferedOutputStream(OutputStream out)
BufferedOutputStream(OutputStream out, int size)
```

```java
// Copy "I Want It That Way" lyrics file, buffered
try (var in  = new BufferedInputStream(new FileInputStream("lyrics.bin"));
     var out = new BufferedOutputStream(new FileOutputStream("copy.bin"))) {
    byte[] buf = new byte[8192];
    int n;
    while ((n = in.read(buf)) != -1) {
        out.write(buf, 0, n);
    }
}
```

The outer `try-with-resources` closes both streams in reverse order automatically, even if an exception is thrown --- `out` is closed first, then `in`.

::: {.tip}
**Tip:** The default buffer size is 8 KB, which is reasonable for most workloads.
For large sequential reads (log files, media) you can pass a larger size like `65536` to the constructor.
:::

## Classic Character Streams

\index{FileReader@\texttt{FileReader}}
\index{FileWriter@\texttt{FileWriter}}
\index{BufferedReader@\texttt{BufferedReader}}
\index{BufferedWriter@\texttt{BufferedWriter}}
\index{PrintWriter@\texttt{PrintWriter}}

### `FileReader` and `FileWriter`

`FileReader` reads characters from a file; `FileWriter` writes them.
Constructors:

```java
FileReader(String fileName)                throws FileNotFoundException
FileReader(File file)                      throws FileNotFoundException
FileReader(String fileName, Charset cs)    throws IOException     // Java 11+
FileReader(File file,       Charset cs)    throws IOException     // Java 11+

FileWriter(String fileName)                throws IOException
FileWriter(String fileName, boolean append) throws IOException
FileWriter(File file)                      throws IOException
FileWriter(File file,       boolean append) throws IOException
FileWriter(String fileName, Charset cs)    throws IOException     // Java 11+
```

The pre-Java-11 constructors use the platform default charset --- the Java 11+ constructors let you specify one.

### `BufferedReader`

\index{BufferedReader!readLine@\texttt{readLine()}}

Wrapping a `Reader` in a `BufferedReader` adds the most useful method in the character-stream world:

```java
String readLine() throws IOException
```

`readLine()` reads one line of text, stripping the line terminator, and returns `null` at end of file --- not `-1`.
If you have ever written `while ((line = getline(...)) != EOF)` in C, this is the same pattern with `null` as the sentinel.

```java
try (var br = new BufferedReader(new FileReader("playlist.txt",
                                                StandardCharsets.UTF_8))) {
    String line;
    while ((line = br.readLine()) != null) {
        System.out.println(line);
    }
}
```

### `BufferedWriter` and `PrintWriter`

\index{BufferedWriter!newLine@\texttt{newLine()}}
\index{PrintWriter@\texttt{PrintWriter}}

`BufferedWriter` adds one method over a plain `Writer`:

```java
void newLine() throws IOException
```

`newLine()` writes the platform line separator (`\r\n` on Windows, `\n` on Unix) --- useful when you need portable output.

`PrintWriter` wraps any `Writer` and adds the familiar `print`, `println`, and `printf` methods.
Its constructor:

```java
PrintWriter(Writer out)
PrintWriter(OutputStream out)
PrintWriter(String fileName) throws FileNotFoundException
PrintWriter(File file)       throws FileNotFoundException
```

```java
try (var pw = new PrintWriter(new BufferedWriter(
        new FileWriter("setlist.txt", StandardCharsets.UTF_8)))) {
    pw.println("Wannabe");   // Spice Girls, 1996
    pw.printf("Year: %d%n", 1996);
}
```

::: {.tip}
**Wut:** `PrintWriter` does not throw `IOException` from `print`/`println`/`printf` --- it swallows exceptions silently.
Call `pw.checkError()` after writing if you need to know whether a write failed.
:::

## Bridging Bytes and Characters

\index{InputStreamReader@\texttt{InputStreamReader}}
\index{OutputStreamWriter@\texttt{OutputStreamWriter}}
\index{StandardCharsets@\texttt{StandardCharsets}}

`InputStreamReader` and `OutputStreamWriter` bridge the byte and character worlds.
They wrap a byte stream and decode or encode characters using a specified charset.

```java
InputStreamReader(InputStream in, Charset cs)
InputStreamReader(InputStream in, String charsetName)

OutputStreamWriter(OutputStream out, Charset cs)
OutputStreamWriter(OutputStream out, String charsetName)
```

Use `java.nio.charset.StandardCharsets` for the built-in charsets:

| Constant | Charset |
|:---|:---|
| `StandardCharsets.UTF_8` | UTF-8 |
| `StandardCharsets.UTF_16` | UTF-16 |
| `StandardCharsets.ISO_8859_1` | Latin-1 |
| `StandardCharsets.US_ASCII` | ASCII |

```java
// Read UTF-8 from an InputStream you didn't open yourself (e.g., System.in)
try (var reader = new BufferedReader(
        new InputStreamReader(System.in, StandardCharsets.UTF_8))) {
    String line = reader.readLine();
    System.out.println("You typed: " + line);
}
```

This is exactly the pattern for wrapping `System.in` or a network `InputStream` as a character stream.

## Modern Idioms: `Files` and `Path`

\index{Files@\texttt{Files}}
\index{Path@\texttt{Path}}
\index{NIO.2}

Java 7 introduced NIO.2, a clean redesign of the filesystem API.
Two classes do most of the work: `Path` (a value representing a filesystem path) and `Files` (a utility class of static methods).
The design is almost identical to C++17 `std::filesystem` --- if you have used `std::filesystem::path` and `std::filesystem::copy`, you will feel right at home.

### `Path`

\index{Path!of@\texttt{of()}}
\index{Paths@\texttt{Paths}}

A `Path` is an immutable representation of a filesystem path.
Create one with:

```java
static Path Path.of(String first, String... more)     // Java 11+
static Path Paths.get(String first, String... more)   // Java 7+, same thing
static Path Paths.get(URI uri)
```

```java
Path home    = Path.of("/home/gorgo");
Path lyrics  = Path.of("/home/gorgo", "music", "playlist.txt");
Path rel     = Path.of("data/songs.csv");    // relative path
```

`Path` instances support navigation:

```java
Path resolve(String other)          // append a relative path
Path resolve(Path other)
Path resolveSibling(String other)   // replace filename
Path getParent()                    // parent directory
Path getFileName()                  // last element
Path toAbsolutePath()               // make absolute
```

### `Files` Utility Class

\index{Files!exists@\texttt{exists()}}
\index{Files!createFile@\texttt{createFile()}}
\index{Files!delete@\texttt{delete()}}
\index{Files!copy@\texttt{copy()}}
\index{Files!move@\texttt{move()}}
\index{Files!list@\texttt{list()}}
\index{Files!walk@\texttt{walk()}}

`Files` provides static methods for every common filesystem operation.

**Existence and type checks:**

```java
static boolean Files.exists(Path path, LinkOption... options)
static boolean Files.isDirectory(Path path, LinkOption... options)
static boolean Files.isRegularFile(Path path, LinkOption... options)
static boolean Files.isReadable(Path path)
static boolean Files.isWritable(Path path)
```

**Creating files and directories:**

```java
static Path    Files.createFile(Path path, FileAttribute<?>... attrs) throws IOException
static Path    Files.createDirectory(Path dir, FileAttribute<?>... attrs) throws IOException
static Path    Files.createDirectories(Path dir, FileAttribute<?>... attrs) throws IOException
```

`createDirectories` creates all missing intermediate directories, like `mkdir -p`.

**Deleting:**

```java
static void    Files.delete(Path path) throws IOException
static boolean Files.deleteIfExists(Path path) throws IOException
```

**Copying and moving:**

```java
static Path Files.copy(Path source, Path target, CopyOption... options) throws IOException
static Path Files.move(Path source, Path target, CopyOption... options) throws IOException
```

Common `CopyOption` values are `StandardCopyOption.REPLACE_EXISTING` and `StandardCopyOption.COPY_ATTRIBUTES`.

**Listing and walking:**

```java
static Stream<Path> Files.list(Path dir) throws IOException
static Stream<Path> Files.walk(Path start, int maxDepth, FileVisitOption... options) throws IOException
static Stream<Path> Files.walk(Path start, FileVisitOption... options) throws IOException
```

`Files.list` returns the direct contents of a directory (like `readdir`).
`Files.walk` returns a recursive tree walk (like `find`).
Both return `Stream<Path>`, which means they are lazy and must be closed.

```java
// Print all .txt files under a directory
try (Stream<Path> walk = Files.walk(Path.of("music"))) {
    walk.filter(p -> p.toString().endsWith(".txt"))
        .forEach(System.out::println);
}
```

### Reading and Writing Text the Modern Way

\index{Files!readString@\texttt{readString()}}
\index{Files!writeString@\texttt{writeString()}}
\index{Files!readAllLines@\texttt{readAllLines()}}
\index{Files!lines@\texttt{lines()}}

For small-to-medium text files, `Files` provides one-shot read and write methods introduced in Java 11:

```java
static String       Files.readString(Path path) throws IOException
static String       Files.readString(Path path, Charset cs) throws IOException
static List<String> Files.readAllLines(Path path) throws IOException
static List<String> Files.readAllLines(Path path, Charset cs) throws IOException
static Stream<String> Files.lines(Path path) throws IOException
static Stream<String> Files.lines(Path path, Charset cs) throws IOException
static Path         Files.writeString(Path path, CharSequence csq,
                        OpenOption... options) throws IOException
static Path         Files.writeString(Path path, CharSequence csq,
                        Charset cs, OpenOption... options) throws IOException
```

`readString` reads the entire file into a single `String`.
`readAllLines` returns a `List<String>` with one element per line.
`lines` returns a lazy `Stream<String>` --- useful for large files where you do not want to load everything into memory at once.
`writeString` writes a `CharSequence` to a file.

```java
// Write a setlist
Path setlist = Path.of("setlist.txt");
Files.writeString(setlist,
    "I Want It That Way\nSay You'll Be There\nReturn of the Mack\n",
    StandardCharsets.UTF_8);

// Read it back as a stream, process line by line
try (Stream<String> lines = Files.lines(setlist, StandardCharsets.UTF_8)) {
    lines.map(String::trim)
         .filter(s -> !s.isEmpty())
         .forEach(System.out::println);
}
```

::: {.tip}
**Tip:** `Files.lines` returns a `Stream` that holds an open file handle.
Always close it --- use try-with-resources.
`Files.readAllLines` reads everything eagerly and closes the file for you, which is simpler but uses more memory.
:::

::: {.tip}
**Trap:** `Files.readString` and `Files.readAllLines` without a charset argument use UTF-8 (Java 11+).
In Java 8--10, `Files.readAllLines` uses UTF-8 by default; `readString` did not exist yet.
Always pass `StandardCharsets.UTF_8` explicitly to be safe.
:::

## NIO: `FileChannel` and `ByteBuffer`

\index{FileChannel@\texttt{FileChannel}}
\index{ByteBuffer@\texttt{ByteBuffer}}
\index{NIO}

For high-performance I/O --- bulk data transfer, memory-mapped files, non-blocking I/O --- Java NIO provides `FileChannel` and `ByteBuffer`.
This is the Java equivalent of `mmap` and direct `read`/`write` system calls.

### `ByteBuffer`

\index{ByteBuffer!allocate@\texttt{allocate()}}
\index{ByteBuffer!allocateDirect@\texttt{allocateDirect()}}

A `ByteBuffer` is a fixed-size byte container with three key state fields: `position`, `limit`, and `capacity`.
Reading moves `position` forward; `flip()` prepares the buffer for writing by setting `limit = position` and `position = 0`.

```java
static ByteBuffer ByteBuffer.allocate(int capacity)       // heap buffer
static ByteBuffer ByteBuffer.allocateDirect(int capacity) // off-heap, OS-friendly
```

A **direct** buffer is allocated outside the Java heap.
The OS can read/write into it directly without an extra copy --- important for high-throughput I/O.

### `FileChannel`

\index{FileChannel!open@\texttt{open()}}

```java
static FileChannel FileChannel.open(Path path, OpenOption... options) throws IOException
```

Common `OpenOption` values from `StandardOpenOption`:

| Option | Meaning |
|:---|:---|
| `READ` | open for reading |
| `WRITE` | open for writing |
| `APPEND` | writes go to end of file |
| `CREATE` | create if not exists |
| `CREATE_NEW` | fail if already exists |
| `TRUNCATE_EXISTING` | truncate to zero on open |

```java
ByteBuffer buf = ByteBuffer.allocateDirect(65536);

try (FileChannel ch = FileChannel.open(Path.of("data.bin"),
                                       StandardOpenOption.READ)) {
    while (ch.read(buf) > 0) {
        buf.flip();
        // process buf.remaining() bytes
        buf.clear();
    }
}
```

### Memory-Mapped Files

\index{FileChannel!map@\texttt{map()}}
\index{MappedByteBuffer@\texttt{MappedByteBuffer}}

`FileChannel.map` creates a `MappedByteBuffer` backed directly by the file on disk.
The OS handles paging; you read and write the `MappedByteBuffer` as if it were a byte array.

```java
MappedByteBuffer FileChannel.map(FileChannel.MapMode mode, long position, long size)
    throws IOException
```

```java
try (FileChannel ch = FileChannel.open(Path.of("huge.bin"), StandardOpenOption.READ)) {
    MappedByteBuffer mapped = ch.map(FileChannel.MapMode.READ_ONLY, 0, ch.size());
    byte first = mapped.get(0);
    // access any offset in O(1) -- the OS loads pages on demand
}
```

This is exactly `mmap(2)` --- if you have used memory-mapped files in C, the concept is identical.

::: {.tip}
**Tip:** Use `FileChannel` and `ByteBuffer` when you need maximum throughput, random access, or memory-mapped I/O.
For ordinary text file reading and writing, the `Files` utility methods are simpler and sufficient.
:::

## Try-with-Resources for I/O

\index{try-with-resources!I/O}

Chapter 12 introduced try-with-resources.
I/O is the canonical use case.
Every `InputStream`, `OutputStream`, `Reader`, `Writer`, `FileChannel`, and `Stream<Path>` from `Files` must be closed.
Forgetting to close a stream leaks a file descriptor --- the same bug you would get in C by calling `fopen` without `fclose`.

The pattern is:

```java
try (Resource1 r1 = open1();
     Resource2 r2 = open2()) {
    // use r1 and r2
} // r2 closed first, then r1
```

Here is a complete example that reads a text file and writes a filtered copy:

```java
import java.io.*;
import java.nio.charset.StandardCharsets;
import java.nio.file.*;

public class FilterSongs {
    public static void main(String[] args) throws IOException {
        Path src = Path.of("playlist.txt");
        Path dst = Path.of("nineties.txt");

        try (BufferedReader in  = new BufferedReader(
                 new FileReader(src.toFile(), StandardCharsets.UTF_8));
             PrintWriter    out = new PrintWriter(new BufferedWriter(
                 new FileWriter(dst.toFile(), StandardCharsets.UTF_8)))) {
            String line;
            while ((line = in.readLine()) != null) {
                if (line.contains("199")) {   // rough 1990s filter
                    out.println(line);
                }
            }
        }

        System.out.println("Done. Filtered lines written to " + dst);
    }
}
```

When the `try` block exits --- normally or via exception --- both `out` and `in` are closed.
The buffered writer flushes its buffer before closing.
No explicit `finally` block required.

::: {.tip}
**Tip:** When the logic is simple enough, prefer `Files.readAllLines` + `Files.writeString` over the full stream stack.
Reserve the classic stream hierarchy for streaming large files, binary data, or cases where you need fine-grained control over buffering.
:::

## Key Points

- Java has two parallel I/O hierarchies: byte streams (`InputStream`/`OutputStream`) and character streams (`Reader`/`Writer`).
Character streams handle encoding; byte streams handle raw bytes.
- `FileInputStream`/`FileOutputStream` are the byte-level file classes; always wrap them with `BufferedInputStream`/`BufferedOutputStream` to avoid per-byte system calls.
- `FileReader`/`FileWriter` are the character-level file classes; `BufferedReader` adds `readLine()` which returns `null` at EOF.
- `InputStreamReader` and `OutputStreamWriter` bridge byte and character streams; always specify `StandardCharsets.UTF_8` rather than relying on the platform default.
- NIO.2 (Java 7+) provides `Path` (immutable path value) and `Files` (static utility methods) that mirror C++17 `std::filesystem`.
- `Files.readString`, `Files.readAllLines`, and `Files.lines` (Java 11) are the modern idioms for reading text files without writing stream-wrapping boilerplate.
- `FileChannel` and `ByteBuffer` provide high-performance I/O including memory-mapped files, equivalent to `mmap(2)` in C.
- All I/O resources are `AutoCloseable` --- always use try-with-resources.
Forgetting to close a stream leaks a file descriptor.
- `Files.lines` and `Files.list`/`Files.walk` return `Stream` objects that hold open file handles and must be closed with try-with-resources.
