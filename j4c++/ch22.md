# Reflection and Annotations

C++ gives you `typeid` and a handful of type traits at compile time, but almost nothing at runtime.
If you want to know the name of a type at runtime in C++, you get a mangled string that is implementation-defined and barely readable.
Java goes in the opposite direction: every loaded class carries a rich `Class<T>` object that lets you inspect its fields, methods, and constructors, invoke methods by name, and read metadata attached by the programmer at compile time.
This is **reflection** --- the ability of a program to examine and modify its own structure at runtime.

Alongside reflection, Java has a first-class **annotation** system.
Annotations are structured metadata you attach to declarations --- classes, methods, fields, parameters --- that tools, frameworks, and your own code can read at compile time or runtime.
Spring, Hibernate, JUnit, and virtually every major Java framework lean heavily on annotations.
This chapter covers both.

## The `Class<T>` Object

\index{Class object}
\index{reflection}

Every class loaded by the JVM has exactly one \index{Class}\index{java.lang.Class}`java.lang.Class<T>` object associated with it.
It is the entry point to everything reflection can do.
You get a `Class<T>` object three ways:

```java
// 1. From an instance
String s = "Return of the Mack";
Class<? extends String> c1 = s.getClass();       // runtime type of s

// 2. Class literal --- resolved at compile time
Class<String> c2 = String.class;

// 3. By name --- resolved at runtime (throws ClassNotFoundException)
Class<?> c3 = Class.forName("java.lang.String");
```

The class literal `String.class` is the preferred form when the class is known at compile time --- it is checked by the compiler and carries no runtime cost.
`Class.forName` is useful when the class name is only known at runtime, such as when it comes from a configuration file.

Compare this to C++ `typeid(expr)`: it returns a `std::type_info` reference that gives you a mangled name and identity equality, but nothing more.
The Java `Class<T>` object lets you enumerate members, create instances, and invoke methods.

The primary signatures for obtaining a `Class` object:

```java
public final Class<?> Object.getClass()
public static Class<?> Class.forName(String className) throws ClassNotFoundException
```

### Querying Type Names

\index{Class!getName}
\index{Class!getSimpleName}
\index{Class!getCanonicalName}

`Class` provides three name-returning methods:

```java
public String getName()          // binary name, e.g. "java.lang.String"
public String getSimpleName()    // simple name, e.g. "String"
public String getCanonicalName() // canonical name, e.g. "java.lang.String"
```

They differ for arrays and nested classes:

```java
Class<?> c = int[].class;
System.out.println(c.getName());          // [I
System.out.println(c.getSimpleName());    // int[]
System.out.println(c.getCanonicalName()); // int[]
```

`getName()` returns the JVM internal representation; use `getSimpleName()` or `getCanonicalName()` for human-readable output.

### Querying Superclass and Interfaces

\index{Class!getSuperclass}
\index{Class!getInterfaces}

```java
public Class<? super T> getSuperclass()
public Class<?>[]        getInterfaces()
```

```java
Class<?> c = Integer.class;
System.out.println(c.getSuperclass());  // class java.lang.Number
for (Class<?> iface : c.getInterfaces()) {
    System.out.println(iface);          // interface java.lang.Comparable, etc.
}
```

`getSuperclass()` returns `null` for `Object`, interfaces, primitives, and `void`.

## Inspecting Fields, Methods, and Constructors

\index{Field}
\index{Method}
\index{Constructor}

The `Class` object exposes four categories of members, each with two variants --- one that returns only public members (including inherited ones) and one that returns all members declared directly in the class, regardless of access:

| Returns | Public (+ inherited) | All declared in class |
|:--------|:---------------------|:----------------------|
| Fields | `getFields()` | `getDeclaredFields()` |
| Methods | `getMethods()` | `getDeclaredMethods()` |
| Constructors | `getConstructors()` | `getDeclaredConstructors()` |

```java
public Field[]         getFields()
public Field[]         getDeclaredFields()
public Method[]        getMethods()
public Method[]        getDeclaredMethods()
public Constructor<?>[] getConstructors()
public Constructor<?>[] getDeclaredConstructors()
```

To retrieve a single member by name:

```java
public Field       getField(String name) throws NoSuchFieldException
public Field       getDeclaredField(String name) throws NoSuchFieldException
public Method      getMethod(String name, Class<?>... parameterTypes) throws NoSuchMethodException
public Method      getDeclaredMethod(String name, Class<?>... parameterTypes) throws NoSuchMethodException
public Constructor<T> getConstructor(Class<?>... parameterTypes) throws NoSuchMethodException
public Constructor<T> getDeclaredConstructor(Class<?>... parameterTypes) throws NoSuchMethodException
```

Notice the `parameterTypes` argument: because Java supports method overloading, the name alone is not enough to identify a method --- you must also supply the parameter types.

```java
import java.lang.reflect.*;

public class Inspector {
    public static void main(String[] args) throws Exception {
        Class<?> c = String.class;

        System.out.println("--- public methods ---");
        for (Method m : c.getMethods()) {
            System.out.println(m.getName());
        }

        System.out.println("--- declared fields ---");
        for (Field f : c.getDeclaredFields()) {
            System.out.println(f.getType().getSimpleName() + " " + f.getName());
        }
    }
}
```

## Accessing Fields Reflectively

\index{Field!get}
\index{Field!set}
\index{setAccessible}

`Field` lets you read and write a field on any object instance at runtime.
The key methods:

```java
public Object Field.get(Object obj) throws IllegalAccessException
public void   Field.set(Object obj, Object value) throws IllegalAccessException
```

For public fields, you call them directly.
For `private` fields you must first call:

```java
public void AccessibleObject.setAccessible(boolean flag)
```

`setAccessible(true)` overrides the access check.
This is powerful and dangerous --- it lets you read or write fields that were deliberately made private.
In the Java module system (Java 9+, covered in Chapter 21), a module must `opens` its package before other modules can call `setAccessible` on its types; failing to do so throws `InaccessibleObjectException`.

```java
import java.lang.reflect.*;

public class FieldAccess {
    private String title = "Return of the Mack";

    public static void main(String[] args) throws Exception {
        FieldAccess obj = new FieldAccess();

        Field f = FieldAccess.class.getDeclaredField("title");
        f.setAccessible(true);                           // bypass private

        System.out.println(f.get(obj));                  // Return of the Mack
        f.set(obj, "Mack Is Back");
        System.out.println(f.get(obj));                  // Mack Is Back
    }
}
```

::: {.tip}
**Trap:** `setAccessible(true)` bypasses encapsulation.
Use it only in frameworks, testing utilities, or migration code --- never in normal application logic.
It breaks when the module system's `opens` declarations are absent, and it couples your code to implementation details that may change without warning.
:::

## Invoking Methods Reflectively

\index{Method!invoke}

`Method.invoke` calls a method on an object:

```java
public Object Method.invoke(Object obj, Object... args)
    throws IllegalAccessException, InvocationTargetException
```

`obj` is the instance to invoke on (`null` for static methods).
`args` are the arguments.
The return value is `Object`; you cast it to the expected type.
If the invoked method throws, `invoke` wraps the cause in `InvocationTargetException`; unwrap it with `getCause()`.

```java
import java.lang.reflect.*;

public class MethodInvoke {
    public String shout(String s) {
        return s.toUpperCase() + "!";
    }

    public static void main(String[] args) throws Exception {
        MethodInvoke obj = new MethodInvoke();
        Method m = MethodInvoke.class.getMethod("shout", String.class);
        String result = (String) m.invoke(obj, "return of the mack");
        System.out.println(result);    // RETURN OF THE MACK!
    }
}
```

For `private` methods, call `m.setAccessible(true)` before `invoke`, subject to the same module-system restrictions as fields.

## Creating Instances Reflectively

\index{Constructor!newInstance}

`Constructor<T>` creates new instances:

```java
public T Constructor.newInstance(Object... args)
    throws InstantiationException, IllegalAccessException, InvocationTargetException
```

```java
import java.lang.reflect.*;

public class ReflectNew {
    private String value;

    public ReflectNew(String value) {
        this.value = value;
    }

    @Override
    public String toString() {
        return "ReflectNew{value='" + value + "'}";
    }

    public static void main(String[] args) throws Exception {
        Constructor<ReflectNew> ctor =
            ReflectNew.class.getConstructor(String.class);
        ReflectNew obj = ctor.newInstance("Mark Morrison");
        System.out.println(obj);    // ReflectNew{value='Mark Morrison'}
    }
}
```

::: {.tip}
**Tip:** If you need to create instances from a `Class<?>` whose type is not known at compile time, `getDeclaredConstructor()` with no arguments gives you the no-arg constructor.
Calling `newInstance()` on it is the traditional factory pattern used by dependency injection frameworks.
:::

## Built-in Annotations

\index{annotation}
\index{annotation!built-in}

Annotations are metadata attached to a declaration using the `@` prefix.
The compiler understands several built-in annotations:

### `@Override`

\index{@Override}

```java
@Override
public String toString() { return "..."; }
```

Tells the compiler you intend to override a method from a superclass or interface.
If the method does not actually override anything --- perhaps you mistyped the name or used the wrong parameter types --- the compiler reports an error.
In C++ you use the `override` keyword for the same purpose; `@Override` is the Java equivalent.

### `@Deprecated`

\index{@Deprecated}

```java
@Deprecated(since = "9", forRemoval = true)
public void oldMethod() { ... }
```

Marks a method (or class, or field) as deprecated.
The compiler emits a warning at every call site.
`since` records when it was deprecated; `forRemoval = true` signals the element will eventually be removed.

### `@SuppressWarnings`

\index{@SuppressWarnings}

```java
@SuppressWarnings("unchecked")
public <T> List<T> unsafeCast(List<?> list) {
    return (List<T>) list;
}
```

Suppresses a specific compiler warning category.
Common values: `"unchecked"`, `"deprecation"`, `"rawtypes"`, `"serial"`.

::: {.tip}
**Trap:** Do not suppress `"unchecked"` warnings globally or on a whole class.
Place `@SuppressWarnings` on the smallest scope possible --- ideally a single method or field.
Suppressing too broadly hides real problems.
:::

### `@FunctionalInterface`

\index{@FunctionalInterface}

```java
@FunctionalInterface
public interface Transformer<T> {
    T transform(T input);
}
```

Asks the compiler to verify that the interface has exactly one abstract method.
It adds no runtime behavior; it is purely a compile-time safeguard.
Covered in depth in Chapter 8.

### `@SafeVarargs`

\index{@SafeVarargs}

```java
@SafeVarargs
public final <T> List<T> listOf(T... items) { ... }
```

Suppresses heap-pollution warnings that arise when a generic varargs method stores or passes the `items` array in a way that could cause type-safety problems.
Apply it only when you have verified that the method does not do anything unsafe with the varargs array.

## Defining Custom Annotations

\index{annotation!custom}
\index{@interface}

You define an annotation type with `@interface`:

```java
public @interface RunTest {
    String description() default "";
    int    priority()    default 1;
}
```

Annotation elements look like methods but are actually keys in a key-value metadata map.
They can have defaults.
An annotation with a single element conventionally names it `value()`, which allows the shorthand `@RunTest("smoke test")` instead of `@RunTest(description = "smoke test")`.

### Retention

\index{annotation!retention}
\index{RetentionPolicy}

`@Retention` controls how long the annotation survives:

```java
import java.lang.annotation.*;

@Retention(RetentionPolicy.RUNTIME)
public @interface RunTest {
    String description() default "";
    int    priority()    default 1;
}
```

| Policy | Survives to |
|:-------|:------------|
| `SOURCE` | Discarded by the compiler. Used by compile-time tools like `@Override`. |
| `CLASS` | Written to `.class` bytecode but not loaded into the JVM at runtime. The default if `@Retention` is omitted. |
| `RUNTIME` | Loaded into the JVM; readable via reflection. Required if you want to query annotations at runtime. |

### Target

\index{annotation!target}
\index{ElementType}

`@Target` restricts where the annotation can be applied:

```java
@Target({ElementType.METHOD, ElementType.TYPE})
@Retention(RetentionPolicy.RUNTIME)
public @interface RunTest {
    String description() default "";
    int    priority()    default 1;
}
```

Common `ElementType` values:

| Value | Applies to |
|:------|:-----------|
| `TYPE` | Class, interface, enum, annotation type |
| `FIELD` | Field declaration |
| `METHOD` | Method declaration |
| `PARAMETER` | Method or constructor parameter |
| `CONSTRUCTOR` | Constructor declaration |
| `LOCAL_VARIABLE` | Local variable declaration |
| `ANNOTATION_TYPE` | Annotation type declaration |
| `PACKAGE` | Package declaration |

Omitting `@Target` means the annotation can be placed anywhere.
Adding `@Target` is good practice because it catches mistakes at compile time.

## Reading Annotations at Runtime

\index{annotation!reading at runtime}
\index{getAnnotation}
\index{isAnnotationPresent}

With `@Retention(RetentionPolicy.RUNTIME)`, you can read annotations through `Method`, `Field`, `Class`, and `Constructor`:

```java
public <A extends Annotation> A Method.getAnnotation(Class<A> annotationType)
public boolean                   Method.isAnnotationPresent(Class<A> annotationType)
public <A extends Annotation> A[] Method.getAnnotationsByType(Class<A> annotationType)
```

`getAnnotation` returns the annotation instance, or `null` if the annotation is not present.
`isAnnotationPresent` is just a null-check convenience.
`getAnnotationsByType` is used for repeatable annotations (those marked `@Repeatable`).

### Complete Example: A Minimal Test Runner

Here is a self-contained example that defines an annotation, applies it to methods, and uses reflection to find and invoke the annotated methods:

```java
import java.lang.annotation.*;
import java.lang.reflect.*;
import java.util.*;

// --- annotation definition ---
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
@interface RunTest {
    String description() default "";
    int    priority()    default 1;
}

// --- class under test ---
public class ReflectionTestRunner {

    @RunTest(description = "checks upper case", priority = 2)
    public void testUpperCase() {
        String s = "return of the mack".toUpperCase();
        if (!s.equals("RETURN OF THE MACK")) {
            throw new AssertionError("toUpperCase failed");
        }
        System.out.println("testUpperCase: PASS");
    }

    @RunTest(description = "checks length", priority = 1)
    public void testLength() {
        if ("Mack".length() != 4) {
            throw new AssertionError("length wrong");
        }
        System.out.println("testLength: PASS");
    }

    public void notATest() {
        System.out.println("this should not run");
    }

    public static void main(String[] args) throws Exception {
        Class<?> cls       = ReflectionTestRunner.class;
        Object   instance  = cls.getDeclaredConstructor().newInstance();

        // collect @RunTest methods and sort by priority
        List<Method> tests = new ArrayList<>();
        for (Method m : cls.getDeclaredMethods()) {
            if (m.isAnnotationPresent(RunTest.class)) {
                tests.add(m);
            }
        }
        tests.sort(Comparator.comparingInt(
            m -> m.getAnnotation(RunTest.class).priority()));

        // run them
        for (Method m : tests) {
            RunTest ann = m.getAnnotation(RunTest.class);
            System.out.printf("Running [priority=%d] %s: %s%n",
                ann.priority(), m.getName(), ann.description());
            try {
                m.invoke(instance);
            } catch (InvocationTargetException e) {
                System.out.println(m.getName() + ": FAIL --- " +
                    e.getCause().getMessage());
            }
        }
    }
}
```

Output:

```
Running [priority=1] testLength: checks length
testLength: PASS
Running [priority=2] testUpperCase: checks upper case
testUpperCase: PASS
```

This is essentially how JUnit discovers and runs your test methods --- annotations tell the framework which methods to invoke, and reflection does the invocation.

::: {.tip}
**Wut:** Annotation element values are restricted to: primitives, `String`, `Class<?>`, enum constants, other annotations, and arrays of any of the above.
You cannot use `int[]` from a variable --- only a literal array initializer.
This is more restrictive than a regular Java method parameter list.
:::

## Annotation Processors (Compile-Time)

\index{annotation processor}
\index{javax.annotation.processing}

Some annotations are not read at runtime via reflection --- they are read by **annotation processors** that run as part of the compiler pipeline.
A processor implements `javax.annotation.processing.Processor` and participates in the `javac` compilation process.

You will rarely write annotation processors yourself, but you use their output constantly:

- **Lombok** (`@Data`, `@Builder`, `@Slf4j`) generates `equals`, `hashCode`, `toString`, constructors, and logger fields.
- **Dagger 2** (`@Module`, `@Provides`, `@Inject`) generates dependency injection wiring code at compile time.
- **MapStruct** (`@Mapper`) generates type-safe object mapping code.
- `@SuppressWarnings`, `@Override`, and `@Deprecated` are processed directly by the compiler.

The key difference from runtime annotations: processors generate `.java` or `.class` files during compilation, before the JVM ever runs.
There is no runtime cost.
The generated code is just as efficient as hand-written code.

::: {.tip}
**Tip:** If you see a library that promises "zero runtime overhead" annotation magic, it is almost certainly using an annotation processor.
The work happens at build time; what runs in production is plain compiled Java.
:::

## Key Points

- Every class loaded by the JVM has a `Class<T>` object; get it via `obj.getClass()`, `Foo.class`, or `Class.forName("name")`.
- `getFields()` / `getMethods()` / `getConstructors()` return public (including inherited) members; `getDeclaredFields()` / `getDeclaredMethods()` / `getDeclaredConstructors()` return everything declared in the class regardless of access.
- `Field.get` / `Field.set` and `Method.invoke` give runtime access to otherwise inaccessible state; call `setAccessible(true)` first for non-public members, subject to module-system restrictions.
- `Constructor.newInstance(args)` creates instances without knowing the type at compile time.
- Built-in annotations: `@Override` (verify override), `@Deprecated` (warn callers), `@SuppressWarnings` (suppress warnings), `@FunctionalInterface` (verify SAM), `@SafeVarargs` (suppress heap pollution warning).
- Define custom annotations with `@interface`; elements may have defaults; `value()` enables shorthand syntax.
- `@Retention(RetentionPolicy.RUNTIME)` is required for annotations to be readable via reflection; `SOURCE` annotations are discarded by the compiler; `CLASS` (default) annotations are in bytecode but not available at runtime.
- `@Target` restricts where an annotation may be applied; use it to catch misuse at compile time.
- Read annotations at runtime with `getAnnotation`, `isAnnotationPresent`, and `getAnnotationsByType`.
- Annotation processors run at compile time; they generate code with no runtime overhead --- Lombok, Dagger 2, and MapStruct are common examples.

## Exercises

1. **Think about it:** Reflection lets you call private methods and read private fields on any object.
   This completely bypasses encapsulation.
   When is this a legitimate tool, and when is it a design smell?
   How does the Java module system's `opens` directive help address the abuse?

2. **What does this do?**

    ```java
    import java.lang.reflect.*;

    public class Quiz {
        private int value = 42;

        public static void main(String[] args) throws Exception {
            Quiz q = new Quiz();
            Field f = Quiz.class.getDeclaredField("value");
            f.setAccessible(true);
            f.set(q, 99);
            System.out.println(f.get(q));
        }
    }
    ```

    What does this print?
    What would happen if you removed the `f.setAccessible(true)` call?

3. **Calculation:** A class has 3 public methods, 2 private methods, and inherits 10 public methods from its superclass (not counting `Object`'s methods).
   How many methods does `getMethods()` return (include `Object`'s 11 public methods)?
   How many does `getDeclaredMethods()` return?

4. **Where is the bug?**

    ```java
    import java.lang.annotation.*;
    import java.lang.reflect.*;

    @Retention(RetentionPolicy.SOURCE)
    @Target(ElementType.METHOD)
    @interface Tag {
        String value() default "none";
    }

    public class Broken {
        @Tag("important")
        public void doWork() {}

        public static void main(String[] args) throws Exception {
            Method m = Broken.class.getMethod("doWork");
            Tag tag  = m.getAnnotation(Tag.class);
            System.out.println(tag.value());
        }
    }
    ```

    This compiles but throws a `NullPointerException` at runtime.
    Why, and how do you fix it?
