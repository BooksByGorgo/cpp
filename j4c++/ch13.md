# Lambdas and Method References

You already know C++ lambdas: `[capture](params) -> ret { body }`.
You choose exactly what to capture and whether to capture by value or by reference.
Java has had lambdas since Java 8, and the surface syntax is cleaner --- but the capture rules are different enough to bite you if you assume they work the same way.
This chapter covers lambda syntax, the functional interfaces that give lambdas their types, and method references, which let you reuse existing methods anywhere a lambda is expected.

## Lambda Syntax

\index{lambda}
\index{lambda!syntax}

A Java lambda has two forms: an expression lambda and a block lambda.

```java
// expression lambda -- the result of the expression is returned implicitly
(String s) -> s.toUpperCase()

// block lambda -- needs an explicit return if you want to return a value
(String s) -> { return s.toUpperCase(); }
```

Type inference lets you drop the parameter types when the compiler can figure them out from context:

```java
// types inferred from context
(s) -> s.toUpperCase()
```

A single parameter needs no parentheses:

```java
s -> s.toUpperCase()
```

A zero-parameter lambda requires empty parentheses:

```java
() -> "Buddy Holly"
```

The C++ equivalent of that last one is `[]() { return "Buddy Holly"; }`.
In Java you write `() -> "Buddy Holly"` --- the `->` replaces `[]()` and there is no capture list.

## Capture Rules: Effectively Final

\index{lambda!capture}
\index{effectively final}

In C++, you choose how to capture each variable: `[x]` captures `x` by value, `[&x]` by reference, `[=]` captures everything by value, `[&]` captures everything by reference.
Mutable lambdas (with the `mutable` keyword) can even modify by-value captures.

Java has none of that flexibility.
A lambda in Java captures local variables **by value, implicitly**, but only if those variables are **effectively final** --- meaning the variable is never reassigned after the point where it is captured.
The `final` keyword is not required, but the variable must not change.

```java
String artist = "Weezer";       // effectively final -- never reassigned
Supplier<String> s = () -> "Playing: " + artist;  // OK

artist = "Green Day";           // compile error: artist is no longer effectively final
```

::: {.tip}
**Wut:** "Effectively final" means the compiler checks that the variable is never reassigned --- it does not mean the object the variable refers to is immutable.
You can call mutating methods on a captured reference; you just cannot point the variable at a different object.

```java
List<String> songs = new ArrayList<>();
Runnable r = () -> songs.add("Buddy Holly"); // OK -- songs is effectively final
songs = new ArrayList<>();                   // compile error -- songs reassigned
```
:::

Instance fields are a different story.
A lambda in an instance method captures `this` implicitly.
Through `this`, it can read and write any instance field freely --- the "effectively final" rule applies only to local variables.
This means a lambda in an instance method can have side effects on the enclosing object's state without any explicit capture declaration.
In C++ you would write `[this]` to opt in; in Java the capture is always implicit and unconditional.

::: {.tip}
**Trap:** Because `this` is always captured, a lambda stored in a field of an object will keep that object alive.
This is the Java equivalent of a C++ `[this]` capture --- the object cannot be garbage-collected while the lambda is reachable.
:::

## Functional Interfaces

\index{functional interface}
\index{@FunctionalInterface@\texttt{@FunctionalInterface}}

A lambda has no type on its own.
It is always assigned to a **functional interface** --- an interface with exactly one abstract method.
The lambda provides the implementation of that one method.

```java
@FunctionalInterface
interface Greeter {
    String greet(String name);
}

Greeter g = name -> "Hey " + name + "!";
System.out.println(g.greet("Buddy"));  // Hey Buddy!
```

The `@FunctionalInterface` annotation is optional but recommended --- the compiler will flag the interface as an error if you accidentally add a second abstract method.

In C++ the closest concept is `std::function<Ret(Params...)>`, which can hold any callable with a matching signature.
In Java, the type system is more explicit: the lambda target must be a named functional interface.

## Common Functional Interfaces from `java.util.function`

\index{java.util.function@\texttt{java.util.function}}

Java ships a ready-made toolkit of functional interfaces in `java.util.function`.
You rarely need to define your own.

### `Predicate<T>`

\index{Predicate@\texttt{Predicate}}

Signature: `boolean test(T t)`

Tests whether a value satisfies a condition.
This is the workhorse for filtering.

```java
Predicate<String> isNineties = s -> s.contains("199");
System.out.println(isNineties.test("1994"));   // true
System.out.println(isNineties.test("2001"));   // false
```

### `Function<T, R>`

\index{Function@\texttt{Function}}

Signature: `R apply(T t)`

Transforms a value of type `T` into a value of type `R`.

```java
Function<String, Integer> length = String::length;  // method reference -- covered below
System.out.println(length.apply("Buddy Holly"));    // 11
```

### `Consumer<T>`

\index{Consumer@\texttt{Consumer}}

Signature: `void accept(T t)`

Consumes a value and returns nothing --- for side effects.

```java
Consumer<String> print = System.out::println;
print.accept("Say it ain't so");    // Say it ain't so
```

### `Supplier<T>`

\index{Supplier@\texttt{Supplier}}

Signature: `T get()`

Produces a value without taking any input.

```java
Supplier<String> song = () -> "Buddy Holly";
System.out.println(song.get());    // Buddy Holly
```

### `BiFunction<T, U, R>`

\index{BiFunction@\texttt{BiFunction}}

Signature: `R apply(T t, U u)`

Like `Function` but takes two inputs.

```java
BiFunction<String, Integer, String> repeat = (s, n) -> s.repeat(n);
System.out.println(repeat.apply("na-", 4));   // na-na-na-na-
```

### `UnaryOperator<T>` and `BinaryOperator<T>`

\index{UnaryOperator@\texttt{UnaryOperator}}
\index{BinaryOperator@\texttt{BinaryOperator}}

`UnaryOperator<T>` extends `Function<T,T>` with signature `T apply(T t)` --- useful when input and output are the same type.
`BinaryOperator<T>` extends `BiFunction<T,T,T>` with signature `T apply(T t1, T t2)` --- useful for fold/reduce operations.

```java
UnaryOperator<String> shout = s -> s.toUpperCase() + "!";
System.out.println(shout.apply("weezer"));   // WEEZER!

BinaryOperator<Integer> add = (a, b) -> a + b;
System.out.println(add.apply(1994, 3));      // 1997
```

### Primitive Specializations

\index{IntPredicate@\texttt{IntPredicate}}
\index{IntFunction@\texttt{IntFunction}}
\index{ToIntFunction@\texttt{ToIntFunction}}

Generics cannot hold primitives --- an `int` in a `Function<Integer, Integer>` gets autoboxed to `Integer` on every call.
For numerical pipelines where performance matters, use the primitive specializations: `IntPredicate`, `LongPredicate`, `DoublePredicate`, `IntFunction<R>`, `ToIntFunction<T>`, `IntUnaryOperator`, `IntBinaryOperator`, and so on.

```java
IntPredicate  isEven    = n -> n % 2 == 0;
ToIntFunction<String> charCount = String::length;
```

## Method References

\index{method reference}

A method reference is shorthand for a lambda that does nothing but call a single existing method.
It uses the `::` operator.
There are four forms.

### Static Method Reference: `ClassName::staticMethod`

\index{method reference!static}

```java
// lambda form
Function<String, Integer> parse = s -> Integer.parseInt(s);

// method reference form
Function<String, Integer> parse = Integer::parseInt;
```

The lambda and the method reference are equivalent --- both call `Integer.parseInt(s)` when `apply(s)` is invoked.

### Bound Instance Method Reference: `instance::instanceMethod`

\index{method reference!bound instance}

The receiver object is fixed at the time the reference is created.

```java
// lambda form
Consumer<String> print = s -> System.out.println(s);

// method reference form
Consumer<String> print = System.out::println;
```

`System.out` is the bound receiver.
Every call to `print.accept(s)` will call `System.out.println(s)`.

### Unbound Instance Method Reference: `ClassName::instanceMethod`

\index{method reference!unbound instance}

The receiver is the first argument supplied at call time --- it is not bound when the reference is created.

```java
// lambda form
Function<String, String> upper = s -> s.toUpperCase();

// method reference form
Function<String, String> upper = String::toUpperCase;
```

When `upper.apply("weezer")` is called, `"weezer"` becomes the receiver and the result is `"WEEZER"`.
This form looks like a static method reference but it is not --- the first parameter becomes `this` inside the method.

::: {.tip}
**Wut:** `String::toUpperCase` and `Integer::parseInt` look identical in form, but they are different kinds of references.
`Integer::parseInt` is a static reference (no receiver needed).
`String::toUpperCase` is an unbound instance reference (the first argument is the receiver).
The compiler figures out which kind you mean from the functional interface's signature.
:::

### Constructor Reference: `ClassName::new`

\index{method reference!constructor}

```java
// lambda form
Supplier<StringBuilder> make = () -> new StringBuilder();

// method reference form
Supplier<StringBuilder> make = StringBuilder::new;
```

Constructor references work with any functional interface whose abstract method's signature matches a constructor of the target class.

## Composing Functions

\index{Predicate!and@\texttt{and()}}
\index{Predicate!or@\texttt{or()}}
\index{Predicate!negate@\texttt{negate()}}
\index{Function!andThen@\texttt{andThen()}}
\index{Function!compose@\texttt{compose()}}

Functional interfaces in `java.util.function` provide default methods for building pipelines without the Stream API.

`Predicate` offers:
- `Predicate<T> and(Predicate<? super T> other)` --- both must be true
- `Predicate<T> or(Predicate<? super T> other)` --- either must be true
- `Predicate<T> negate()` --- logical NOT

```java
Predicate<String> longWord  = s -> s.length() > 5;
Predicate<String> hasHolly  = s -> s.contains("Holly");

Predicate<String> both = longWord.and(hasHolly);
System.out.println(both.test("Buddy Holly"));   // true
System.out.println(both.test("Weezer"));        // false -- too short and no Holly
```

`Function` offers:
- `Function<T, V> andThen(Function<? super R, ? extends V> after)` --- apply `this`, then `after`
- `Function<V, R> compose(Function<? super V, ? extends T> before)` --- apply `before`, then `this`

```java
Function<String, String> trim  = String::trim;
Function<String, String> upper = String::toUpperCase;

Function<String, String> trimThenUpper = trim.andThen(upper);
System.out.println(trimThenUpper.apply("  buddy holly  "));  // BUDDY HOLLY
```

`andThen` reads left-to-right: apply `trim`, then apply `upper`.
`compose` reads right-to-left: `f.compose(g)` means "apply `g`, then apply `f`."
Use `andThen` --- it is easier to reason about.

## Key Points

- A Java lambda is `(params) -> expression` or `(params) -> { statements; }`.
Single parameters do not need parentheses; zero parameters require `()`.
- Local variables captured by a lambda must be **effectively final** --- never reassigned after capture.
Instance fields are captured through `this` implicitly, with no restriction.
- A lambda has no standalone type; it is always assigned to a **functional interface** --- an interface with exactly one abstract method.
- The `java.util.function` package provides ready-made interfaces: `Predicate<T>`, `Function<T,R>`, `Consumer<T>`, `Supplier<T>`, `BiFunction<T,U,R>`, `UnaryOperator<T>`, `BinaryOperator<T>`, and primitive specializations.
- Method references (`::`) are shorthand for a lambda that calls a single method; there are four forms: static, bound instance, unbound instance, and constructor.
- `Predicate` supports `.and()`, `.or()`, `.negate()`; `Function` supports `.andThen()` and `.compose()` for building pipelines without streams.
- Prefer primitive specializations (`IntPredicate`, `ToIntFunction`, etc.) in numerical pipelines to avoid autoboxing overhead.
- Unlike C++ `[&]` captures, Java lambdas cannot hold a mutable reference to a reassignable local variable --- design your code so captured locals do not need to change.

## Exercises

1. **Think about it:** In C++ you can write `[count](int x) mutable { return ++count + x; }` to create a lambda that maintains private mutable state across calls.
   Java's effectively-final rule makes that pattern impossible with a local variable.
   How would you achieve the same "lambda with mutable state" effect in Java?
   What are the tradeoffs of that approach?

2. **What does this print?**

    ```java
    import java.util.function.*;

    public class Q2 {
        public static void main(String[] args) {
            Function<String, String> f = s -> "[" + s + "]";
            Function<String, String> g = String::toUpperCase;

            Function<String, String> h = f.andThen(g);
            Function<String, String> k = f.compose(g);

            System.out.println(h.apply("weezer"));
            System.out.println(k.apply("weezer"));
        }
    }
    ```

3. **Calculation:** How many abstract methods may a functional interface have?
   Given the following interface, is it a valid functional interface?
   Explain why or why not.

    ```java
    @FunctionalInterface
    interface Transformer<T> {
        T transform(T input);
        default T identity() { return transform(transform(transform(transform(input)))); }
        static <T> Transformer<T> noOp() { return x -> x; }
    }
    ```

    (Hint: default and static methods do not count toward the abstract method total.)

4. **Where is the bug?**

    ```java
    import java.util.function.*;

    public class Counter {
        public static void main(String[] args) {
            int count = 0;
            Consumer<String> printer = s -> {
                count++;                       // increment for each item printed
                System.out.println(count + ": " + s);
            };
            printer.accept("Buddy Holly");
            printer.accept("Undone");
        }
    }
    ```

5. **Write a program:** Write a class `Pipeline` with a `main` method that does the following using only lambdas and method references --- no explicit loops.
   Create a `List<String>` containing at least five 1990s song titles (use `List.of(...)`).
   Use `Predicate`, `Function`, and `Consumer` to: (1) filter to songs whose title length is greater than 8 characters, (2) transform the remaining titles to uppercase, and (3) print each result.
   Chain the operations by calling `.test()`, `.apply()`, and `.accept()` yourself in a loop over the list --- you will use the Stream API in the next chapter to do this without the loop.
