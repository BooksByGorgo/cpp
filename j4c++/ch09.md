# Strings

C++ gives you `std::string` as a mutable, value-semantic container of characters.
You can modify it in place, copy it cheaply with copy-on-write semantics (pre-C++11) or move semantics (C++11+), and index into it like an array.
Java's `String` looks superficially similar but is built on a completely different contract: it is **immutable**.
Every method that appears to modify a `String` actually returns a brand new one.
Once you internalize that difference, the rest of Java's string API makes a lot more sense --- including why `StringBuilder` exists and why `==` will silently lie to you.

This chapter covers `String` immutability and the string pool, the full set of commonly used `String` methods, `StringBuilder` for efficient string construction, text blocks for multiline literals, and `String.format()` for `printf`-style formatting.

## String Immutability and the String Pool

\index{String!immutability}
\index{string pool}

In C++, `std::string s = "hello"; s[0] = 'H';` works fine.
In Java, `String` objects are immutable --- there is no way to change the characters inside one after it is created.
Every operation that looks like a mutation --- `toUpperCase()`, `trim()`, concatenation with `+` --- returns a new `String` object and leaves the original unchanged.

```java
String song = "common people";
String upper = song.toUpperCase(); // returns a new String
System.out.println(song);  // common people  (unchanged)
System.out.println(upper); // COMMON PEOPLE
```

### The String Pool

\index{string pool!interning}
\index{String!intern}

Because `String` objects are immutable, the JVM can safely share them.
String literals in your source code are **interned**: the JVM keeps a single copy of each unique literal in a region called the **string pool**, and all references to the same literal point to that one object.

```java
String a = "Pulp";
String b = "Pulp";
System.out.println(a == b); // true --- same pooled object
```

String objects created with `new` bypass the pool:

```java
String c = new String("Pulp");
System.out.println(a == c); // false --- different objects
```

::: {.tip}
**Trap:** Never use `==` to compare the *contents* of two strings.
`==` compares object identity (like comparing two pointers in C++), not the sequence of characters.
Two `String` objects with identical contents can be different objects, and `==` will return `false`.
Always use `.equals()` to compare string contents.

```java
String x = new String("Common People");
String y = new String("Common People");
System.out.println(x == y);      // false --- different objects
System.out.println(x.equals(y)); // true  --- same content
```
:::

### Concatenation in a Loop

\index{String!concatenation loop}

Because `+` on `String` creates a new object every time, using it inside a loop is expensive:

```java
// Slow: creates a new String object on every iteration
String result = "";
for (int i = 0; i < 100; i++) {
    result += i + ", ";
}
```

Each `+=` allocates a new `String` containing all the previous characters plus the new ones.
For a hundred iterations that is roughly 5,000 characters of allocation and copying.
Use `StringBuilder` instead (see section below).

## Key String Methods

\index{String!methods}

Java's `String` class is in `java.lang`, so it is available without an import.
Here are the methods you will use constantly.

### Length and Character Access

\index{String!length()}
\index{String!charAt()}

```java
int length()
char charAt(int index)
```

`length()` returns the number of UTF-16 code units in the string --- equivalent to `std::string::size()`.
`charAt(index)` returns the character at position `index` (zero-based), equivalent to `s[i]` in C++.

```java
String band = "Pulp";
System.out.println(band.length());   // 4
System.out.println(band.charAt(0));  // P
```

::: {.tip}
**Trap:** `length` on a Java array is a field (no parentheses): `arr.length`.
`length()` on a `String` is a method (parentheses required): `s.length()`.
Mixing them up is a constant source of compiler errors.
:::

### Substrings

\index{String!substring()}

```java
String substring(int beginIndex)
String substring(int beginIndex, int endIndex)
```

The one-argument form returns everything from `beginIndex` to the end.
The two-argument form returns characters from `beginIndex` up to but **not including** `endIndex`.
This is different from C++'s `std::string::substr(pos, len)`, which takes a starting position and a **length**.

```java
String lyric = "Common People";
System.out.println(lyric.substring(7));    // People
System.out.println(lyric.substring(0, 6)); // Common
```

::: {.tip}
**Wut:** `substring(begin, end)` --- `end` is exclusive.
If you are porting C++ code that uses `substr(pos, len)`, the Java equivalent is `substring(pos, pos + len)`, not `substring(pos, len)`.
:::

### Equality

\index{String!equals()}
\index{String!equalsIgnoreCase()}

```java
boolean equals(Object other)
boolean equalsIgnoreCase(String other)
```

`equals()` compares character content and is case-sensitive.
`equalsIgnoreCase()` compares without regard to case.
Both follow the contract established by `Object.equals()` (covered in Chapter 6).

```java
String a = "María";   // "María" - Ricky Martin (1995)
String b = "maría";
System.out.println(a.equals(b));             // false
System.out.println(a.equalsIgnoreCase(b));   // true
```

### Searching

\index{String!indexOf()}
\index{String!lastIndexOf()}
\index{String!contains()}
\index{String!startsWith()}
\index{String!endsWith()}

```java
int indexOf(String str)
int indexOf(String str, int fromIndex)
int lastIndexOf(String str)
int lastIndexOf(String str, int fromIndex)
boolean startsWith(String prefix)
boolean endsWith(String suffix)
boolean contains(CharSequence s)
```

`indexOf()` returns the index of the first occurrence of `str`, or `-1` if not found --- the same convention as `std::string::find()`, which returns `std::string::npos` on failure.
`lastIndexOf()` searches from the end.
`contains()` is a convenience wrapper for `indexOf(...) >= 0`.

```java
String lyric = "Common People";
System.out.println(lyric.indexOf("o"));      // 1
System.out.println(lyric.lastIndexOf("o"));  // 9
System.out.println(lyric.contains("eople")); // true
System.out.println(lyric.startsWith("Com")); // true
System.out.println(lyric.endsWith("ple"));   // true
```

### Case Conversion

\index{String!toLowerCase()}
\index{String!toUpperCase()}

```java
String toLowerCase()
String toLowerCase(java.util.Locale locale)
String toUpperCase()
String toUpperCase(java.util.Locale locale)
```

Both return a new `String` with all characters converted.
The no-argument overloads use the default locale, which can produce surprising results for locale-sensitive characters (the Turkish "I" problem is the classic example).
Prefer the locale-specific overloads in internationalized code.

```java
System.out.println("María".toUpperCase()); // MARÍA
System.out.println("PULP".toLowerCase());  // pulp
```

### Whitespace Handling

\index{String!trim()}
\index{String!strip()}
\index{String!isBlank()}

```java
String trim()
String strip()          // Java 11+
String stripLeading()   // Java 11+
String stripTrailing()  // Java 11+
boolean isBlank()       // Java 11+
```

`trim()` removes ASCII whitespace (characters `<= ' '`) from both ends.
`strip()` (Java 11+) is Unicode-aware --- it removes all Unicode whitespace, including non-breaking spaces.
Prefer `strip()` in new code.
`isBlank()` returns `true` if the string is empty or contains only whitespace.

```java
String s = "  hola  ";
System.out.println(s.trim());    // "hola"
System.out.println(s.strip());   // "hola"
System.out.println(s.isBlank()); // false
System.out.println("   ".isBlank()); // true
```

### Splitting

\index{String!split()}

```java
String[] split(String regex)
String[] split(String regex, int limit)
```

`split()` takes a regular expression and returns an array of substrings.
If you are splitting on a literal dot or pipe, you must escape them: `split("\\.")`, `split("\\|")`.

```java
String csv = "Pulp,Common People,1995";
String[] parts = csv.split(",");
// parts[0] = "Pulp"
// parts[1] = "Common People"
// parts[2] = "1995"
```

### Conversion and Repetition

\index{String!valueOf()}
\index{String!repeat()}

```java
static String valueOf(boolean b)
static String valueOf(char c)
static String valueOf(int i)
static String valueOf(long l)
static String valueOf(float f)
static String valueOf(double d)
static String valueOf(Object obj)
String repeat(int count)    // Java 11+
```

`valueOf()` converts a primitive or object to its string representation.
`repeat()` returns the string repeated `count` times, similar to Python's `"x" * n`.

```java
String s = String.valueOf(1995);   // "1995"
String bar = "-".repeat(20);      // "--------------------"
```

### Joining

\index{String!join()}
\index{String!chars()}

```java
static String join(CharSequence delimiter, CharSequence... elements)
static String join(CharSequence delimiter, Iterable<? extends CharSequence> elements)
```

`String.join()` is the Java equivalent of Python's `str.join()` or C++23's `std::format` join workarounds.

```java
String joined = String.join(", ", "Pulp", "Blur", "Oasis");
System.out.println(joined); // Pulp, Blur, Oasis
```

`String.chars()` returns an `IntStream` of character code points, useful with the Stream API (Chapter 14).

## StringBuilder

\index{StringBuilder}
\index{StringBuffer}

`StringBuilder` is Java's mutable string buffer.
Think of it as a `std::string` you build up piece by piece before converting it to an immutable `String`.

### Signatures

```java
StringBuilder append(String str)
StringBuilder append(int i)
StringBuilder append(char c)
StringBuilder append(double d)
// ... heavily overloaded for all primitive types and Object
StringBuilder insert(int offset, String str)
StringBuilder delete(int start, int end)
StringBuilder deleteCharAt(int index)
StringBuilder reverse()
StringBuilder replace(int start, int end, String str)
int length()
char charAt(int index)
String toString()
```

All mutating methods return `this`, so they can be chained.

### Fixing the Loop

Here is the slow string concatenation loop from earlier, rewritten with `StringBuilder`:

```java
StringBuilder sb = new StringBuilder();
for (int i = 0; i < 100; i++) {
    sb.append(i);
    sb.append(", ");
}
String result = sb.toString();
```

Only one object is built up; no intermediate copies.

### Example

```java
// "Common People" - Pulp (1995)
StringBuilder sb = new StringBuilder();
sb.append("I took her to a supermarket").append('\n');
sb.append("I don't know why but I had to start it").append('\n');
sb.reverse();   // reverses the entire buffer in place
System.out.println(sb.toString());
```

### StringBuffer

\index{StringBuffer}

`StringBuffer` is an older, thread-safe version of `StringBuilder`.
Its methods are `synchronized`, which makes it safe to use from multiple threads but adds locking overhead.
In practice, you almost never need `StringBuffer`: if you are sharing a string builder across threads you almost certainly have a design problem.
Use `StringBuilder` by default.

::: {.tip}
**Tip:** Always use `StringBuilder`, not `StringBuffer`, unless you have a documented reason to share a mutable string buffer across threads.
:::

## Text Blocks

\index{text block}
\index{String!text block}

Java 13 introduced **text blocks** (finalized in Java 15): triple-quoted string literals that preserve indentation and newlines without escaping.
If you have ever wrestled with multiline C++ raw string literals (`R"(...)"`) or escaped every quote in a JSON string, you will appreciate this.

A text block begins with `"""` followed immediately by a newline and ends with a closing `"""` on its own line (or on the last content line):

```java
String json = """
        {
            "artist": "Pulp",
            "song":   "Common People",
            "year":   1995
        }
        """;
```

The indentation of the closing `"""` determines how much leading whitespace is stripped from each line.
Here the closing `"""` is indented eight spaces, so eight spaces are stripped from every content line, leaving the JSON body cleanly indented with four spaces.

```java
String sql = """
        SELECT artist, title
        FROM   songs
        WHERE  year = 1995
        ORDER BY artist
        """;
```

::: {.tip}
**Tip:** Text blocks are ideal for embedding SQL, JSON, HTML, and XML in Java code.
They eliminate the escaping and concatenation noise that makes embedded literals hard to read.
:::

::: {.tip}
**Wut:** A text block is still an immutable `String` --- it is just a nicer syntax for creating one.
All the same immutability rules apply.
:::

## String.format() and formatted()

\index{String.format()}
\index{String!formatted()}
\index{printf!Java}

Java's `String.format()` works like C's `sprintf`: it produces a formatted string according to a format specifier, without printing it.

```java
static String format(String format, Object... args)
static String format(java.util.Locale l, String format, Object... args)
```

Java 15 added `formatted()` as an instance method that does the same thing:

```java
String formatted(Object... args)  // Java 15+
```

Common format specifiers:

| Specifier | Prints |
|:----------|:-------|
| `%s`      | string (calls `toString()` on objects) |
| `%d`      | integer (decimal) |
| `%f`      | floating-point (6 decimal places by default) |
| `%.2f`    | floating-point with 2 decimal places |
| `%n`      | platform-specific line separator (prefer over `\n` in format strings) |
| `%10d`    | integer right-aligned in a field 10 wide |
| `%-10s`   | string left-aligned in a field 10 wide |
| `%05d`    | integer zero-padded to 5 digits |

```java
String artist = "Pulp";
int    year   = 1995;
double rating = 9.8;

// Static method
String msg = String.format("%-10s %d  %.1f/10", artist, year, rating);
System.out.println(msg); // Pulp       1995  9.8/10

// Instance method (Java 15+)
String msg2 = "%-10s %d  %.1f/10".formatted(artist, year, rating);
System.out.println(msg2); // Pulp       1995  9.8/10
```

`System.out.printf()` combines formatting and printing in one call:

```java
System.out.printf("Artist: %s%n", artist);
System.out.printf("Year:   %d%n", year);
```

::: {.tip}
**Tip:** Use `%n` instead of `\n` in format strings passed to `printf` and `String.format()`.
`%n` emits the platform-correct line separator (`\r\n` on Windows, `\n` everywhere else), which matters when writing files or network protocols.
:::

## Key Points

- `String` in Java is immutable --- every "modification" returns a new object.
- String literals are interned in the string pool; `==` compares object identity, not content.
- Always use `.equals()` (or `.equalsIgnoreCase()`) to compare string contents.
- `substring(begin, end)` is exclusive of `end`; this differs from C++'s `substr(pos, len)`.
- `strip()` is the modern replacement for `trim()` --- it is Unicode-aware (Java 11+).
- Use `StringBuilder.append()` in loops to avoid creating many temporary `String` objects.
- `StringBuffer` is thread-safe but almost never needed; prefer `StringBuilder`.
- Text blocks (`"""..."""`) eliminate escaping noise for multiline string literals (Java 15+).
- `String.format()` and `formatted()` work like C's `sprintf`; `System.out.printf()` prints directly.
- `String.join()` and `split()` handle delimiter-separated values.
