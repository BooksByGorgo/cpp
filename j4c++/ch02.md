# Your First Java Program

Every Java program you write is organized around classes, packages, and a well-known entry point.
If you are coming from C++, the familiar punctuation --- curly braces, semicolons, `if`/`else`, `for` --- will feel like home, but the structure around them is different enough to trip you up on your first day.
There are no header files, no preprocessor, no free functions, and no global variables at the top level.
Everything lives inside a class.

This chapter walks through a complete Java program token by token, explains the package and import system, breaks down `main`, and shows you how to produce output and read input.

## Hello, World

\index{Hello, World}

Here is the canonical Java Hello World program:

```java
package com.example;

public class HelloWorld {
    public static void main(String[] args) {
        System.out.println("Hello, World");
    }
}
```

Every token matters.
We will unpack each piece in this chapter.
Save this as `HelloWorld.java` (the filename must match the public class name exactly), compile with `javac HelloWorld.java`, and run with `java com.example.HelloWorld` (or `java HelloWorld` if you skip the `package` declaration for now).

## Packages and Imports

\index{package}
\index{import}

### Packages

In C++ you organize code into **namespaces** and manage compilation units with header files.
Java replaces both with **packages**.
\index{package!declaration}
A package is a hierarchical namespace declared at the very top of a source file, before anything else:

```java
package com.example.myapp;
```

Package names are conventionally written in reverse domain name order (`com.example`) to guarantee global uniqueness.
The directory structure must mirror the package hierarchy: a class in `com.example.myapp` must live in a directory `com/example/myapp/`.

::: {.tip}
**Tip:** The directory path and the package declaration must agree exactly.
If the file is in `src/com/example/myapp/Foo.java` but declares `package com.example`, `javac` will refuse to compile it.
:::

In C++ you can nest namespaces arbitrarily and they have no relationship to the filesystem.
In Java, the mapping between package and directory is enforced by the compiler.

### Imports

\index{import!statement}
\index{import!vs \#include}

`import` brings a type name (or a static member) into scope so you can refer to it by its short name:

```java
import java.util.ArrayList;
import java.util.List;
```

Without the `import`, you would have to write `java.util.ArrayList` everywhere.
With it, you write just `ArrayList`.

This is **not** like `#include`.
`#include` performs textual substitution --- it copies the contents of a header file into the current translation unit.
`import` in Java is purely a **naming convenience**; it tells the compiler what the short name means.
No code is copied.
No compilation of header contents is triggered.
There is no separate compilation model in the C++ sense; the compiler reads `.java` source files directly.

\index{import!wildcard}
You can import all types in a package with a wildcard:

```java
import java.util.*;    // imports all public types in java.util
```

Wildcard imports do not affect performance --- the compiler still only loads what it needs.
Most style guides prefer explicit imports for readability.

### java.lang Is Always Available

\index{java.lang}

The package `java.lang` is imported automatically in every Java file.
This is why you can write `String`, `System`, `Math`, `Integer`, and `Object` without any import statement.
Everything else requires an explicit import.

::: {.tip}
**Wut:** `String` is a class in `java.lang`, not a primitive type and not a keyword.
It behaves like a value in most contexts because the compiler has special support for string literals, but under the hood `String` is a full class.
This is unlike `std::string` in C++, which is an ordinary class with no compiler magic.
:::

### Static Imports

\index{import!static}

You can import static members (methods and fields) directly:

```java
import static java.lang.Math.PI;
import static java.lang.Math.sqrt;

double r = sqrt(2.0) * PI;
```

This is handy in test code where you want to call `assertEquals(...)` instead of `Assertions.assertEquals(...)`.

## `public static void main(String[] args)`

\index{main method}

Every standalone Java program needs an entry point.
In C++ that entry point is a free function:

```cpp
int main(int argc, char** argv) { ... }
```

In Java, `main` must live inside a class:

```java
public class App {
    public static void main(String[] args) { ... }
}
```

Each modifier has a specific meaning.

### `public`

\index{public}

`public` is an **access modifier**.
It means the method is accessible from anywhere --- other classes, other packages, and the JVM launcher itself.
`main` must be `public` so the JVM can invoke it.
We will cover all access modifiers in depth in the Classes chapter.

### `static`

\index{static method}

`static` means this method belongs to the **class**, not to an instance of the class.
You can call it without creating an object --- just like a free function in C++.
The JVM calls `main` without instantiating your class, so `main` must be `static`.

::: {.tip}
**Trap:** Forgetting `static` on `main` is a classic first-day mistake.
The code compiles, but the JVM throws an error at runtime: `Main method is not static in class App`.
:::

### `void`

\index{void return type}

`main` returns `void`.
Unlike C++, where `main` returns `int` to signal success or failure to the OS, Java's `main` returns nothing.
If you need to signal a non-zero exit code, call `System.exit(int)`.

### `String[] args`

\index{command-line arguments}
\index{String[] args}

`String[] args` is an array of `String` objects holding the command-line arguments.
This maps to `argv` in C++, but without the separate `argc` --- Java arrays carry their length in the `length` field:

| C++ | Java |
|:----|:-----|
| `int argc` | `args.length` |
| `char** argv` | `String[] args` |
| `argv[0]` is the program name | `args[0]` is the first user argument (no program name) |

Unlike C++, `args[0]` in Java is the first argument the user typed after the class name, not the executable name.

### Java 21+ Shorthand

\index{main method!Java 21 shorthand}

Java 21 introduced a preview feature (standardized in Java 25) allowing simpler entry points for single-file programs:

```java
void main() {
    System.out.println("shorter in Java 21+");
}
```

The canonical `public static void main(String[] args)` form is still the standard for all real programs and is what you will see in production code.

## Basic Syntax: What Is the Same, What Is Different

\index{syntax!Java vs C++}

### What Is the Same

Java inherited most of its syntax from C, the same ancestor as C++.
The following features work exactly as you expect:

- Curly braces delimit blocks.
- Statements end with semicolons.
- `if`, `else`, `while`, `do`/`while`, `for`, `break`, `continue`, `return` all work the same.
- `//` single-line comments and `/* */` multi-line comments are identical.
- Integer and floating-point arithmetic operators (`+`, `-`, `*`, `/`, `%`) work the same.
- Comparison operators (`==`, `!=`, `<`, `<=`, `>`, `>=`) work the same for primitives.
- Logical operators (`&&`, `||`, `!`) short-circuit the same way.
- Bitwise operators (`&`, `|`, `^`, `~`, `<<`, `>>`) work the same (with one addition: `>>>` unsigned right shift).
- The ternary operator `condition ? a : b` works the same.

### What Is Different

\index{no header files}
\index{no preprocessor}
\index{no global functions}

| C++ feature | Java equivalent |
|:------------|:----------------|
| `#include` | No equivalent; `import` handles naming only |
| Preprocessor (`#define`, `#ifdef`) | None; use constants and language features |
| Free functions | Static methods in a class |
| Global variables | Static fields in a class |
| `::` scope resolution | `.` for member access; no `::` in everyday code |
| `namespace Foo { }` | `package com.example;` (file-level only) |
| Multiple `.cpp` / `.h` per class | One `.java` file per public class (same name) |
| `std::string` | `String` (in `java.lang`, immutable) |
| Operator overloading | Not supported (except `+` on `String`, built into the compiler) |
| Pointers, `*`, `&`, `->` | References only; no pointer arithmetic |
| Destructors, RAII | Garbage collector; `try`-with-resources for cleanup |

::: {.tip}
**Wut:** Java has no `::` for scope resolution in ordinary code.
Member access always uses `.`: `System.out.println`, not `System::out::println`.
(Method references use `::`, but that is a different syntax covered in the Lambdas chapter.)
:::

::: {.tip}
**Trap:** `==` on objects compares **references** (identity), not values.
`"hello" == "hello"` might be `true` due to string interning, but you cannot rely on it.
Always use `.equals()` to compare object values.
This is covered in depth in the Strings chapter.
:::

## `System.out.println` and Basic I/O

\index{System.out}
\index{println}
\index{PrintStream}

### Output

`System.out` is a public static field of type `PrintStream`.
\index{PrintStream}
It is the Java equivalent of `std::cout`, wired to standard output.

The methods you will use most:

```
void println(Object x)
void println(String x)
void print(Object x)
void print(String x)
void printf(String format, Object... args)
```

`println` calls `toString()` on its argument and appends a newline.
`print` does the same without the newline.
`printf` uses C-style format strings.

```java
System.out.println("Te quiero");       // prints: Te quiero\n
System.out.print("Losing");            // prints: Losing (no newline)
System.out.print(" My Religion\n");    // prints:  My Religion\n
System.out.printf("Year: %d%n", 1991); // prints: Year: 1991\n
```

::: {.tip}
**Tip:** In `printf` format strings, prefer `%n` over `\n` for the newline.
`%n` emits the platform-correct line separator (CRLF on Windows, LF elsewhere), while `\n` always emits a bare LF.
:::

`PrintStream` also has `format`, which is identical to `printf`:

```
PrintStream format(String format, Object... args)
```

And `System.err` is a second `PrintStream` wired to standard error, used exactly like `System.out`:

```java
System.err.println("something went wrong");
```

### A Running Example

Here is a small program that puts it all together using the assigned 1990s reference:

```java
public class Religion {
    public static void main(String[] args) {
        // "Losing My Religion" - R.E.M. (1991)
        String song   = "Losing My Religion"; // title
        String artist = "R.E.M.";             // band
        int    year   = 1991;                 // released

        System.out.printf("%-20s  %s  (%d)%n", song, artist, year);
        System.out.println("That's me in the corner");
        System.out.println("That's me in the spotlight");
    }
}
```

Output:

```
Losing My Religion    R.E.M.  (1991)
That's me in the corner
That's me in the spotlight
```

### Reading Input with Scanner

\index{Scanner}
\index{java.util.Scanner}

Java's nearest equivalent to `std::cin` is `Scanner`.
It is not in `java.lang`, so you must import it:

```java
import java.util.Scanner;

public class Greeter {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        System.out.print("Enter your name: ");
        String name = sc.nextLine();
        System.out.println("Hola, " + name + "!");
        sc.close();
    }
}
```

Key `Scanner` methods:

| Method | What it reads |
|:-------|:--------------|
| `nextLine()` | One full line as a `String` |
| `next()` | Next whitespace-delimited token as a `String` |
| `nextInt()` | Next token parsed as `int` |
| `nextDouble()` | Next token parsed as `double` |
| `hasNextLine()` | `true` if more input exists |

`Scanner` wraps any `InputStream`, so `new Scanner(System.in)` reads from standard input, but `new Scanner(new File("data.txt"))` reads from a file.
We will cover file I/O in the I/O chapter.

::: {.tip}
**Trap:** Mixing `nextInt()` (or `nextDouble()`) with `nextLine()` leaves a dangling newline in the buffer.
If you call `nextLine()` right after `nextInt()`, you get an empty string.
The fix: call `nextLine()` once after `nextInt()` to consume the leftover newline, then call `nextLine()` again for the actual input.
:::

## Key Points

- Every Java file begins with an optional `package` declaration, then `import` statements, then class definitions.
- `import` is a naming shortcut, not textual inclusion; it has no analog to `#include`.
- `java.lang` is always imported automatically; everything else requires an explicit import.
- `main` must be `public static void main(String[] args)` for the JVM to launch it.
- `static` means no instance is needed; `public` means the JVM can reach it from outside the class.
- `args[0]` is the first user-supplied argument, not the program name.
- Java has no header files, no preprocessor, no free functions, and no top-level global variables.
- `==` on objects compares identity, not value; use `.equals()` for value comparison.
- `System.out` is a `PrintStream`; use `println`, `print`, and `printf` for output.
- Use `Scanner` with `new Scanner(System.in)` for console input.

   What are the design advantages and disadvantages of this restriction?

    ```java

            String a = "corner";

            System.out.println(a == c);
            System.out.println(a.equals(c));
        }
    }
    ```

    ```java
    public class Args {
        public static void main(String[] args) {

    ```

    What happens when you run it with `java Broken`, and why?
