# Control Flow

\index{control flow}
Java programmers are immediately comfortable with `if`, `for`, and `switch` in Go --- the syntax is close enough that you can write working code on day one.
But Go has a few surprises: there is only one loop keyword, `switch` does not fall through by default, and `defer` is a concept with no Java equivalent.
This chapter covers all of it.

## if / else

\index{if}
`if` and `else` work the same as in Java.
The main syntactic difference is that the condition does not require parentheses (though they are allowed).

```go
score := 95
if score >= 90 {
    fmt.Println("A")
} else if score >= 80 {
    fmt.Println("B")
} else {
    fmt.Println("C")
}
// A
```

### The Init Statement

\index{if!init statement}
Go's `if` statement supports an optional **init statement** separated from the condition by a semicolon.
Variables declared in the init statement are scoped to the entire `if`/`else if`/`else` chain --- they disappear after the closing brace.

```go
if n := rand.IntN(10); n < 5 {
    fmt.Println("low:", n)
} else {
    fmt.Println("high:", n)
}
// n is not accessible here
```

The most common use is capturing the result of a function call and checking the error in one line:

```go
if err := doSomething(); err != nil {
    fmt.Println("error:", err)
    return
}
```

This pattern is ubiquitous in Go.
You will see it constantly when you read idiomatic Go code.
Chapter 10 covers error handling in full, but start recognising this shape now.

## for --- the Only Loop

\index{for}
Go has exactly one loop keyword: `for`.
There is no `while`, no `do...while`, and no `foreach` (that role is played by `for range`).
Three forms cover every use case.

### C-Style Loop

The familiar three-clause form works exactly as in Java:

```go
for i := 0; i < 5; i++ {
    fmt.Println(i)
}
// 0 1 2 3 4 (each on its own line)
```

### While-Style Loop

Omit the init and post clauses and you get a while loop:

```go
n := 1
for n < 100 {
    n *= 2
}
fmt.Println(n) // 128
```

### Infinite Loop

Omit the condition entirely for an infinite loop.
Use `break` to exit.

```go
for {
    line := readLine()
    if line == "" {
        break
    }
    process(line)
}
```

::: {.tip}
**Tip:** The infinite `for` loop with an explicit `break` is the idiomatic Go replacement for `do...while`.
:::

## range

\index{range}
`for range` provides the idiomatic iteration over collections, strings, channels, and (as of Go 1.22) integers.

### Slices and Arrays

```go
fruits := []string{"manzana", "naranja", "uva"}
for i, v := range fruits {
    fmt.Println(i, v)
}
// 0 manzana
// 1 naranja
// 2 uva
```

### Maps

```go
m := map[string]int{"one": 1, "two": 2, "three": 3}
for k, v := range m {
    fmt.Println(k, v)
}
// output order is random --- never rely on it
```

::: {.tip}
**Wut:** Map iteration order in Go is deliberately randomised on every run.
Java's `HashMap` also makes no order guarantee, but in practice the order is stable within a run.
Go actively randomises it to prevent accidental reliance on order.
:::

### Strings

As covered in Chapter 3, `for range` over a string decodes UTF-8 runes.
The index is the **byte** position, and the value is a **rune**:

```go
for i, r := range "café" {
    fmt.Printf("%d: %c\n", i, r)
}
// 0: c
// 1: a
// 2: f
// 3: é
```

### Channels

`for range` on a channel receives values until the channel is closed.
Channels are covered in Chapter 11.

### Integers (Go 1.22+)

\index{range!integer}
Since Go 1.22, you can range directly over an integer to get the sequence 0 to n-1:

```go
for i := range 5 {
    fmt.Print(i, " ")
}
// 0 1 2 3 4
```

### Iterator Functions (Go 1.23+)

\index{range!iterator}
Since Go 1.23, `for range` can iterate over functions that match the iterator function signature defined in the `iter` package (`iter.Seq[V]` or `iter.Seq2[K, V]`).
This allows library authors to expose custom iterators.
Details are in Chapter 18.

### Discarding Values with `_`

\index{blank identifier}
Use the blank identifier `_` to discard the index or the value when you do not need it:

```go
for _, v := range fruits {
    fmt.Println(v) // index discarded
}

for i := range fruits {
    fmt.Println(i) // value implicitly discarded (single-variable range)
}
```

## switch

\index{switch}
Go's `switch` looks familiar but has two important differences from Java:

1. Cases do **not** fall through by default.
2. The `switch` expression is optional.

### Basic switch

```go
day := "lunes"
switch day {
case "lunes", "martes", "miércoles", "jueves", "viernes":
    fmt.Println("weekday")
case "sábado", "domingo":
    fmt.Println("weekend")
default:
    fmt.Println("unknown")
}
// weekday
```

Notice that multiple values can appear in one case, separated by commas.
No `break` is needed --- each case exits automatically.

::: {.tip}
**Wut:** In Java, forgetting `break` causes execution to fall into the next case.
In Go, the opposite is true: execution stops at the end of each case by default.
This eliminates an entire class of Java bugs.
:::

### fallthrough

\index{fallthrough}
When you genuinely need Java-style fall-through, use the `fallthrough` keyword explicitly.
It transfers control to the **first statement** of the next case body without re-evaluating the case condition.

```go
n := 1
switch n {
case 1:
    fmt.Println("one")
    fallthrough
case 2:
    fmt.Println("one or two")
case 3:
    fmt.Println("three")
}
// one
// one or two
```

`fallthrough` is unconditional --- it always falls through regardless of whether the next case condition would match.
It is rarely needed in practice.

### Expression-Less switch

\index{switch!expression-less}
Omit the switch expression and each case becomes an independent boolean condition.
This is a cleaner alternative to a long `if`/`else if` chain:

```go
temp := 38.5
switch {
case temp < 0:
    fmt.Println("freezing")
case temp < 20:
    fmt.Println("cold")
case temp < 37:
    fmt.Println("warm")
default:
    fmt.Println("fiebre!")
}
// fiebre!
```

### Type Switch (Preview)

\index{type switch}
A type switch selects a case based on the dynamic type of an interface value:

```go
switch v := i.(type) {
case int:
    fmt.Println("int:", v)
case string:
    fmt.Println("string:", v)
default:
    fmt.Printf("other: %T\n", v)
}
```

Type switches are covered fully in Chapter 9 alongside interfaces.

## Labeled break and continue

\index{labeled break}
\index{labeled continue}
Java supports labeled statements to break out of nested loops.
Go supports the same with labeled `break` and `continue`.

```go
outer:
for i := 0; i < 3; i++ {
    for j := 0; j < 3; j++ {
        if i == 1 && j == 1 {
            break outer // exits both loops
        }
        fmt.Println(i, j)
    }
}
// 0 0
// 0 1
// 0 2
// 1 0
```

`continue outer` would skip the rest of the inner loop body and continue with the next iteration of the outer loop.

### goto

\index{goto}
Go has `goto`, which jumps to a labeled statement within the same function.
It cannot jump over variable declarations.
It is legal but almost never the right tool --- `goto` is mentioned here so you know it exists, not as an invitation to use it.

## defer

\index{defer}
`defer` is one of Go's most distinctive features.
A `defer` statement pushes a function call onto a per-function stack.
All deferred calls run when the enclosing function returns, in **last-in, first-out** (LIFO) order.

```go
func greet() {
    defer fmt.Println("goodbye")
    defer fmt.Println("see you later")
    fmt.Println("hello")
}

// greet() prints:
// hello
// see you later
// goodbye
```

### Arguments Are Evaluated Immediately

\index{defer!argument evaluation}
The arguments to a deferred function call are evaluated **at the `defer` statement**, not when the deferred call actually runs.

```go
func demo() {
    x := 10
    defer fmt.Println(x) // x is captured as 10 right now
    x = 99
}
// prints: 10
```

This catches many Go beginners off guard.
The value of `x` at defer time (10) is baked in; the change to `x = 99` does not affect it.

### Closures Capture Variables by Reference

\index{defer!closure}
If the deferred function is a **closure** (an anonymous function with no arguments), it captures variables by reference and sees their values at the time it actually runs.

```go
func demo() {
    x := 10
    defer func() { fmt.Println(x) }() // closure, not a direct call
    x = 99
}
// prints: 99
```

This distinction is important: a deferred call with arguments evaluates the arguments immediately, but a deferred closure evaluates its captured variables lazily at return time.

### Common Uses

\index{defer!uses}
**Closing resources** is the most common use of `defer`:

```go
f, err := os.Open("cancion.txt")
if err != nil {
    return err
}
defer f.Close() // guaranteed to run even if the rest of the function panics
```

This pattern ensures cleanup happens no matter how the function exits --- return, error return, or panic.

**Releasing locks:**

```go
mu.Lock()
defer mu.Unlock()
```

**Printing structured exit messages** (useful during debugging):

```go
func process() {
    fmt.Println("process: start")
    defer fmt.Println("process: done")
    // ... work ...
}
```

### defer Runs Even During a Panic

\index{defer!panic}
If a function panics, all of its deferred calls still run before the panic propagates up the call stack.
This is why `defer f.Close()` is safe even when something unexpected happens.

```go
func riskyOp() {
    defer fmt.Println("cleanup always runs")
    panic("something went wrong")
}

func main() {
    riskyOp()
}
// prints: cleanup always runs
// then panics
```

::: {.tip}
**Tip:** Pair `defer` with `recover` (covered in Chapter 10) to catch a panic and return a normal error instead of crashing the program.
:::

## init()

\index{init()}
Every Go source file can declare one or more `init` functions:

```go
func init() {
    // runs before main
}
```

`init` functions are called automatically by the Go runtime after all package-level variables have been initialised, and before `main` runs.
You cannot call `init` explicitly --- the runtime owns it.

### Rules

- A single file may contain multiple `init` functions; they run in source order.
- Multiple files in a package: `init` functions run in the order the compiler processes the files (alphabetical by filename).
- If package A imports package B, B's `init` functions complete before A's.
- `init` cannot be called directly by user code.

```go
// config.go
var configLoaded bool

func init() {
    loadConfig()
    configLoaded = true
}
```

### When to Use init()

Use `init` for:

- One-time setup that cannot be expressed as a simple variable initialiser.
- Registering database drivers, codec implementations, or similar plugin-style registrations.
- Validating configuration at startup before anything else runs.

::: {.tip}
**Trap:** Overusing `init` makes the startup sequence hard to follow and test.
Prefer explicit initialisation in `main` or in constructor functions when possible.
:::

## Key Points

- `if` supports an init statement: `if err := f(); err != nil` --- scopes the variable to the block.
- `for` is the only loop keyword in Go; it covers C-style, while-style, and infinite loops.
- `for range` iterates slices (index+value), maps (key+value), strings (byte-index+rune), channels, integers (Go 1.22), and iterator functions (Go 1.23).
- Map iteration order is deliberately randomised.
- `switch` does not fall through by default; use `fallthrough` explicitly when needed.
- An expression-less `switch` acts as a cleaner if/else chain.
- Labeled `break` and `continue` break out of nested loops.
- `defer` pushes a call onto a LIFO stack; all deferred calls run when the function returns.
- Defer arguments are evaluated immediately; closures in defer capture variables by reference.
- `defer` runs even when the function panics.
- `init()` runs before `main`, after package-level variable initialisation; it cannot be called explicitly.
