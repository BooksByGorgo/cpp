# Introduction

Java's syntax was derived directly from C.
Curly braces, semicolons, `if`/`else`, `for`, `while`, `switch` --- all of that came from C.
If you have written Java, you have already been writing C-flavored code without knowing it.
The differences are real, but they are narrower than you might expect.

This chapter introduces you to C, shows you the go-to reference book, and gets you writing and printing output right away.

## The Book

\index{K\&R}
\index{The C Programming Language}

The definitive reference for C is **The C Programming Language, Second Edition** by Brian W. Kernighan and Dennis M. Ritchie.
It is commonly called **K&R** after its authors.
Dennis Ritchie invented C, so this is about as authoritative as it gets.
It is a slim book, clearly written, and worth having on your shelf.

K&R opens with this:

> **Getting Started**
>
> The only way to learn a new programming language is by writing programs in it.
> The first program to write is the same for all languages:
> Print the words hello, world.
> This is the big hurdle; to leap over it you have to be able to create the program text somewhere, compile it successfully, load it, run it, and find out where your output went.
> With these mechanical details mastered, everything else is comparatively easy.
>
> In C, the program to print "hello, world" is
>
>     #include <stdio.h>
>     main()
>     {
>         printf("hello, world\n");
>     }
>
> Just how to run this program depends on the system you are using.
> As a specific example, on the UNIX operating system you must create the program in a file whose name ends in ".c", such as hello.c, then compile it with the command `cc hello.c`.
> If you haven't botched anything, such as omitting a character or misspelling something, the compilation will proceed silently, and make an executable file called a.out.
> If you run a.out by typing the command `a.out`, it will print `hello, world`.
> On other systems, the rules will be different; check with a local expert.

The K&R example above is written in pre-ANSI C style.
A modern version looks like this:

```c
#include <stdio.h>

int main(void) {
    printf("hello, world\n");
    return 0;
}
```

The differences are small but worth noting: `int main(void)` declares that `main` takes no arguments and returns an integer, and `return 0;` signals success to the operating system.
We will use modern C (C11 or later) throughout this booklet.

## `#include`

\index{\#include}
\index{header file}

The very first line of the K&R example is `#include <stdio.h>`.
In Java, you bring in external code with `import`:

```java
import java.util.ArrayList;
```

`#include` looks similar but works very differently.
It is a **preprocessor directive** --- before the compiler sees your code at all, a preprocessing step runs and literally **pastes the contents** of the named file into your source file in place of the `#include` line.

\index{preprocessor}

```c
#include <stdio.h>   /* pastes the system stdio.h file here */
#include "myutils.h" /* pastes your own header file here */
```

Angle brackets (`< >`) tell the preprocessor to look in the system include directories.
Double quotes (`" "`) tell it to look in the current directory first, then fall back to the system directories.

Unlike a Java `import`, which is purely a name-resolution shortcut that lets you write `ArrayList` instead of `java.util.ArrayList`, `#include` has no notion of packages or namespaces.
Everything pasted in becomes part of your file.

So what is in those header files?
Mostly **declarations** --- statements that tell the compiler a function or type exists and what it looks like, without providing the actual implementation.
For example, `<stdio.h>` contains the declaration for `printf` so the compiler knows what arguments it takes and what it returns.
The actual implementation of `printf` lives in a compiled library that gets linked in when you build the executable.

::: {.tip}
**Tip:** A C `#include` is not optional the way a Java `import` is.
In Java, `import java.util.ArrayList` just saves you from writing the full name everywhere --- you can always write `java.util.ArrayList` without any import at all.
In C, if you do not `#include <stdio.h>`, the compiler has no declaration for `printf` and will reject the call.
Also unlike `import`, including the same header twice produces duplicate declarations --- which is why well-written headers use **include guards** (`#ifndef MYHEADER_H` / `#define MYHEADER_H` / `#endif`) to prevent this.
:::

## Declarations and Definitions

\index{declaration}
\index{definition}

In Java, when you write a method, you declare and define it simultaneously:

```java
// declare and define at the same time --- Java style
public int add(int a, int b) {
    return a + b;
}
```

C separates these two concepts.

A **declaration** tells the compiler that something exists and describes its type --- but provides no implementation.
A **definition** provides the actual implementation (for functions) or allocates actual storage (for variables).

\index{function!prototype}

For a function, the declaration is called a **prototype**:

```c
int add(int a, int b);   /* declaration (prototype) --- no body */
```

The definition comes later:

```c
int add(int a, int b) {  /* definition --- with body */
    return a + b;
}
```

Why does C need this?
The C compiler processes files from top to bottom in a single pass.
If you call a function before its definition appears in the file, the compiler has not seen it yet and does not know what arguments it takes or what it returns.
A forward declaration solves this:

```c
#include <stdio.h>

int add(int a, int b);   /* forward declaration: compiler now knows about add */

int main(void) {
    printf("%d\n", add(3, 4));   /* valid: compiler has seen the declaration */
    return 0;
}

int add(int a, int b) {  /* definition can come after main */
    return a + b;
}
```

Java does not have this problem because the Java compiler reads all class members before resolving any method calls --- order within a class does not matter.

\index{header file!purpose}

This is exactly what header files are for.
A `.h` file contains the declarations (prototypes) for functions defined in a corresponding `.c` file.
Any other `.c` file that wants to call those functions `#include`s the header to get the declarations, and the linker connects the calls to the definitions at link time.

Structures can also be forward-declared:

```c
struct point;   /* forward declaration: compiler knows 'struct point' is a type */
```

You will see more of this in the Variables and Functions chapters.

::: {.tip}
**Wut:** Java programmers are sometimes surprised that the order of function definitions in a C file matters.
If `foo` calls `bar` and both are in the same `.c` file, either put `bar` before `foo`, or add a prototype for `bar` at the top of the file.
The Java compiler handles this for you; the C compiler does not.
:::

## Java vs C: A Quick Comparison

\index{Java!vs C}

Before diving in, here is a side-by-side overview of the most important differences:

| Java | C |
|:---|:---|
| `String` | `char` arrays with `'\0'` |
| `ArrayList` | raw arrays or `malloc` |
| `System.out.println` | `printf` |
| `Scanner` | `scanf` |
| `new` / GC | `malloc` / `free` |
| Objects (auto GC) | Raw pointers (manual memory) |
| References | Pointers (`*`) |
| `boolean` (built-in) | `_Bool` or `#include <stdbool.h>` |
| `// comments` | `//` works; `/* comments */` common in older code |

Java compiles to bytecode that runs on the JVM.
C compiles directly to native machine code for the target CPU.
There is no virtual machine, no garbage collector, and no runtime safety net.
That means faster execution and full control --- and also means that when you make a mistake, the consequences are immediate.

## printf

\index{printf}
\index{stdio.h}

C does not have `System.out.println`.
Output goes through `printf`, declared in `<stdio.h>`.
You must `#include <stdio.h>` at the top of any file that uses it.

`printf` takes a **format string** followed by values to print.
The format string can contain plain text and **format specifiers** that describe how to print each value.

\index{format specifier}

### Format Specifiers

\index{printf!format specifiers}

| Specifier | Prints | Example |
|:---|:---|:---|
| `%d` | `int` (decimal) | `printf("%d", 42);` prints `42` |
| `%x` | `int` (lowercase hex) | `printf("%x", 255);` prints `ff` |
| `%X` | `int` (uppercase hex) | `printf("%X", 255);` prints `FF` |
| `%f` | `double` (decimal notation) | `printf("%f", 3.14);` prints `3.140000` |
| `%e` | `double` (scientific notation) | `printf("%e", 3.14);` prints `3.140000e+00` |
| `%c` | `char` | `printf("%c", 'A');` prints `A` |
| `%s` | `char *` (string) | `printf("%s", "hola");` prints `hola` |
| `%p` | pointer address | `printf("%p", ptr);` prints address |
| `%zu` | `size_t` (unsigned size) | `printf("%zu", sizeof(int));` |
| `%%` | literal `%` sign | `printf("100%%");` prints `100%` |

A few quick examples:

```c
#include <stdio.h>

int main(void) {
    int year   = 1982;           // Eye of the Tiger
    double bpm = 109.0;
    char   key = 'E';

    printf("Year: %d\n", year);
    printf("BPM:  %.1f\n", bpm);
    printf("Key:  %c\n", key);
    printf("Hex:  %x\n", year);    // 7be

    return 0;
}
```

### Width, Precision, and Zero-Fill

\index{printf!width}
\index{printf!precision}
\index{printf!zero-fill}

You can control the width of the printed field and the number of decimal places:

- `%8d` --- print an integer in a field 8 characters wide (right-aligned by default)
- `%-8d` --- left-align in an 8-character field
- `%08d` --- right-align and zero-fill to 8 characters
- `%.2f` --- print a floating-point number with exactly 2 decimal places
- `%8.2f` --- floating-point in an 8-wide field with 2 decimal places

```c
#include <stdio.h>

int main(void) {
    printf("[%8d]\n",  1984);    // [    1984]
    printf("[%-8d]\n", 1984);    // [1984    ]
    printf("[%08d]\n", 1984);    // [00001984]
    printf("[%.2f]\n", 3.14159); // [3.14]
    printf("[%8.2f]\n", 3.14);   // [    3.14]

    return 0;
}
```

### Escape Sequences

\index{escape sequence}

Inside a format string, `\n` means newline.
Other common escape sequences:

| Sequence | Meaning |
|:---|:---|
| `\n` | newline |
| `\t` | tab |
| `\\` | literal backslash |
| `\"` | literal double-quote inside a string |
| `\0` | null character (end of a C string) |

::: {.tip}
**Tip:** `printf` does not automatically add a newline the way Java's `System.out.println` does.
If you want a newline, you must put `\n` at the end of your format string.
:::

::: {.tip}
**Trap:** Mismatching the format specifier and the argument type is undefined behavior.
Using `%d` to print a `double`, for example, will produce garbage output.
The compiler will warn you if you use `-Wall`; pay attention to those warnings.
:::

## scanf

\index{scanf}

`scanf` is the C standard library's input function, the rough equivalent of Java's `Scanner`.
It reads from standard input using the same format specifiers as `printf`.

```c
#include <stdio.h>

int main(void) {
    int year;

    printf("Enter a year: ");
    scanf("%d", &year);
    printf("You entered: %d\n", year);

    return 0;
}
```

Notice the `&` before `year`.
\index{address-of operator}
The `&` is the **address-of** operator --- it gives `scanf` the memory address of `year` so the function can store the value there.
This is the C equivalent of "passing by reference."
We will cover this in depth in the Pointers chapter.

::: {.tip}
**Trap:** Forgetting the `&` in `scanf` is one of the most common C bugs for beginners.
Without it, you are passing the *value* of `year` as an address, which will likely crash your program or silently corrupt memory.
:::

## Compiling a C Program

\index{compiling}
\index{cc}

To compile a C program on a Unix-like system:

```
cc -Wall -Wextra -pedantic -o hello hello.c
```

- `-Wall` enables most warnings
- `-Wextra` enables additional warnings
- `-pedantic` enforces strict standard conformance
- `-o hello` names the output executable `hello`

Run it with:

```
./hello
```

::: {.tip}
**Tip:** Always compile with `-Wall -Wextra -pedantic`.
C will let you write code that compiles without errors but has serious bugs.
Warnings are your first line of defense.
:::

## Try It

Type in this program, compile it, and run it.
Then modify it: change the format strings, try different specifiers, add more variables.

```c
#include <stdio.h>

int main(void) {
    /* "Don't Stop Believin'" - Journey (1981) */
    char  song[]  = "Don't Stop Believin'";
    char  artist[]= "Journey";
    int   year    = 1981;
    float minutes = 4.11f;

    printf("Song:    %s\n",    song);
    printf("Artist:  %s\n",    artist);
    printf("Year:    %d\n",    year);
    printf("Length:  %.2f min\n", minutes);
    printf("Year in hex: %x\n", year);    // 7bd

    /* Try reading a year from the user */
    int your_year;
    printf("\nEnter your birth year: ");
    scanf("%d", &your_year);
    printf("You were born in %d --- that makes you about %d years old.\n",
           your_year, year - your_year);

    return 0;
}
```

## Key Points

- Java's syntax came from C --- if you know Java, C syntax will feel familiar.
- `#include` physically pastes a header file into your source before compilation --- it is not like a Java `import`.
- Angle brackets (`< >`) include system headers; double quotes (`" "`) include local headers.
- Header files contain **declarations**; the corresponding `.c` files contain the **definitions**.
- A **declaration** describes a function's name, return type, and parameters --- no body.
- A **definition** provides the function body. The C compiler processes files top to bottom, so you must declare a function before calling it.
- Java handles this automatically; C does not.
- `#include <stdio.h>` brings in declarations for `printf` and `scanf`.
- `printf` uses format specifiers: `%d`, `%f`, `%c`, `%s`, `%x`, `%p`, `%zu`, `%%`.
- Width and precision modifiers control field width and decimal places.
- `\n` is required explicitly --- `printf` does not add a newline automatically.
- `scanf` reads input using the same format specifiers; always use `&` before variable names.
- C compiles to native machine code; there is no JVM and no garbage collector.
- Compile with `-Wall -Wextra -pedantic` and fix all warnings.
