
# Functions

In Java, every function is a method --- it must belong to a class.
There is no such thing as a free-standing function; even `main` lives inside a class.
In C, functions stand on their own.
There are no classes, no methods, no `this` pointer, and no implicit receiver object.
A C function is just a named block of code with parameters and a return value.

Java also provides method overloading, default parameters (via overloading), and the illusion of pass by reference for objects.
C has none of these.
What C does have is a clean, predictable model: every argument is copied, every function has a unique name, and if you want indirection, you use a pointer.
Once you internalize that model, C functions are easy to reason about.

## Function Declarations and Definitions

\index{function!declaration}
\index{function!definition}
\index{prototype}

A **declaration** (also called a **prototype**) tells the compiler the function's return type, name, and parameter types --- without the body.
A **definition** provides the body.

```c
int add(int a, int b);        // declaration (prototype) -- no body

int add(int a, int b) {       // definition -- has a body
    return a + b;
}
```

Parameter names are optional in a declaration --- `int add(int, int);` is just as legal.
They are usually included anyway because a prototype with good names documents how to call the function: `int divide(int dividend, int divisor);` tells you the argument order, `int divide(int, int);` leaves you guessing.

\index{header file}
In a multi-file C project, prototypes go in header files (`.h`) so that other `.c` files can call the function.
The definition lives in exactly one `.c` file.
In Java you never wrote a separate declaration; the class definition served both roles.
In C, forgetting the prototype means the compiler may reject the call or assume a wrong return type.

::: {.tip}
**Tip:** Always declare a function before you call it.
The safest way to ensure this is to put the prototype at the top of the file (or in a header file) and the definition later.
:::

## Empty Parameter Lists: Use `void`

\index{void parameter list}

In Java, `void foo()` unambiguously means "this method takes no arguments."
In C the story is more complicated:

```c
int get_score(void);    // takes no parameters -- compiler enforces this
int get_score();        // unspecified parameters -- compiler won't check
```

In C17 and earlier, `int foo()` means "takes an *unspecified* number and type of parameters" --- the compiler will accept any arguments you pass without complaint.
C23 changed this to match Java and C++: `int foo()` now means "takes no parameters."
Until C23 is universally available, write `int foo(void)` to be safe.

::: {.tip}
**Wut:** `int foo()` does NOT mean "takes no parameters" in C17 and earlier --- it means "takes some unspecified parameters."
This is a common source of hard-to-find bugs.
Always write `int foo(void)` when the function takes no arguments.
You will see `int main(void)` throughout this book for exactly this reason.
:::

## No Overloading

\index{function!overloading}

Java lets you define multiple methods with the same name as long as the parameter types differ:

```java
int max(int a, int b) { return a > b ? a : b; }
double max(double a, double b) { return a > b ? a : b; }  // fine in Java
```

C does not support this.
Every function must have a unique name.
If you need `max` for both `int` and `double`, you give them different names:

```c
int    max_int(int a, int b)          { return a > b ? a : b; }
double max_double(double a, double b) { return a > b ? a : b; }
```

The C standard library does exactly this.
`abs` handles `int`, and `fabs` handles `double`.
`strlen` returns a `size_t`, and the string functions come in versions for different tasks --- `strcmp`, `strncmp`, `strcasecmp`.
The naming convention carries the type information that overloading would otherwise provide.

## No Default Arguments

\index{function!default arguments}

Java programmers simulate default arguments with overloading:

```java
void greet(String name)            { greet(name, 1); }
void greet(String name, int times) { /* ... */ }
```

C has no overloading, so there are no default arguments either.
Every argument must be supplied at every call site.
C programmers use two conventions to get a similar effect.

\index{function!sentinel value}
**Sentinel values** treat a distinguished input --- `0`, `-1`, or `NULL` --- as "use the default":

```c
void play(const char *title, int times) {
    if (times <= 0) times = 1;   // 0 means "use the default"
    for (int i = 0; i < times; i++) {
        printf("Playing: %s\n", title);
    }
}

play("Girls Just Want to Have Fun", 0);   // plays once (default)
play("Take On Me",                  3);   // plays three times
```

\index{function!name variation}
**Name variations** provide a short-name wrapper that calls the full version with the default filled in:

```c
void play_n(const char *title, int times) {
    for (int i = 0; i < times; i++) {
        printf("Playing: %s\n", title);
    }
}

void play(const char *title) {
    play_n(title, 1);   // default of 1
}
```

::: {.tip}
**Tip:** Use name variations when the default represents a meaningfully different call (e.g., writing to `stdout` vs. an arbitrary file, as `printf` vs. `fprintf`).
Use sentinel values to indicate "use the default" when a parameter has values that no caller would ever mean literally.
For example, `NULL` is an invalid pointer value; you cannot have a negative number of items, so `-1` is a good sentinel value for a count.
:::

## Pass by Value

\index{pass by value}

As you saw in the Pointers chapter, all function parameters in C are pass by value.
Every argument is copied.
To modify a caller's variable, pass a pointer to it.
There are no `&` reference parameters in C; every "output" parameter is a pointer.

Java programmers often think Java is "pass by reference" for objects.
It is not.
Java passes a copy of the object reference (a copy of the pointer).
The method can use that copy to reach and modify the object's fields, but it cannot make the caller's variable point to a different object.
C makes this explicit --- you always know exactly what is being copied.

## `const` Parameters

\index{const!parameter}

When a function receives a pointer, the caller cannot tell from the call site whether the function plans to modify the data the pointer points to.
The `const` keyword makes a promise: "I will not modify what this pointer points to."

```c
#include <stdio.h>

void sing(const char *lyrics) {
    printf("%s\n", lyrics);
    // lyrics[0] = 'X';   // ERROR -- const pointer
}

int main(void) {
    sing("Don't you forget about me");
    return 0;
}
```

\index{const!documentation}
Using `const` serves two purposes.
First, it documents intent --- anyone reading the prototype knows the function will not modify the data.
Second, it catches bugs at compile time.
If you accidentally try to write through a `const` pointer, the compiler stops you.

::: {.tip}
**Tip:** Make every pointer parameter `const` unless the function genuinely needs to modify the pointed-to data.
`const char *` is the standard type for "a string I will read but not change."
Functions like `printf`, `strlen`, and `strcmp` all take `const char *` for exactly this reason.
:::

## Passing Structures

\index{struct!passing}

Structures can be passed by value just like any other type.
The function receives a complete copy of the struct:

```c
#include <stdio.h>

struct song {
    char title[50];
    int  year;
};

void print_song(struct song s) {
    printf("\"%s\" (%d)\n", s.title, s.year);
}

int main(void) {
    struct song fav = {"White Wedding", 1982};
    print_song(fav);   // passes a COPY of fav
    return 0;
}
```

This works, but copying a large struct on every call is wasteful.
If `struct song` held a large album art buffer, every call would copy all of it onto the stack.
The solution is to pass a pointer.
Since `print_song` only reads the data, use `const`:

```c
void print_song(const struct song *s) {
    printf("\"%s\" (%d)\n", s->title, s->year);
}

int main(void) {
    struct song fav = {"White Wedding", 1982};
    print_song(&fav);   // passes only an 8-byte pointer
    return 0;
}
```

When the function needs to modify the struct, drop the `const`:

```c
void set_year(struct song *s, int year) {
    s->year = year;
}
```

::: {.tip}
**Tip:** For small structs (a handful of bytes), passing by value is fine and sometimes clearer.
For anything larger, prefer `const struct type *param`.
This is the C equivalent of Java's object reference parameter --- the pointer is copied, but the data the pointer points to is not.
:::

## Recursive Functions

\index{recursion}

C supports recursion just like Java.
A function can call itself, and each call gets its own frame on the call stack with its own set of local variables.

```c
#include <stdio.h>

long factorial(int n) {
    if (n <= 1)
        return 1;
    return n * factorial(n - 1);
}

int main(void) {
    printf("5!  = %ld\n", factorial(5));    // 120
    printf("10! = %ld\n", factorial(10));   // 3628800
    return 0;
}
```

::: {.tip}
**Trap:** C has no stack overflow exception.
When a recursive function goes too deep, the stack simply runs out of space and the program crashes with a segmentation fault.
Keep your recursion depth reasonable, or convert deep recursion to an iterative loop.
Java throws a `StackOverflowError` and gives you a useful stack trace; C gives you a crash and silence.
:::

## Function Pointers

\index{function pointer}

In Java, you pass behavior around using interfaces, abstract classes, or lambdas.
C has none of those --- but it does have **function pointers**.
A function pointer is a variable that holds the address of a function.
You can store it, pass it to another function, and call the function through it.

### Declaring Function Pointers

The syntax is unusual.
A pointer to a function that takes two `int` parameters and returns an `int` looks like this:

```c
int (*fp)(int, int);
```

Read it from the inside out: `fp` is a pointer (`*fp`) to a function that takes `(int, int)` and returns `int`.

::: {.tip}
**Wut:** The parentheses around `*fp` are critical.
Without them, `int *fp(int, int)` declares a *function* that returns `int *` --- a completely different thing.
The parentheses force `fp` to be a pointer first.
:::

### Using Function Pointers

A function name decays to a pointer to that function, just like an array name decays to a pointer to its first element.
You assign a function to a function pointer by name, and call through the pointer with normal call syntax:

```c
#include <stdio.h>

int add(int a, int b)      { return a + b; }
int multiply(int a, int b) { return a * b; }

int main(void) {
    int (*op)(int, int);

    op = add;
    printf("3 + 4 = %d\n", op(3, 4));    // 7

    op = multiply;
    printf("3 * 4 = %d\n", op(3, 4));    // 12

    return 0;
}
```

### Simplifying with `typedef`

\index{typedef!function pointer}

The raw function pointer syntax is noisy.
A `typedef` gives it a readable name:

```c
#include <stdio.h>

typedef int (*math_fn)(int, int);

int sumar(int a, int b)  { return a + b; }    // sumar = add in Spanish
int restar(int a, int b) { return a - b; }    // restar = subtract in Spanish

void compute(math_fn fn, int x, int y) {
    printf("  result = %d\n", fn(x, y));
}

int main(void) {
    compute(sumar,  10, 3);    //   result = 13
    compute(restar, 10, 3);    //   result = 7
    return 0;
}
```

Now `math_fn` is a type that means "pointer to a function taking two `int`s and returning `int`."
You can use it for parameters, local variables, struct members, and arrays of function pointers.

### Callbacks

\index{callback}

Function pointers are most useful as **callbacks** --- you pass a function pointer to another function, which calls it at the right moment.

Imagine a lineup of 80s cartoon heroes and you want to apply some action to each one:

```c
#include <stdio.h>

typedef void (*action_fn)(const char *);

void announce(const char *hero) {
    printf("By the power of Grayskull: %s!\n", hero);
}

void introduce(const char *hero) {
    printf("For the honor of Grayskull: %s!\n", hero);
}

void run_lineup(const char *heroes[], int count, action_fn act) {
    for (int i = 0; i < count; i++) {
        act(heroes[i]);
    }
}

int main(void) {
    const char *lineup[] = {
        "He-Man",
        "She-Ra",
        "Teela"
    };

    printf("-- Announcing --\n");
    run_lineup(lineup, 3, announce);

    printf("-- Introducing --\n");
    run_lineup(lineup, 3, introduce);

    return 0;
}
```

The Odds and Ends chapter shows a real-world example using `qsort`, the standard library's sorting function, which takes a comparison callback.

::: {.tip}
**Tip:** In Java, you pass behavior with an interface or a lambda.
In C, you pass a function pointer.
The concept is the same --- you are passing a piece of callable code to another function --- only the syntax differs.
:::

## Try It

This program ties together prototypes, `const` parameters, struct pointers, recursion, and function pointers:

```c
#include <stdio.h>

// Prototype with const pointer parameter
void dancing(const char *msg);

// Struct and a function that takes a const pointer to it
struct song {
    char title[50];
    int  year;
};

void print_song(const struct song *s) {
    printf("\"%s\" (%d)\n", s->title, s->year);
}

// Recursive countdown
void countdown(int n) {
    if (n <= 0) {
        printf("Go!\n");
        return;
    }
    printf("%d...\n", n);
    countdown(n - 1);
}

// Function pointer demo
int sumar(int a, int b)  { return a + b; }
int restar(int a, int b) { return a - b; }

typedef int (*math_fn)(int, int);

void compute(math_fn fn, int x, int y) {
    printf("  result = %d\n", fn(x, y));
}

// Definition of dancing (declared above)
void dancing(const char *msg) {
    printf(">>> %s <<<\n", msg);
}

int main(void) {
    // const parameter
    dancing("Dancing in the Dark");

    // Passing a struct by pointer
    struct song fav = {"Footloose", 1984};
    print_song(&fav);

    // Recursion
    countdown(3);

    // Function pointers
    printf("sumar:\n");
    compute(sumar,  8, 3);    //   result = 11
    printf("restar:\n");
    compute(restar, 8, 3);    //   result = 5

    return 0;
}
```

## Key Points

- C functions are standalone --- they do not belong to a class.
- Always declare a function before calling it.
  Use `int foo(void)` (not `int foo()`) to declare a function that takes no arguments, in C17 and earlier.
- C has no function overloading and no default arguments.
  Use distinct names (e.g., `max_int` vs. `max_double`) or sentinel values as workarounds.
- All parameters are pass by value.
  To modify a caller's variable, pass a pointer --- see the Pointers chapter.
- Use `const` on pointer parameters when the function does not modify the pointed-to data.
  It documents intent and catches bugs at compile time.
- For large structs, prefer `const struct type *param` over pass by value to avoid expensive copies.
- Function pointers let you store and pass functions as values.
  Use `typedef` to make the types readable.
  This is C's equivalent of Java interfaces or lambdas for callbacks.
