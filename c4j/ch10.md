# Standard I/O

\index{FILE}

In Java you use `System.out.println`, `System.out.printf`, and `Scanner` for I/O.
In C, all of that goes through `<stdio.h>` and the `FILE *` type --- an opaque pointer that tracks the state of an I/O stream.
You have already used `printf` in chapter 1.
This chapter goes deeper: reading input with `scanf`, working with files, writing formatted strings into buffers, and understanding how buffering works.

## `scanf` for Input

\index{scanf}

```c
int scanf(const char *format, ...);
```

For input from the keyboard, C uses `scanf`.
It reads formatted data from standard input using the same format specifiers as `printf`:

```c
#include <stdio.h>

int main(void) {
    int year;
    printf("Enter a year: ");
    scanf("%d", &year);
    printf("You entered: %d\n", year);
    return 0;
}
```

Notice the `&` before `year`.
\index{address-of operator}
Since C is pass-by-value, `scanf` needs the *address* of the variable so it can store the result there.
Forgetting `&` is one of the most common C beginner bugs --- the program compiles but crashes or produces garbage at runtime.
In Java, you would pass a `Scanner` the value type you expect and get back a result; in C, you hand `scanf` the memory location directly.

`scanf` uses similar format specifiers to `printf`, but not identical.
Notably, `scanf` uses `%lf` for `double` while `printf` uses `%f`:

```c
char name[50];
double gpa;
scanf("%49s %lf", name, &gpa);
```

`name` does not need `&` because an array name is already the address of its first element.
`gpa` does need `&` because `scanf` needs to know where `gpa` lives in memory to fill it in.

::: {.tip}
**Trap:** `scanf("%s", ...)` reads a single word and stops at whitespace.
It also has no bounds checking --- it will happily overflow your buffer.
Always use a width specifier like `%49s` to limit input to 49 characters (plus the null terminator).
:::

`scanf` returns the number of items successfully matched.
Checking that return value tells you whether the read succeeded:

```c
int n;
if (scanf("%d", &n) != 1) {
    fprintf(stderr, "Error: expected an integer\n");
    return 1;
}
```

## `stdin`, `stdout`, and `stderr`

\index{stdin}
\index{stdout}
\index{stderr}

When your C program starts, three streams of type `FILE *` are already open:

| Stream   | Purpose                   | Java equivalent         |
|:---------|:--------------------------|:------------------------|
| `stdin`  | Standard input (keyboard) | `System.in`             |
| `stdout` | Standard output (screen)  | `System.out`            |
| `stderr` | Standard error (screen)   | `System.err`            |

`printf(...)` is shorthand for `fprintf(stdout, ...)`.
You can write error messages to `stderr` like this:

```c
fprintf(stderr, "Error: file not found\n");
```

Error messages sent to `stderr` are not affected by output redirection.
Running `./program > output.txt` only redirects `stdout`, so error messages still appear on the terminal.
Running `./program 2> err.txt` redirects `stderr` to a file while `stdout` still goes to the screen.

## `fprintf` and `fscanf`

\index{fprintf}
\index{fscanf}

```c
int fprintf(FILE *stream, const char *format, ...);
int fscanf(FILE *stream, const char *format, ...);
```

`fprintf` and `fscanf` are the file versions of `printf` and `scanf`.
They take a `FILE *` as the first argument.
In Java this is similar to wrapping a stream with a `PrintStream` or `Scanner` and calling methods on it; in C you just pass the stream as the first argument:

```c
fprintf(stdout, "Hello\n");            // same as printf("Hello\n")
fprintf(stderr, "Something went wrong\n"); // write to stderr
```

More usefully, use them with files you have opened yourself.
Here is `fscanf` reading names and scores from a file:

```c
FILE *f = fopen("scores.txt", "r");
if (f != NULL) {
    char name[50];
    int score;
    while (fscanf(f, "%49s %d", name, &score) == 2) {
        printf("%s scored %d\n", name, score);
    }
    fclose(f);
}
```

`fscanf` returns the number of items successfully read, so checking the return value tells you whether the read succeeded or the file ended.

## Opening and Closing Files

\index{fopen}
\index{fclose}

```c
FILE *fopen(const char *path, const char *mode);
int   fclose(FILE *stream);
```

To read or write a file, open it with `fopen` and close it with `fclose`.
Java programmers use `FileReader`/`BufferedReader` or `try-with-resources` to manage files; in C you call `fopen` and `fclose` manually:

```c
#include <stdio.h>

int main(void) {
    FILE *f = fopen("log.txt", "w");
    if (f == NULL) {
        fprintf(stderr, "Cannot open file\n");
        return 1;
    }

    fprintf(f, "Never gonna give you up\n");    /* Rick Astley, 1987 */
    fprintf(f, "Year: %d\n", 1987);

    fclose(f);
    return 0;
}
```

`fopen` returns `NULL` if the file cannot be opened --- always check before using the pointer.
In Java a failed open throws an exception that you are forced to handle; in C you get `NULL` back and it is up to you to check.

The second argument to `fopen` is the **mode string**:

| Mode   | Meaning                                  |
|:-------|:-----------------------------------------|
| `"r"`  | Read (file must exist)                   |
| `"w"`  | Write (creates or truncates)             |
| `"a"`  | Append (creates or appends)              |
| `"r+"` | Read and write (file must exist)         |
| `"w+"` | Read and write (creates or truncates)    |
| `"a+"` | Read and append                          |

\index{fopen!binary mode}
To open a file in **binary mode**, add `b` to the mode string: `"rb"`, `"wb"`, `"ab"`, etc.
On Unix and macOS, text and binary modes behave identically.
On Windows, text mode translates `\r\n` to `\n` on input and back on output --- binary mode does not.

## Reading Lines: `fgets`

\index{fgets}

```c
char *fgets(char *s, int size, FILE *stream);
```

`fgets` reads a line from a stream into a buffer.
It stops when it has read `size - 1` characters, encounters a newline (which it includes in the buffer), or reaches end of file.
It always null-terminates the result.
Think of it as the C equivalent of `BufferedReader.readLine()`, except it keeps the newline:

```c
char line[80];
while (fgets(line, sizeof(line), f) != NULL) {
    printf("%s", line);   /* line already includes '\n' */
}
```

`fgets` returns `NULL` at end of file or on error, making it easy to use in a loop.
It is generally safer than `scanf` for reading lines because it always respects the buffer size.

::: {.tip}
**Tip:** Prefer `fgets` over `scanf("%s", ...)` when reading text input.
`fgets` is bounded, keeps the newline so you know a full line was read, and is simpler to reason about.
:::

## `sprintf`, `sscanf`, and `snprintf`

\index{sprintf}
\index{sscanf}
\index{snprintf}

`sprintf` writes formatted output into a string buffer instead of a stream.
`sscanf` reads formatted input from a string.
These are useful for building strings programmatically or parsing structured text --- similar to Java's `String.format` and regex parsing, but lower-level:

```c
char buf[100];
sprintf(buf, "Track %02d: %s", 7, "Walking on Sunshine");
/* buf is now "Track 07: Walking on Sunshine" */

int track;
char title[50];
sscanf(buf, "Track %d: %49[^\n]", &track, title);
/* track is 7, title is "Walking on Sunshine" */
```

The `%[^\n]` in the `sscanf` call is a **scan set** --- it reads everything except a newline, which lets you capture the rest of the line as a string.

::: {.tip}
**Trap:** `sprintf` does not check the size of the destination buffer --- it will overflow if the formatted output is too long.
Use `snprintf` instead, which takes a maximum size argument:

```c
int snprintf(char *str, size_t size, const char *format, ...);
```

```c
snprintf(buf, sizeof(buf), "Track %02d: %s", 7, "Walking on Sunshine");
```

`snprintf` guarantees it will never write more than `sizeof(buf)` bytes including the null terminator.
:::

## Binary I/O: `fread` and `fwrite`

\index{fread}
\index{fwrite}

```c
size_t fread (void       *ptr, size_t size, size_t count, FILE *stream);
size_t fwrite(const void *ptr, size_t size, size_t count, FILE *stream);
```

For reading and writing raw binary data (not text), use `fread` and `fwrite`.
In Java you would use `FileInputStream`/`FileOutputStream` for byte-level I/O; in C you use `fread`/`fwrite` with a `FILE *` opened in binary mode:

```c
#include <stdio.h>

int main(void) {
    int nums[] = {1983, 1985, 1987};   /* Blue Monday, Walking on Sunshine, Never Gonna Give You Up */

    /* write binary data */
    FILE *f = fopen("years.bin", "wb");
    fwrite(nums, sizeof(int), 3, f);
    fclose(f);

    /* read it back */
    int result[3];
    f = fopen("years.bin", "rb");
    fread(result, sizeof(int), 3, f);
    fclose(f);

    for (int i = 0; i < 3; i++) {
        printf("%d ", result[i]);   /* 1983 1985 1987 */
    }
    printf("\n");
    return 0;
}
```

Both functions take four arguments: a pointer to the data, the size of each element, the number of elements, and the file stream.
`fwrite` returns the number of elements successfully written; `fread` returns the number of elements successfully read.
If either returns fewer elements than requested, check `feof` or `ferror` to find out why.

## Buffering and `fflush`

\index{buffering}
\index{fflush}

`stdio` does not write directly to the output device on every call.
Instead, it accumulates data in an internal buffer and flushes it in larger chunks for efficiency.
Java's `BufferedWriter` does something similar; in C the buffering is built into every `FILE *`.

There are three buffering modes:

- **Full buffering:** Output is written when the buffer fills up (default for files).
- **Line buffering:** Output is written when a `\n` is seen (default for `stdout` when connected to a terminal).
- **Unbuffered:** Output is written immediately (default for `stderr`).

Use `fflush` to force the buffer to write now:

```c
int fflush(FILE *stream);
```

```c
printf("Karma Chameleon loading...");   /* Culture Club, 1983 */
fflush(stdout);                          /* force output to appear now */
/* ... long computation ... */
printf(" done!\n");
```

::: {.tip}
**Trap:** When `stdout` is connected to a terminal it is **line buffered** --- a `\n` triggers a flush.
When `stdout` is redirected to a file or pipe it is **fully buffered** --- output may not appear until the buffer fills or the program exits.
If you need output to appear immediately (for example, a progress indicator without a newline), call `fflush(stdout)` after printing.
`stderr` is always unbuffered, which is why error messages appear right away.
:::

## Try It: Standard I/O Starter

```c
#include <stdio.h>
#include <string.h>

int main(void) {
    /* snprintf: safe string formatting */
    char buf[100];
    snprintf(buf, sizeof(buf), "Track %02d: %s", 1, "Blue Monday");  /* New Order, 1983 */
    printf("snprintf: %s\n", buf);

    /* sscanf: parse from a string */
    int track;
    char title[50];
    sscanf(buf, "Track %d: %49[^\n]", &track, title);
    printf("sscanf:   track=%d title='%s'\n", track, title);

    /* fprintf to stderr */
    fprintf(stderr, "This goes to stderr\n");

    /* fwrite/fread round-trip */
    int nums[] = {10, 20, 30};
    FILE *f = fopen("/tmp/tryit_data.bin", "wb");
    if (f == NULL) {
        fprintf(stderr, "Cannot open file for writing\n");
        return 1;
    }
    fwrite(nums, sizeof(int), 3, f);
    fclose(f);

    int result[3];
    f = fopen("/tmp/tryit_data.bin", "rb");
    if (f == NULL) {
        fprintf(stderr, "Cannot open file for reading\n");
        return 1;
    }
    fread(result, sizeof(int), 3, f);
    fclose(f);

    printf("fread:    %d %d %d\n", result[0], result[1], result[2]);

    /* fgets: read a line from stdin */
    printf("Enter a line: ");
    fflush(stdout);
    char line[80];
    if (fgets(line, sizeof(line), stdin) != NULL) {
        printf("You said: %s", line);
    }

    return 0;
}
```

## Key Points

- Java uses `System.out.println` and `Scanner`; C uses `printf`/`scanf` through `<stdio.h>`.
- `scanf` needs the address (`&`) of each variable --- arrays are the exception since they already decay to a pointer.
- `printf(...)` is shorthand for `fprintf(stdout, ...)`.
- `stdin`, `stdout`, and `stderr` are `FILE *` pointers corresponding to Java's `System.in`, `System.out`, and `System.err`.
- `fopen` returns `NULL` on failure --- always check before using the file pointer.
- Java's `try-with-resources` closes files automatically; in C you must call `fclose` manually.
- Add `"b"` to the mode string for binary files --- this matters on Windows.
- `fread` and `fwrite` transfer raw bytes with no format conversion.
- `snprintf` is the safe version of `sprintf` --- always prefer it.
- `stdout` is line-buffered at a terminal and fully buffered when redirected. Use `fflush` when you need output to appear immediately.
