# Strings

\index{string}

In Java, `String` is a full-featured class.
You get `.length()`, `.indexOf()`, `.substring()`, `.equals()`, `.toUpperCase()`, and dozens more methods --- all built in.
In C, none of that exists.
\index{null terminator}A "string" in C is just an array of `char` values that ends with a special null character `'\0'`.
Every string function in C depends on finding that null terminator to know where the string ends.

This chapter covers how C strings work, the standard library functions for working with them, and the traps that catch nearly every programmer at least once.

## There Is No `String` Type

In Java you might write:

```java
String song = "Come on Eileen";
int len = song.length();  // 14
```

In C, you write:

```c
char song[] = "Come on Eileen";
size_t len = strlen(song);  // 14
```

The array `song` holds 15 bytes: 14 visible characters plus the `'\0'` that the compiler appends automatically.
`strlen` counts the characters before the `'\0'` and returns the result as a `size_t` --- an unsigned integer type for sizes.
Use `%zu` to print a `size_t` value.

::: {.tip}
**Trap:** Always remember the null terminator when sizing your buffers.
The string `"Come on Eileen"` needs 15 bytes, not 14.
Off-by-one errors with null terminators are one of the most common bugs in C.
:::

## Declaring C Strings

\index{string!declaration}

There are several ways to declare a string:

```c
char greeting[] = "Hola, mundo";      // compiler sizes it: 12 bytes (11 + '\0')
char band[20]   = "The Police";       // 20-byte buffer, only 11 bytes used
char empty[10]  = "";                 // 10 bytes, first byte is '\0'
```

You can also use a pointer to a string literal:

```c
const char *lyric = "Roxanne";        // pointer to read-only memory
```

These two forms look similar but behave very differently.

## String Literals vs. Arrays

\index{string literal}

There is an important difference between these two declarations:

```c
char arr[]        = "Message in a Bottle";   /* modifiable copy on the stack */
const char *ptr   = "Message in a Bottle";   /* pointer to read-only memory */
```

With `char arr[]`, the compiler creates a local array and copies the string into it.
You can modify the characters freely.

With `const char *ptr`, the pointer points directly into a read-only section of the program.
Attempting to modify the string through a non-const pointer is undefined behavior --- typically a crash:

```c
arr[0] = 'm';   /* fine --- arr is a modifiable array */
ptr[0] = 'm';   /* COMPILE ERROR --- ptr is const char * */
```

If you forget the `const`, the compiler may not prevent the mistake:

```c
char *bad = "Message in a Bottle";   /* compiles, but dangerous */
bad[0] = 'm';                        /* UNDEFINED BEHAVIOR --- likely a crash */
```

In Java, `String` objects are immutable --- you cannot change a character in place.
C `char` arrays are mutable, but string literals are read-only.
Always declare pointers to string literals as `const char *`.

::: {.tip}
**Trap:** Assigning a string literal to a plain `char *` (without `const`) compiles but is dangerous.
The program may crash at runtime when you try to modify it, or worse, silently corrupt memory.
Always use `const char *` when pointing to a string literal.
:::

## String Functions

C provides a library of string manipulation functions in `<string.h>`.
These are the ones you will use most often.

\index{strlen}
**`strlen` --- Get the Length**

```c
size_t strlen(const char *s);
```

Returns the number of characters before the null terminator:

```c
#include <stdio.h>
#include <string.h>

int main(void) {
    char lyric[] = "Every breath you take";
    printf("'%s' has %zu characters\n", lyric, strlen(lyric));  // 21
    return 0;
}
```

In Java, `song.length()` returns the number of characters --- same as C's `strlen`.
Neither counts the null terminator (Java has no null terminator, C's `strlen` stops before it).

\index{strcpy}
\index{strncpy}
**`strcpy` / `strncpy` --- Copy a String**

```c
char *strcpy(char *dest, const char *src);
char *strncpy(char *dest, const char *src, size_t n);
```

`strcpy` copies the source string (including the null terminator) into the destination buffer.
You must make sure the destination is large enough:

```c
char dest[30];
strcpy(dest, "Every move you make");   // copies 20 bytes (19 chars + '\0')
```

`strncpy` is the safer variant --- it copies at most `n` characters:

```c
char dest[10];
strncpy(dest, "Every vow you break", 9);
dest[9] = '\0';   // strncpy does NOT guarantee null termination!
```

::: {.tip}
**Wut:** `strncpy` does not null-terminate the destination if the source is longer than `n`.
Always set the last byte yourself: `dest[sizeof(dest) - 1] = '\0';`
:::

\index{strcmp}
**`strcmp` --- Compare Strings**

```c
int strcmp(const char *s1, const char *s2);
```

In Java, comparing two `String` objects with `==` checks whether they are the same object (reference equality), not whether they contain the same text --- this is a notorious Java bug.
You use `.equals()` for content comparison.
C has the exact same problem: using `==` on two `char` arrays compares their addresses, not their contents.
Use `strcmp` instead:

```c
char a[] = "Billie Jean";
char b[] = "Billie Jean";

if (a == b) {
    // Compares ADDRESSES, not content --- almost certainly false
}

if (strcmp(a, b) == 0) {
    // Compares the actual characters --- correct!
    printf("Same title!\n");
}
```

`strcmp` returns `0` if the strings are equal, a negative value if the first is lexicographically less, and a positive value if it is greater.

::: {.tip}
**Trap:** `strcmp` returns `0` for equal strings --- not `1`.
Think of it as returning the "difference" between the two strings.
Zero difference means they are equal.
:::

\index{strncmp}
**`strncmp` --- Compare a Prefix**

```c
int strncmp(const char *s1, const char *s2, size_t n);
```

`strncmp` works like `strcmp` but compares at most `n` characters.
It is useful for checking whether a string starts with a particular prefix:

```c
char cmd[] = "beat it now";
if (strncmp(cmd, "beat", 4) == 0) {
    printf("Beat it!\n");
}
```

\index{strchr}
\index{strrchr}
**`strchr` / `strrchr` --- Find a Character**

```c
char *strchr(const char *s, int c);
char *strrchr(const char *s, int c);
```

`strchr` finds the first occurrence of a character in a string.
`strrchr` finds the last.
Both return a pointer to the found character, or `NULL` if not found.

```c
char lyric[] = "Every smile you fake";
char *first_e = strchr(lyric, 'e');    // points to 'e' in "Every"... wait
char *last_e  = strrchr(lyric, 'e');   // points to 'e' in "fake"

if (first_e != NULL) {
    printf("First 'e' at position %td\n", first_e - lyric);
}
```

\index{ptrdiff\_t}
Use `%td` to print the result of pointer subtraction (a `ptrdiff_t` value).

\index{strstr}
**`strstr` --- Find a Substring**

```c
char *strstr(const char *haystack, const char *needle);
```

Finds the first occurrence of a substring within a string.
Java's `String.indexOf(String)` does the same thing.
`strstr` returns a pointer to the start of the match, or `NULL` if not found:

```c
char title[] = "Thriller (1982)";
char *found = strstr(title, "1982");
if (found != NULL) {
    printf("Year: %s\n", found);   // "1982)"
}
```

\index{strcat}
\index{strncat}
**`strcat` / `strncat` --- Concatenate Strings**

```c
char *strcat(char *dest, const char *src);
char *strncat(char *dest, const char *src, size_t n);
```

`strcat` appends one string to the end of another.
In Java you use `+` or `StringBuilder.append()` and never worry about memory.
In C, you must ensure the destination buffer is large enough for both strings plus the null terminator:

```c
char message[50] = "I melt ";
strcat(message, "with you");
printf("%s\n", message);   // "I melt with you"
```

This works fine as long as the buffer is large enough.
But `strcat` does not check bounds --- if you run out of space, it writes past the end of the array.

::: {.tip}
\index{buffer overflow}
**Trap:** `strcat` is one of the most dangerous functions in C.
It has no way to know how large the destination buffer is, so it blindly appends bytes.
If the combined strings exceed the buffer size, you get a **buffer overflow** --- one of the most common security vulnerabilities in the history of software.
Use `strncat` instead.
:::

`strncat` takes a maximum number of characters to append.
Leave room for the null terminator:

```c
char buf[20] = "Hola";
strncat(buf, ", mundo!", sizeof(buf) - strlen(buf) - 1);
```

\index{strdup}
**`strdup` --- Duplicate a String**

```c
char *strdup(const char *s);
```

`strdup` allocates new memory on the heap, copies the string into it, and returns a pointer to the copy.
You are responsible for freeing the memory when you are done:

```c
char *copy = strdup("Total Eclipse of the Heart");
printf("%s\n", copy);
free(copy);   // you must free memory allocated by strdup
```

::: {.tip}
**Tip:** `strdup` calls `malloc` internally.
Every call to `strdup` must eventually be paired with a call to `free`.
If you forget, you have a memory leak.
Note that `strdup` is a POSIX function, not part of the C standard until C23.
It is available on virtually every system you will use, but compiling with `-std=c99 -pedantic` may produce a warning.
:::

\index{strtok}
**`strtok` --- Tokenize a String**

```c
char *strtok(char *str, const char *delim);
```

`strtok` splits a string into tokens separated by any character in a delimiter set.
In Java you might use `String.split()` --- in C, `strtok` is the standard approach:

```c
#include <stdio.h>
#include <string.h>

int main(void) {
    char lyric[] = "With or Without You";

    char *tok = strtok(lyric, " ");
    while (tok != NULL) {
        printf("'%s'\n", tok);
        tok = strtok(NULL, " ");
    }
    return 0;
}
// Output:
// 'With'
// 'or'
// 'Without'
// 'You'
```

The first call passes the string to tokenize.
Each subsequent call passes `NULL` to continue tokenizing the same string.
`strtok` returns `NULL` when there are no more tokens.

There are two important gotchas.
First, `strtok` **modifies the original string** by replacing delimiter characters with `'\0'`.
If you need the original string preserved, make a copy with `strdup` before tokenizing.
Second, `strtok` stores its state in a hidden static variable, which means it is **not thread-safe** and you cannot tokenize two strings simultaneously.

::: {.tip}
\index{strtok\_r}
**Tip:** Use `strtok_r` (POSIX) or `strtok_s` (C11 Annex K / Windows) instead of `strtok`.
These reentrant versions take an extra `char **saveptr` parameter to store the tokenizer state, making them safe to use in multi-threaded programs and allowing nested tokenization:

```c
char *strtok_r(char *str, const char *delim, char **saveptr);
```

```c
char *saveptr;
char *tok = strtok_r(lyric, " ", &saveptr);
while (tok != NULL) {
    printf("'%s'\n", tok);
    tok = strtok_r(NULL, " ", &saveptr);
}
```
:::

## The Dangers of `strcat`

Let's look at a concrete example of why `strcat` is dangerous:

```c
#include <stdio.h>
#include <string.h>

int main(void) {
    char buf[12] = "Buenas ";     // 7 chars + '\0', 4 bytes remaining

    // "noches" is 6 chars --- doesn't fit in 4 remaining bytes!
    strcat(buf, "noches");        // BUFFER OVERFLOW --- undefined behavior

    printf("%s\n", buf);          // might print garbage, might crash
    return 0;
}
```

The buffer is 12 bytes, `"Buenas "` uses 8 (including the `'\0'`), and `"noches"` needs 7 more bytes (including its own `'\0'`).
That is 14 bytes total in a 12-byte buffer.
The extra bytes overwrite whatever happens to be next to the buffer in memory, which can corrupt other variables, crash the program, or --- worst of all --- create a security exploit.

## Character Classification: `<ctype.h>`

\index{ctype.h}
\index{isalpha}
\index{isdigit}
\index{toupper}
\index{tolower}

The `<ctype.h>` header provides functions for classifying and converting individual characters.
These are useful when processing strings character by character:

| Function      | Returns non-zero if                           |
|---------------|-----------------------------------------------|
| `isalpha(c)`  | `c` is a letter (A--Z, a--z)                  |
| `isdigit(c)`  | `c` is a digit (0--9)                         |
| `isalnum(c)`  | `c` is a letter or digit                      |
| `isspace(c)`  | `c` is whitespace (space, tab, newline, etc.) |
| `isupper(c)`  | `c` is an uppercase letter                    |
| `islower(c)`  | `c` is a lowercase letter                     |

`toupper` and `tolower` convert a character's case:

```c
#include <ctype.h>
#include <stdio.h>
#include <string.h>

int main(void) {
    char title[] = "billie jean";
    for (size_t i = 0; i < strlen(title); i++) {
        title[i] = toupper((unsigned char)title[i]);
    }
    printf("%s\n", title);   /* BILLIE JEAN */
    return 0;
}
```

Here is a function that checks whether a string consists entirely of digits:

```c
int all_digits(const char *s) {
    for (; *s; s++) {
        if (!isdigit((unsigned char)*s))
            return 0;
    }
    return 1;
}
```

::: {.tip}
**Wut:** The `<ctype.h>` functions take an `int`, not a `char`.
On platforms where `char` is signed, a character with a value above 127 would be passed as a negative `int`, which is undefined behavior.
Always cast to `unsigned char` first: `toupper((unsigned char)c)`.
:::

## A Preview: `sprintf` and `sscanf`

\index{sprintf}
\index{sscanf}

```c
int sprintf(char *str, const char *format, ...);
int sscanf(const char *str, const char *format, ...);
```

Java's `String.format()` lets you build a string from a format template.
C's `sprintf` does the same thing --- it writes formatted output into a character buffer:

```c
char result[50];
int year = 1983;
sprintf(result, "Thriller came out in %d. Muy bueno!", year);
// result is now "Thriller came out in 1983. Muy bueno!"
```

\index{snprintf}
Just as `strncat` is the safer sibling of `strcat`, `snprintf` is the safer sibling of `sprintf`:

```c
char buf[20];
snprintf(buf, sizeof(buf), "The year is %d", 1983);
/* buf is "The year is 1983" --- safely truncated if it were longer */
```

`snprintf` guarantees it will not write more than the specified number of bytes, preventing buffer overflows.
We will cover `sprintf`, `snprintf`, and `sscanf` in detail in the Standard I/O chapter.

## Try It: String Starter

```c
#include <stdio.h>
#include <string.h>
#include <stdlib.h>
#include <ctype.h>

int main(void) {
    /* strlen */
    char song[] = "Come on Eileen";
    printf("Song: '%s' (%zu chars)\n", song, strlen(song));

    /* strcpy */
    char copy[30];
    strcpy(copy, song);
    printf("Copy: '%s'\n", copy);

    /* strcmp */
    printf("Compare '%s' to '%s': %d\n", song, copy, strcmp(song, copy));
    printf("Compare 'Roxanne' to 'Thriller': %d\n",
           strcmp("Roxanne", "Thriller"));

    /* strncat */
    char greeting[30] = "Buenos ";
    strncat(greeting, "dias, amigo!", sizeof(greeting) - strlen(greeting) - 1);
    printf("Greeting: '%s'\n", greeting);

    /* strchr and strstr */
    char *ch = strchr(song, 'E');
    if (ch) printf("Found 'E' at position %td\n", ch - song);

    char *sub = strstr(song, "Eileen");
    if (sub) printf("Found substring: '%s'\n", sub);

    /* toupper via ctype.h */
    char title[] = "beat it";
    for (size_t i = 0; i < strlen(title); i++) {
        title[i] = toupper((unsigned char)title[i]);
    }
    printf("Uppercased: '%s'\n", title);

    /* strdup */
    char *dup = strdup("Every breath you take");
    printf("Duplicate: '%s'\n", dup);
    free(dup);

    return 0;
}
```

## Key Points

- C strings are `char` arrays terminated by `'\0'`. There is no `String` class.
- Always account for the null terminator when sizing buffers --- `"hello"` needs 6 bytes, not 5.
- String literals like `"hello"` live in read-only memory. Use `char s[] = "..."` for a mutable copy and `const char *p = "..."` for a read-only pointer.
- In Java, `==` on strings compares references --- not content. C has the same problem with `char` arrays. Use `strcmp` (not `==`) to compare string contents. `strncmp` compares at most `n` characters.
- `strcpy` and `strcat` do not check buffer bounds. Prefer `strncpy` and `strncat`.
- `strcat` causes buffer overflows if the destination is too small --- always prefer `strncat`.
- `strdup` allocates memory with `malloc` --- you must `free` the result.
- `strtok` splits strings into tokens but modifies the original string and is not thread-safe. Use `strtok_r` or `strtok_s` instead.
- `<ctype.h>` provides character classification (`isalpha`, `isdigit`, etc.) and conversion (`toupper`, `tolower`). Always cast `char` to `unsigned char` before passing.
- `snprintf` is the safe alternative to `sprintf` --- it limits output to a specified buffer size.
- `strlen` returns the number of characters before the `'\0'`, not the total buffer size.
