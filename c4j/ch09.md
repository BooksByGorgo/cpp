
# Numbers and Casting

To the CPU, everything is just a number.
There are no characters, no strings, no pointers, no objects --- only numeric values stored in registers and memory.
The types you give to variables in C do not change the underlying bits; they tell the *compiler* how to interpret and work with those bits.

Java programmers already know most of this at an intuitive level.
When you write `int x = 5`, the JVM stores the value `5` in 32 bits.
C works the same way --- the difference is that C exposes the underlying reality more directly and gives you far fewer guardrails.

## Everything Is a Number

\index{char}

A `char` is just a small integer, typically 8 bits.
Assigning `'A'` is exactly the same as assigning the number `65` --- the ASCII code for `A`.
You can do arithmetic on characters just as you would on any integer:

```c
#include <stdio.h>

int main(void) {
    char grade = 'A';
    int  code  = 65;

    /* Both hold the same numeric value */
    printf("grade: %c = %d\n", grade, grade);   // grade: A = 65
    printf("code:  %c = %d\n", code,  code);    // code:  A = 65

    char next = grade + 1;                       // 65 + 1 = 66 = 'B'
    printf("Next grade: %c\n", next);            // Next grade: B

    return 0;
}
```

\index{pointer!as a number}

A pointer is also just a number --- an integer that represents a memory address.
The pointer type (`int *`, `char *`, etc.) tells the compiler what operations to perform when you dereference it and how many bytes to step over during pointer arithmetic.
You can print the raw address using `%p`:

```c
int val = 1983;         /* "Maniac" by Michael Sembello */
int *p  = &val;

printf("Address: %p\n", (void *)p);   // e.g., 0x7ffcb3a2
printf("Value:   %d\n", *p);          // 1983
```

## Strings Are Not Special

Because everything is just a number, C has no native concept of "strings."
A string in C is simply an array of characters (small integers) that ends with a special `0` byte --- the null terminator `'\0'`.

When you write a string literal like `"Hola"`, the compiler lays out four bytes (`72 111 108 97`) followed by a zero byte, and gives you a `char *` pointer to the first byte.
The standard library functions in `<string.h>` give strings their meaning by processing these arrays until they hit that `0`.

```c
#include <stdio.h>

int main(void) {
    char word[] = "Rio";   /* "Rio" — Duran Duran (1982) */

    printf("String: %s\n", word);
    printf("Bytes:  ");
    for (int i = 0; i < (int)sizeof(word); i++)
        printf("%d ", word[i]);
    printf("\n");

    return 0;
}
// Output:
// String: Rio
// Bytes:  82 105 111 0
```

The four bytes are the ASCII values for `R`, `i`, `o`, and the null terminator.

## Integer Types

\index{integer types}
\index{sizeof}

In Java, `int` is always 32 bits and `long` is always 64 bits, regardless of platform.
C is more flexible --- and more treacherous.
The C standard specifies only minimum sizes, so the exact sizes depend on the compiler and platform.
Here are the typical sizes on a 64-bit Linux or macOS system:

| Type | Bytes | Range |
|:---|:---:|:---|
| `signed char` | 1 | $-128$ to $127$ |
| `unsigned char` | 1 | $0$ to $255$ |
| `short` | 2 | $-32{,}768$ to $32{,}767$ |
| `unsigned short` | 2 | $0$ to $65{,}535$ |
| `int` | 4 | $-2^{31}$ to $2^{31}-1$ |
| `unsigned int` | 4 | $0$ to $2^{32}-1$ |
| `long` | 8 | $-2^{63}$ to $2^{63}-1$ |
| `unsigned long` | 8 | $0$ to $2^{64}-1$ |
| `long long` | 8 | $-2^{63}$ to $2^{63}-1$ |
| `unsigned long long` | 8 | $0$ to $2^{64}-1$ |

\index{limits.h}
Use `<limits.h>` and `sizeof` to inspect the actual sizes and limits on your machine:

```c
#include <stdio.h>
#include <limits.h>

int main(void) {
    printf("char:  %zu byte,  range %d to %d\n",
           sizeof(char), CHAR_MIN, CHAR_MAX);
    printf("int:   %zu bytes, range %d to %d\n",
           sizeof(int), INT_MIN, INT_MAX);
    printf("long:  %zu bytes, range %ld to %ld\n",
           sizeof(long), LONG_MIN, LONG_MAX);
    return 0;
}
```

::: {.tip}
**Wut:** Most integer types are signed by default, but `char` is special --- its signedness is implementation-defined.
On x86_64, `char` is signed; on many ARM systems, `char` is unsigned.
If you care about signedness, write `signed char` or `unsigned char` explicitly.
:::

\index{two's complement}
Signed integers use **two's complement** representation on virtually all modern hardware.
The top bit is the sign bit: if it is set, the number is negative.
Two's complement has one more negative value than positive values --- `INT_MIN` is `-2147483648` but `INT_MAX` is only `2147483647`.

### Signed vs. Unsigned Issues

\index{signed vs. unsigned}

Mixing signed and unsigned types in comparisons and arithmetic is a common source of bugs.
When a signed and an unsigned value appear in the same expression, the signed value is converted to unsigned, which can produce surprising results:

```c
#include <stdio.h>

int main(void) {
    int           a = -1;
    unsigned int  b = 1;

    if (a < b)
        printf("a is less than b\n");
    else
        printf("a is NOT less than b\n");   // prints this!

    return 0;
}
```

When `a` (which is `-1`) is converted to `unsigned int`, it becomes `4294967295` --- much larger than `1`.
Compile with `-Wall` and C will warn you about signed/unsigned comparisons.

### Integer Promotion

\index{integer promotion}

When integer types smaller than `int` appear in an expression, they are automatically promoted to `int` (or to `unsigned int` if `int` cannot hold all the values of the type).
This is called **integer promotion**.

::: {.tip}
\index{size\_t}
**Trap:** One place where promotion causes surprising results is with `size_t`, which is the unsigned type returned by `sizeof` and `strlen`.
Subtracting two `size_t` values when the first is smaller than the second wraps around to a huge positive number:

```c
#include <stdio.h>
#include <string.h>

int main(void) {
    char *a = "Hola";          // strlen = 4
    char *b = "Panama";        /* "Panama" — Van Halen (1984), strlen = 6 */

    size_t diff = strlen(a) - strlen(b);   // 4 - 6 wraps around!
    printf("size_t diff:  %zu\n", diff);   // large positive number

    long sdiff = (long)strlen(a) - (long)strlen(b);
    printf("signed diff:  %ld\n", sdiff);  // -2
    return 0;
}
```
:::

## Floating-Point Types

\index{float}
\index{double}

Floating-point numbers represent values with fractional components.
Like Java, C has `float` (32-bit) and `double` (64-bit).
Java also has `float` and `double` with the same sizes and IEEE 754 semantics.

| Type | Size | Range |
|:---|:---:|:---|
| `float` | 4 bytes | ~$\pm 3.4 \times 10^{38}$ |
| `double` | 8 bytes | ~$\pm 1.7 \times 10^{308}$ |
| `long double` | 16 bytes | ~$\pm 1.2 \times 10^{4932}$ |

\index{long double}
Floating-point numbers cannot always represent a value exactly.
The classic example: `0.1 + 0.2` is not exactly `0.3` in IEEE 754 arithmetic.
Never use `==` to compare floating-point values; compare the absolute difference against a small tolerance (epsilon) instead.

::: {.tip}
**Wut:** Floating-point literals without a suffix are `double` by default, not `float`.
Adding the suffix `f` makes a `float` literal: `1.5` is a `double`, `1.5f` is a `float`.
Assigning `1.5` to a `float` causes a silent precision loss; comparing the result back to `1.5` (a `double`) may fail because the lost precision is not recovered.
:::

## Converting Strings to Numbers

\index{strtol}
\index{stdlib.h}

Because strings are arrays of characters (numbers), the text `"1984"` is completely different from the integer `1984`.
Converting between the two is a common task.

To parse a string into an integer, use `strtol` (string to long) from `<stdlib.h>`:

```c
long strtol(const char *str, char **endptr, int base);
```

The first argument is the string to parse.
The second, `endptr`, is set to point to the first character after the parsed number; pass `NULL` if you do not need it.
The third argument is the numeric base (`10` for decimal, `16` for hex, `0` to auto-detect from the prefix):

```c
#include <stdio.h>
#include <stdlib.h>

int main(void) {
    char *year_str = "1984";    /* "Hello" — Lionel Richie (1984) */

    long year = strtol(year_str, NULL, 10);
    printf("Year: %ld\n", year);   // 1984

    long hex_val = strtol("7C0", NULL, 16);
    printf("0x7C0 = %ld\n", hex_val);   // 1984

    return 0;
}
```

\index{strtod}
For floating-point conversions, use `strtod` (string to double) --- same idea, no base argument.

\index{atoi}
\index{atof}
You may also see the older `atoi` and `atof` in existing code:

```c
int    atoi(const char *str);   // string to int
double atof(const char *str);   // string to double
```

They are simpler to call but return `0` for invalid input with no way to distinguish it from a legitimate zero, and they provide no overflow detection.

::: {.tip}
**Tip:** Prefer `strtol` and `strtod` over `atoi` and `atof`.
`strtol` gives you an `endptr` showing exactly what was parsed and reports overflow through `errno`.
Think of `atoi` as something you will read, not something you will write.
:::

Later chapters on Standard I/O will cover `sprintf`/`sscanf` for converting numbers to formatted strings and back again.

## Casting

\index{cast}

A **cast** forces the compiler to treat a value of one type as a different type.
The syntax is `(type) value` --- the same syntax Java uses.

```c
double pi   = 3.14159;
int roughly = (int)pi;   // truncates to 3 (does not round)
```

In Java, casting an `int` to a `double` is a widening conversion guaranteed to be safe.
Casting a `double` to an `int` is a narrowing conversion that discards the fractional part, and Java throws an exception if an object cast is invalid.

In C, casts are much simpler --- and much less safe.
There is one universal cast syntax, it works on integers, floating-point values, and pointers, and the compiler trusts you implicitly.
No exception is thrown.
No magic conversion happens.
You are telling the compiler: "I know what I am doing, suppress any warnings, and treat this value as the type I specified."

```c
#include <stdio.h>

int main(void) {
    int   a = 7, b = 2;
    double result;

    result = a / b;                       // integer division: 3
    printf("int / int:    %f\n", result); // 3.000000

    result = (double)a / b;               // cast a to double first: 3.5
    printf("double / int: %f\n", result); // 3.500000

    return 0;
}
```

The following table summarizes allowed C casts:

| From / To | Integer | Floating-Point | Pointer |
|:---|:---:|:---:|:---:|
| **Integer** | Yes | Yes | Yes |
| **Floating-Point** | Yes | Yes | No |
| **Pointer** | Yes | No | Yes |

::: {.tip}
**Trap:** A classic beginner mistake is trying to convert a string to an integer by casting the pointer:

```c
char *year_str  = "1982";           /* "Rio" — Duran Duran (1982) */
int   bad_year  = (int)year_str;    /* BUG: not 1982! */
long  good_year = strtol(year_str, NULL, 10);   /* correct: 1982 */
```

Casting a `char *` to `int` takes the *memory address* of the string and truncates it to fit in an `int`.
On a 64-bit system, a pointer is 8 bytes and an `int` is 4 bytes, so the compiler will actually warn you that you are casting a pointer to an integer of a different size.
Always use `strtol` (or `atoi`) to parse strings into numbers.
:::

### Casting Pointers

\index{void pointer}

`void *` is a generic pointer that can point to anything.
Any other pointer type converts to and from `void *` without a cast in C.
This is why `malloc` returns `void *` --- you can assign it directly to any pointer variable.

Casting between other pointer types requires explicit casts and demands that you understand the memory layout:

```c
#include <stdio.h>

int main(void) {
    int nums[] = {1983, 1984, 1985};

    void *vp = nums;            // any pointer converts to void * freely
    int  *ip = (int *)vp;       // cast back to use it
    printf("First: %d\n", ip[0]);   // 1983

    /* Byte-level access */
    unsigned char *bp = (unsigned char *)nums;
    printf("First byte of nums[0]: 0x%02x\n", bp[0]);

    return 0;
}
```

## Try It: Numbers and Casting

```c
#include <stdio.h>
#include <stdlib.h>
#include <limits.h>
#include <string.h>

int main(void) {
    /* Characters are just numbers */
    char ch = 'D';
    printf("'%c' is %d\n", ch, ch);
    printf("'%c' + 3 = '%c' (%d)\n", ch, ch + 3, ch + 3);

    /* Strings are arrays of numbers */
    char title[] = "Drive";    /* "Drive" — The Cars (1984) */
    printf("\"%s\" bytes: ", title);
    for (int i = 0; i < (int)sizeof(title); i++)
        printf("%d ", title[i]);
    printf("\n");

    /* String to number conversion */
    char *bpm_str = "115";
    long  bpm     = strtol(bpm_str, NULL, 10);
    printf("\"%s\" as a number: %ld\n", bpm_str, bpm);

    /* Hex string to number */
    long color = strtol("FF4500", NULL, 16);
    printf("0x%lX = %ld\n", color, color);

    /* Integer sizes on this machine */
    printf("\nsizeof(char)  = %zu\n", sizeof(char));
    printf("sizeof(short) = %zu\n",  sizeof(short));
    printf("sizeof(int)   = %zu\n",  sizeof(int));
    printf("sizeof(long)  = %zu\n",  sizeof(long));
    printf("INT_MAX       = %d\n",   INT_MAX);

    /* Casting: float to int truncates */
    double tempo = 115.9;
    int    whole = (int)tempo;
    printf("\n(int)%.1f = %d\n", tempo, whole);   // 115, not 116

    /* The classic trap: casting a pointer */
    char *song_year  = "1984";
    long  bad_year   = (long)song_year;            // address, not 1984!
    long  good_year  = strtol(song_year, NULL, 10);
    printf("(long)\"1984\"        = %ld (an address!)\n", bad_year);
    printf("strtol(\"1984\", ...) = %ld\n", good_year);

    /* size_t subtraction trap */
    char *a = "Hola";
    char *b = "Danger Zone";   /* "Danger Zone" — Kenny Loggins (1986) */
    long sdiff = (long)strlen(a) - (long)strlen(b);
    printf("\nlen(\"%s\") - len(\"%s\") = %ld\n", a, b, sdiff);

    return 0;
}
```

## Key Points

- To the CPU, everything is a number; types tell the compiler how to interpret the bits.
- A `char` is just a small integer; `'A'` and `65` are the same value.
- A pointer is just a number representing a memory address; the type says how to use it.
- C has no native strings --- only arrays of `char` ending in `'\0'`.
- Java has fixed-size `int` (32 bits) and `long` (64 bits); C integer sizes are platform-dependent.
- C integer sizes can vary by platform; use `<limits.h>` and `sizeof` to inspect them.
- Signed/unsigned mixing in expressions silently converts the signed value to unsigned.
- Use `strtol`/`strtod` to parse strings into numbers; `atoi`/`atof` exist but lack error reporting.
- C casts `(type)value` tell the compiler to treat a value as the given type --- no magic happens.
- Casting a `char *` to an integer gives you the raw address, not the parsed number.
