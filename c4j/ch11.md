# Low-Level I/O

\index{file descriptor}

The `<stdio.h>` functions you used in the previous chapter are built on top of a lower-level I/O interface provided by the operating system.
These system calls --- `read`, `write`, `open`, and `close` --- work directly with **file descriptors** rather than `FILE *` pointers.
In Java, `java.io.FileDescriptor` wraps the same concept, and `FileInputStream`/`FileOutputStream` sit above it.
In C, file descriptors are just plain integers, and you can use them directly.
Understanding them helps you see what `stdio` is actually doing under the hood.

## File Descriptors

\index{file descriptor}

A file descriptor is a small non-negative integer that the operating system uses to identify an open file (or pipe, socket, device, etc.).
When your program starts, three file descriptors are already open:

| File Descriptor | POSIX Name       | Purpose         | Java equivalent          |
|:----------------|:-----------------|:----------------|:-------------------------|
| 0               | `STDIN_FILENO`   | Standard input  | `System.in` (fd 0)       |
| 1               | `STDOUT_FILENO`  | Standard output | `System.out` (fd 1)      |
| 2               | `STDERR_FILENO`  | Standard error  | `System.err` (fd 2)      |

\index{STDIN\_FILENO}
\index{STDOUT\_FILENO}
\index{STDERR\_FILENO}
\index{unistd.h}
These constants are defined in `<unistd.h>`.
They correspond to `stdin`, `stdout`, and `stderr` from `<stdio.h>`, but at the raw operating-system level.
In Java, `FileDescriptor.in`, `FileDescriptor.out`, and `FileDescriptor.err` wrap the exact same underlying file descriptors.

## `read` and `write`

\index{read}
\index{write}
\index{ssize\_t}

```c
ssize_t read (int fd, void       *buf, size_t count);
ssize_t write(int fd, const void *buf, size_t count);
```

The `read` and `write` system calls transfer raw bytes between a file descriptor and a buffer.
There is no formatting, no newline handling, and no buffering --- just bytes in and out.
In Java, `InputStream.read()` and `OutputStream.write()` are the closest equivalents:

```c
#include <unistd.h>

/* write to stdout: "Come As You Are\n" (Nirvana, 1991) */
write(1, "Come As You Are\n", 16);

/* read from stdin and echo it back */
char buf[100];
ssize_t n = read(0, buf, sizeof(buf));   /* read from stdin  */
write(1, buf, n);                        /* echo it to stdout */
```

`read` returns the number of bytes actually read, which may be less than `count`.
It returns 0 at end of file and -1 on error.
`write` returns the number of bytes written, or -1 on error.

::: {.tip}
**Wut:** A return value less than `count` from `read` is not an error.
It is perfectly normal --- for example, when reading from a terminal, `read` returns as soon as the user presses Enter, even if the buffer could hold more.
If you need to read exactly N bytes, you must loop until you have them all.
:::

## `open` and `close`

\index{open}
\index{close}
\index{fcntl.h}

```c
int open (const char *path, int flags, ... /* mode_t mode */);
int close(int fd);
```

To open a file at the system call level, use `open` from `<fcntl.h>`.
`open` returns a file descriptor (a non-negative integer) on success, or -1 on failure.
In Java, `new FileInputStream("data.txt")` handles this for you; in C, you do it directly:

```c
#include <fcntl.h>
#include <unistd.h>

int fd = open("lyrics.txt", O_RDONLY);
if (fd == -1) {
    write(2, "Cannot open file\n", 17);
    return 1;
}

char buf[256];
ssize_t n = read(fd, buf, sizeof(buf));
write(1, buf, n);

close(fd);
```

\index{open!flags}
The second argument is a set of flags combined with bitwise OR:

| Flag       | Purpose                                    |
|:-----------|:-------------------------------------------|
| `O_RDONLY` | Open for reading only                      |
| `O_WRONLY` | Open for writing only                      |
| `O_RDWR`   | Open for reading and writing               |
| `O_CREAT`  | Create the file if it does not exist       |
| `O_TRUNC`  | Truncate the file to zero length           |
| `O_APPEND` | Append writes to the end of the file       |

To create a new file (or overwrite an existing one), combine flags:

```c
int fd = open("output.txt", O_WRONLY | O_CREAT | O_TRUNC, 0644);
```

\index{file permissions}
The third argument (`0644`) is the **file permissions** and is only used when `O_CREAT` is set.
`0644` means the owner can read and write; everyone else can only read.

::: {.tip}
**Trap:** If you use `O_CREAT` without supplying the permissions argument, you will get whatever random value happens to be on the stack as the permissions.
Always provide the permissions when using `O_CREAT`.
:::

\index{creat}
There is also a `creat` function, which is equivalent to `open` with `O_WRONLY | O_CREAT | O_TRUNC`:

```c
int creat(const char *path, mode_t mode);
```

```c
int fd = creat("output.txt", 0644);
/* same as: open("output.txt", O_WRONLY | O_CREAT | O_TRUNC, 0644) */
```

::: {.tip}
**Wut:** Yes, it is `creat` with no `e`.
Ken Thompson was once asked what he would do differently if he were redesigning Unix.
His answer: "I'd spell creat with an e."
:::

## Seeking: `lseek`

\index{lseek}

```c
off_t lseek(int fd, off_t offset, int whence);
```

`lseek` repositions the read/write offset for an open file descriptor.
In Java, `RandomAccessFile.seek()` is the equivalent:

```c
#include <unistd.h>

lseek(fd, 0, SEEK_SET);   /* go to the beginning           */
lseek(fd, 0, SEEK_END);   /* go to the end                 */
lseek(fd, 100, SEEK_SET); /* go to byte 100                */

off_t pos = lseek(fd, 0, SEEK_CUR);  /* get current position (no move) */

lseek(fd, -3, SEEK_END);  /* go to 3 bytes before the end */
```

\index{SEEK\_SET}
\index{SEEK\_CUR}
\index{SEEK\_END}
The three `SEEK_` constants control what the offset is relative to:

| Constant   | Meaning                                |
|:-----------|:---------------------------------------|
| `SEEK_SET` | Relative to the beginning of the file  |
| `SEEK_CUR` | Relative to the current position       |
| `SEEK_END` | Relative to the end of the file        |

`lseek` returns the new offset from the beginning of the file, or -1 on error.

::: {.tip}
\index{fseek}
\index{ftell}
**Tip:** In `<stdio.h>`, the equivalent functions are `fseek` and `ftell`.
The low-level `lseek` combines both: calling `lseek(fd, 0, SEEK_CUR)` returns the current position without moving, just like `ftell`.
:::

## `pread` and `pwrite`

\index{pread}
\index{pwrite}

```c
ssize_t pread (int fd, void       *buf, size_t count, off_t offset);
ssize_t pwrite(int fd, const void *buf, size_t count, off_t offset);
```

`pread` and `pwrite` are like `read` and `write` but take an explicit offset instead of using or modifying the file's current position.
In Java, `FileChannel.read(ByteBuffer, position)` from NIO is the equivalent:

```c
/* read 100 bytes starting at offset 200, without changing the file position */
ssize_t n = pread(fd, buf, 100, 200);

/* write 50 bytes at offset 0, without changing the file position */
pwrite(fd, data, 50, 0);
```

These are especially useful when multiple threads share a file descriptor.
Since `pread`/`pwrite` do not touch the current file position, there is no race condition between a `lseek` and a `read` in another thread.

## Try It: Low-Level I/O Starter

```c
#include <fcntl.h>
#include <unistd.h>
#include <string.h>
#include <stdio.h>

int main(void) {
    /* write to stdout using file descriptor 1 */
    const char *msg = "Low-level I/O starter\n";
    write(STDOUT_FILENO, msg, strlen(msg));

    /* open, write, close */
    int fd = open("/tmp/tryit_lowio.txt",
                  O_WRONLY | O_CREAT | O_TRUNC, 0644);
    if (fd == -1) {
        write(STDERR_FILENO, "open failed\n", 12);
        return 1;
    }

    /* "Come As You Are" by Nirvana (1991) --- allowed in ch11 */
    const char *lines[] = {
        "Come As You Are\n",
        "Year: 1991\n"
    };
    for (int i = 0; i < 2; i++) {
        write(fd, lines[i], strlen(lines[i]));
    }
    close(fd);

    /* open, read, print */
    fd = open("/tmp/tryit_lowio.txt", O_RDONLY);
    if (fd == -1) {
        write(STDERR_FILENO, "reopen failed\n", 14);
        return 1;
    }

    char buf[256];
    ssize_t n = read(fd, buf, sizeof(buf) - 1);
    write(STDOUT_FILENO, buf, n);

    /* lseek: go back to start and read again */
    lseek(fd, 0, SEEK_SET);
    n = read(fd, buf, sizeof(buf) - 1);
    printf("Read %zd bytes on second pass\n", n);

    close(fd);
    return 0;
}
```

## Key Points

- File descriptors are small integers: 0 is stdin, 1 is stdout, 2 is stderr.
- These correspond to Java's `System.in`, `System.out`, and `System.err`.
- `read` and `write` transfer raw bytes --- no formatting, no buffering.
- `open` returns a file descriptor; `fopen` returns a `FILE *`. They are different levels of abstraction.
- Use `O_CREAT` with `open` to create files. Always provide a permissions argument when using `O_CREAT`.
- `lseek` repositions the read/write offset. Use `SEEK_SET`, `SEEK_CUR`, or `SEEK_END`.
- `pread` and `pwrite` read/write at a specific offset without changing the file position --- useful in multi-threaded programs.
- A short read (fewer bytes than requested) from `read` is not an error.
