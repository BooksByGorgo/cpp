
# Pointers

If you are a Java programmer, pointers may sound like something alien --- a low-level C detail that has nothing to do with you.
Here is the twist: you have been using pointers all along.
What happens in Java when you try to call a method on an object that was never initialized?
You get a `NullPointerException`.
The word *pointer* is right there in the name.
Every object reference in Java is a pointer.
`SomeClass obj = someObject;` --- `obj` holds the *address* of the object in memory, not the object itself.
Java just hides the details and manages everything for you.

In C, the details are yours to manage, and pointers are front and center.
Once you see how they work, a lot of Java behavior that seemed like magic will make complete sense.

\index{pointer}

## What Is a Pointer?

A pointer is a variable that holds a memory address.
Instead of holding a value like `42`, a pointer holds the *location* where `42` is stored.
On a 64-bit system, every pointer is an 8-byte integer --- the address of some byte in memory.
The type before the `*` tells the compiler what kind of data lives at that address.

## Declaring Pointers

\index{pointer!declaration}

A pointer type is declared by placing a `*` after the base type:

```c
int *p;         // p is a pointer to an int
char *s;        // s is a pointer to a char
double *d;      // d is a pointer to a double
```

::: {.tip}
**Trap:** The `*` belongs to the variable, not to the type.
This declaration creates one pointer and one regular `int`:

```c
int *p, q;    // p is a pointer to int; q is just an int
```

To declare two pointers, write two stars: `int *p, *q;`
:::

## The Address-Of Operator: `&`

\index{address-of operator}

The `&` operator returns the address of a variable.
In C, `&` is strictly the address-of operator:

```c
int score = 100;
int *p = &score;   // p now holds the address of score

printf("score = %d\n", score);            // 100
printf("address of score = %p\n", (void *)p);  // something like 0x7ffd5e8a3b2c
```

The `%p` format specifier is for printing pointer values.
The cast to `(void *)` is required by the C standard when printing a pointer.

## Dereferencing: `*`

\index{dereference operator}

The `*` operator on a pointer gives you the value at the address the pointer holds.
This is called **dereferencing**:

```c
int score = 100;
int *p = &score;

printf("Value at p: %d\n", *p);    // 100

*p = 200;                               // modify score through the pointer
printf("score is now: %d\n", score);    // 200
```

Notice the dual use of `*`: in a declaration it means "this is a pointer."
In an expression it means "follow the pointer to the value."

## Pointers to Pointers

\index{pointer!to pointer}

Since a pointer is just a variable, it has an address too.
You can create a pointer to a pointer:

```c
int val = 42;
int *p  = &val;     // p points to val
int **pp = &p;      // pp points to p

printf("val  = %d\n", val);    // 42
printf("*p   = %d\n", *p);     // 42
printf("**pp = %d\n", **pp);   // 42
```

You dereference `pp` twice: once to get `p`, and again to get `val`.
\index{argc}
\index{argv}
Pointers to pointers appear throughout C --- for example, `main` can be declared as `int main(int argc, char **argv)`, where `argv` is a pointer to an array of string pointers (one per command-line argument).

## Visualizing Pointers in Memory

Here is a concrete example using the year 1985 and the famous phone number 867:

```c
int x  = 1985;
int y  = 867;
int *p  = &x;
int **pp = &p;
```

Every variable lives at some address in memory.
Here is what the layout looks like (using made-up but realistic addresses):

```
  Variable    Address      Value
  --------    ----------   ----------
  x           0x1000       1985
  y           0x1004       867
  p           0x1008       0x1000  -------> x
  pp          0x1010       0x1008  -------> p -------> x
```

The variable `x` lives at address `0x1000` and holds `1985`.
The pointer `p` lives at `0x1008` and holds `0x1000` --- the address of `x`.
The pointer-to-pointer `pp` lives at `0x1010` and holds `0x1008` --- the address of `p`.
Following the chain: `*pp` gives you `p` (which is `0x1000`), and `**pp` gives you `x` (which is `1985`).

A pointer is just a variable whose value happens to be an address.
There is nothing magical about it.

## NULL Pointers

\index{NULL pointer}

In Java, `null` means an object reference that points to nothing.
In C, the equivalent is `NULL`.
A pointer that does not point to anything should be set to `NULL`:

```c
int *p = NULL;   // p points to nothing

if (p != NULL) {
    printf("Value: %d\n", *p);
} else {
    printf("Pointer is NULL\n");
}
```

\index{segmentation fault}
Dereferencing a `NULL` pointer is undefined behavior.
In Java, you get a `NullPointerException` --- a polite runtime error that tells you exactly what happened.
In C, you get a **segmentation fault** --- a crash with no helpful message, and you get to figure out where things went wrong.

::: {.tip}
**Tip:** In C, `NULL` is typically defined as `((void *)0)`.
You may also see `0` used directly as a null pointer.
C does not have Java's `null` keyword, so use `NULL`.
:::

::: {.tip}
**Tip:** Always check a pointer before dereferencing it if there is any chance it could be `NULL`.
Out-of-bounds array access is just as dangerous --- Java throws `ArrayIndexOutOfBoundsException`, but C silently reads or writes garbage memory.
You are responsible for staying in bounds.
:::

## Pointers and Arrays

\index{pointer!and arrays}

A pointer might point to a single value, or it might point to the first element of an array of values.
The type system does not tell you which --- an `int *` looks the same either way:

```c
int score = 100;
int *p = &score;              // points to one int

int nums[] = {867, 5309, 1984, 1985};
int *q = nums;                // points to the first of four ints
```

As you saw in the Variables chapter, an array name decays to a pointer to its first element.

\index{pointer!arithmetic}
**Pointer arithmetic** works in units of the pointed-to type.
If `p` is an `int *` and `int` is 4 bytes, then `p + 1` advances the address by 4 bytes to reach the next `int`.
You never need to think about byte sizes --- the compiler handles the scaling:

```c
int nums[] = {867, 5309, 1984, 1985, 42};
int *p = nums;

printf("%d\n", *p);       // 867  (same as nums[0])
printf("%d\n", *(p + 1)); // 5309 (same as nums[1])
printf("%d\n", p[2]);     // 1984 -- yes, [] works on pointers!
```

::: {.tip}
**Wut:** Array indexing `nums[i]` is syntactic sugar for `*(nums + i)`.
That is why you can also write `i[nums]` --- it is `*(i + nums)`, which is the same thing.
Do not write code like that, but knowing this shows exactly how arrays and pointers relate.
:::

::: {.tip}
**Tip:** You can subtract two pointers that point into the same array to find the distance between them.
The result is of type `ptrdiff_t`; use `%td` to print it.

```c
int nums[] = {10, 20, 30, 40};
int *first = &nums[0];
int *last  = &nums[3];
printf("distance: %td\n", last - first);   // 3
```
:::

## Pointers and Structures: The `->` Operator

\index{arrow operator}
\index{struct!pointer to}

You already know how to declare structs and access members with `.` from the Variables chapter.
Pointers to structures are extremely common in C --- almost every non-trivial program passes struct pointers rather than copying entire structs.

```c
struct song {
    char title[40];
    int  year;
};

struct song track = {"Tainted Love", 1981};
struct song *p = &track;
```

To access a field through a pointer, you must dereference the pointer first.
But the `.` operator has higher precedence than `*`, so parentheses are required:

```c
printf("Title: %s\n", (*p).title);   // parentheses required
printf("Year:  %d\n", (*p).year);
```

Writing `(*p).field` everywhere is tedious.
C provides the `->` operator as a shorthand:

```c
printf("Title: %s\n", p->title);    // same as (*p).title
printf("Year:  %d\n", p->year);     // same as (*p).year
```

::: {.tip}
**Tip:** The `->` operator is simply `(*p).field` written more clearly.
You will see `->` far more often than `(*p).` in real C code.
If you have a pointer to a struct, reach for `->`.
:::

::: {.tip}
**Wut:** In Java, every time you write `obj.method()` or `obj.field`, you are actually doing the equivalent of `obj->method()` --- Java is dereferencing a pointer on your behalf.
The `.` operator in Java is secretly `->`.
When Java throws a `NullPointerException`, it is because you tried to dereference a null pointer the same way C crashes on `p->field` when `p` is `NULL`.
:::

## Pass by Value (and Pointers as a Workaround)

\index{pass by value}

In C, **all function parameters are pass by value** --- the function receives a copy of the argument.
If you want a function to modify a variable in the caller, you pass a *pointer* to it.

```c
void increment(int *x) {
    (*x)++;   // dereference the pointer, then increment
}

int main(void) {
    int score = 99;
    increment(&score);      // pass the ADDRESS of score
    printf("%d\n", score);  // 100
    return 0;
}
```

The function `increment` receives a copy of the address, but both the original and the copy point to the same memory, so dereferencing either one reaches the same variable.

### Java's "Pass by Reference" Explained

This is where Java's behavior finally makes perfect sense.
Java is also pass by value --- always.
But object variables in Java hold *references* (pointers) to objects.
When you pass an object to a method, Java passes a copy of the pointer.
The copy points to the same object, so the method can modify the object's contents through that pointer.
But if the method reassigns the local copy of the pointer, the caller's pointer is unaffected.

Consider this Java example:

```java
void addTo(StringBuffer sb, int i) {
    sb.append("!!!");
    i += 3;
}

StringBuffer sb = new StringBuffer();
int i = 0;
addTo(sb, i);
```

After the call, `sb.toString()` is `"!!!"` and `i` is still `0`.
Why?
Because `sb` was passed as a copy of the pointer --- the method used that pointer to reach the same `StringBuffer` object and call `append` on it.
But `i` was passed as the integer value `0` --- the method got a copy of `0`, incremented its local copy to `3`, and the caller's `i` was never touched.

Here is the equivalent pattern in C, using a pointer to simulate what Java does automatically for objects:

```c
#include <stdio.h>
#include <string.h>

typedef struct {
    char buf[64];
} StringBuffer;

void add_to(StringBuffer *sb, int i) {
    strcat(sb->buf, "!!!");   // modifies through the pointer
    i += 3;                   // only modifies the local copy
}

int main(void) {
    StringBuffer sb;
    sb.buf[0] = '\0';
    int i = 0;
    add_to(&sb, i);
    printf("sb = \"%s\"\n", sb.buf);   // sb = "!!!"
    printf("i  = %d\n", i);            // i  = 0
    return 0;
}
```

::: {.tip}
**Tip:** Every time you see a `*` on a parameter in C, ask yourself: "Is this here so the function can modify the caller's variable, or because the function needs to work with an array?"
Often it is one or the other, and understanding which one is key to reading C code.
:::

## Try It

This program demonstrates the core pointer operations in one place.
Type it in, compile it, and try modifying the values to see what changes:

```c
#include <stdio.h>

void swap(int *a, int *b) {
    int temp = *a;
    *a = *b;
    *b = temp;
}

int main(void) {
    // Basic pointer usage
    int val = 1985;
    int *p  = &val;
    printf("val = %d, *p = %d\n", val, *p);
    printf("Address of val: %p\n", (void *)&val);

    // Modify through pointer
    *p = 1984;
    printf("After *p = 1984: val = %d\n", val);

    // Pointer to pointer
    int **pp = &p;
    printf("**pp = %d\n", **pp);

    // Pass by value with pointers
    int x = 867, y = 5309;
    printf("Before swap: x=%d, y=%d\n", x, y);
    swap(&x, &y);
    printf("After swap:  x=%d, y=%d\n", x, y);

    // Arrays and pointers
    int nums[] = {10, 20, 30, 40, 50};
    int *q = nums;
    for (int i = 0; i < 5; i++) {
        printf("nums[%d] = %d  (address: %p)\n", i, q[i], (void *)(q + i));
    }

    return 0;
}
```

## Key Points

- A pointer holds a memory address.
  Use `&` to get an address and `*` to dereference it.
- All pointers are the same size on a given system, regardless of what they point to (8 bytes on 64-bit systems).
- In Java, every object variable is a pointer.
  `NullPointerException` is what happens when you dereference a `NULL` pointer.
- Arrays decay to pointers in most expressions. `a[i]` is equivalent to `*(a + i)`.
- Pointer arithmetic moves in units of the pointed-to type, not bytes.
- Use `->` to access struct fields through a pointer.
  It is shorthand for `(*p).field`.
- All function parameters in C are pass by value.
  Pass a pointer to let a function modify the caller's variable.
