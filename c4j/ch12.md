# Odds and Ends

This chapter covers a few remaining topics that do not fit neatly into earlier chapters but are important for writing real C programs.
You will learn when to use `exit` instead of `return`, how to handle errors without exceptions, how to think about pointer ownership (something Java's garbage collector hid from you), and how to sort with function pointers using `qsort`.

## `exit` vs `return`

\index{exit}

```c
void exit(int status);
```

You already know that `return` in `main` ends the program.
The `exit` function from `<stdlib.h>` does the same thing, but it can be called from *any* function --- not just `main`.
Java has the exact same thing: `System.exit(code)`:

```c
#include <stdio.h>
#include <stdlib.h>

void check_file(const char *path) {
    FILE *f = fopen(path, "r");
    if (f == NULL) {
        fprintf(stderr, "Fatal: cannot open %s\n", path);
        exit(1);   /* end the program immediately */
    }
    /* ... work with the file ... */
    fclose(f);
}
```

`exit` is useful when an error deep inside a call chain is unrecoverable and there is no reasonable way to propagate it back through multiple levels of callers.
In Java you would throw an exception; in C, `exit` is sometimes the pragmatic choice.

::: {.tip}
**Tip:** Use `exit` sparingly.
It is a blunt instrument --- it ends the entire program, bypassing any cleanup code in the functions that called you.
If you can reasonably return an error code back to `main` and let `main` handle it, prefer that.
Reserve `exit` for truly unrecoverable situations.
:::

### `atexit`

\index{atexit}

A C program can end from many places --- a `return` from `main`, or an `exit` call buried deep in a call chain.
If some cleanup must always happen --- removing a temporary file, saving state, restoring terminal settings --- you would have to remember to do it at every one of those exit points.
`atexit` solves this: register a cleanup function once, and `exit` calls it for you no matter where the program ends.
`exit` runs the registered functions first and then flushes all open `stdio` streams before terminating:

```c
int atexit(void (*func)(void));
```

You can register several handlers; they run in *reverse* registration order:

```c
void close_log(void)    { printf("log closed\n"); }
void remove_temp(void)  { printf("temp file removed\n"); }

int main(void) {
    atexit(close_log);     /* registered first, runs last */
    atexit(remove_temp);   /* registered last, runs first */
    printf("working...\n");
    exit(0);
}
```

Reverse order is deliberate: it unwinds resources opposite to the order you set them up, the same way Java's try-with-resources closes resources in reverse order.

`atexit` has real limitations.
Handlers take no arguments and return nothing, so anything they clean up must be reachable through file-scope variables.
Once registered, a handler cannot be unregistered.
And handlers only run on *normal* termination --- `exit` or a `return` from `main`.

::: {.tip}
**Trap:** A crash, `abort`, or a fatal signal (Ctrl-C sends one) skips `atexit` handlers entirely.
Do not rely on them to protect critical data --- write and flush important state as you go.
:::

::: {.tip}
**Tip:** Register a handler as soon as the resource it cleans up exists, and keep handlers small and independent.
Use `atexit` for process-lifetime cleanup: temporary files, terminal state, log files.
For releasing resources on an error path inside one function, use the `goto` cleanup pattern covered later in this chapter instead.
:::

## Pointer Ownership

\index{pointer!ownership}

In Java, the garbage collector manages memory for you.
When no more references point to an object, it gets cleaned up automatically.
In C, there is no garbage collector --- and no smart pointers either.
When a function hands you a pointer, you must ask yourself: **who owns this memory?**

There are three common patterns:

**1. The caller owns it (you must free).**
The function allocates memory and hands ownership to you:

```c
char *copy = strdup("Sweet Dreams (Are Made of This)");   /* Eurythmics, 1983 */
/* You own this memory. You must free it. */
free(copy);
```

**2. The library owns it (do not free).**
The function returns a pointer to memory it manages internally:

```c
struct hostent *h = gethostbyname("example.com");
/* The library owns this. Do NOT free it. */
```

**3. You own it --- you passed it in.**
You allocated (or declared) the memory and passed it to the function.
The function used it but did not take ownership:

```c
char buf[100];
fgets(buf, sizeof(buf), stdin);
/* You still own buf. Nothing to free --- it is on the stack. */
```

::: {.tip}
\index{dangling pointer}
\index{use-after-free}
\index{double free}
**Trap:** Always read the documentation for any C function that returns a pointer.
Look for words like "the caller must free the returned pointer" or "the returned pointer points to a static buffer."
Getting ownership wrong leads to memory leaks (never freeing) or double-free bugs (freeing memory you do not own).
Neither error is usually detected at compile time.
:::

## Error Handling Without Exceptions

\index{error handling!return codes}

In Java, you `throw` an exception and a `catch` block somewhere up the call stack handles it.
C has no exceptions.
Error handling is done through return codes, and cleanup is your responsibility.

The simplest pattern is to check return values and bail out:

```c
FILE *f = fopen("No Existe.txt", "r");
if (f == NULL) {
    perror("fopen");   /* prints: fopen: No such file or directory */
    return -1;
}
```

\index{errno}
\index{perror}
\index{strerror}
Many C library functions set the global variable `errno` (declared in `<errno.h>`) when they fail.
`perror` from `<stdio.h>` prints a human-readable message for the current `errno` value.
`strerror(errno)` from `<string.h>` gives you the message as a string if you need to format it yourself:

```c
#include <errno.h>
#include <string.h>

FILE *f = fopen("missing.txt", "r");
if (f == NULL) {
    fprintf(stderr, "Error opening file: %s\n", strerror(errno));
}
```

### The `goto` Cleanup Pattern

\index{goto}

What happens when a function acquires multiple resources and something fails partway through?
You need to release what you have already acquired, in the correct reverse order.
Java handles this with `try-finally` or `try-with-resources`; C uses `goto` to jump to cleanup labels.

You got a brief introduction to `goto` back in the control flow chapter.
Here it is in full:

```c
int process(const char *path) {
    int status = -1;

    FILE *f = fopen(path, "r");
    if (f == NULL) return -1;

    char *buf = malloc(1024);
    if (buf == NULL) goto close_file;

    char *line = malloc(256);
    if (line == NULL) goto free_buf;

    /* do work with f, buf, and line ... */
    status = 0;

    free(line);
free_buf:
    free(buf);
close_file:
    fclose(f);
    return status;
}
```

Each resource acquired gets a corresponding cleanup label placed below it.
If any allocation fails, control jumps to the label that releases everything acquired so far, in reverse order.
This pattern is used extensively in real C code --- including the Linux kernel.

::: {.tip}
**Wut:** Java programmers are taught to avoid `goto` entirely.
In C, the `goto` cleanup pattern is an accepted and widely-used idiom.
It is the closest thing C has to `try-finally` --- a structured way to ensure resources are always released even when errors occur partway through a function.
:::

The Java `try-finally` equivalent would look like this in pseudocode:

```
try {
    f = open file
    buf = malloc
    line = malloc
    do work
} finally {
    if line != null: free line
    if buf != null: free buf
    if f != null: close f
}
```

The C `goto` pattern achieves exactly the same result.

## `qsort` --- Function Pointers in Action

\index{qsort}

You learned about function pointers in chapter 7.
The most common place you will encounter them in the standard library is `qsort` from `<stdlib.h>`.
In Java, you pass a `Comparator` object to `Arrays.sort()`; in C, you pass a comparison function pointer to `qsort`:

```c
void qsort(void *base, size_t nel, size_t width,
           int (*compar)(const void *, const void *));
```

Here is a complete example sorting an array of integers:

```c
#include <stdio.h>
#include <stdlib.h>

int compare_ints(const void *a, const void *b) {
    int ia = *(const int *)a;
    int ib = *(const int *)b;
    return (ia > ib) - (ia < ib);   /* -1, 0, or 1 */
}

int main(void) {
    /* release years for some favorites */
    int years[] = {1983, 1979, 1985, 1987, 1983};   /* Blue Monday, Video Killed..., Walking on Sunshine, Never Gonna..., Sweet Dreams */
    int n = sizeof(years) / sizeof(years[0]);

    qsort(years, n, sizeof(int), compare_ints);

    for (int i = 0; i < n; i++) {
        printf("%d ", years[i]);
    }
    printf("\n");
    /* 1979 1983 1983 1985 1987 */
    return 0;
}
```

`qsort` takes four arguments: the array, the number of elements, the size of each element, and a pointer to a comparison function.
The comparison function receives `const void *` pointers and must cast them to the correct type.
It returns a negative value if the first argument should come before the second, zero if they are equal, and a positive value if the first should come after.

You can sort anything with `qsort` by writing a suitable comparison function.
Here is one that sorts strings:

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

int compare_strings(const void *a, const void *b) {
    const char *sa = *(const char **)a;
    const char *sb = *(const char **)b;
    return strcmp(sa, sb);
}

int main(void) {
    const char *songs[] = {
        "Sweet Dreams",
        "Master of Puppets",
        "Blue Monday",
        "Karma Chameleon"
    };
    int n = sizeof(songs) / sizeof(songs[0]);

    qsort(songs, n, sizeof(char *), compare_strings);

    for (int i = 0; i < n; i++) {
        printf("%s\n", songs[i]);
    }
    /* Blue Monday       */
    /* Karma Chameleon   */
    /* Master of Puppets */
    /* Sweet Dreams      */
    return 0;
}
```

Notice the double cast in `compare_strings`.
`qsort` passes a pointer *to* each array element.
Since each element is already a `char *`, what arrives at the comparison function is a `char **` disguised as `const void *`.

::: {.tip}
**Wut:** A common mistake in integer comparison functions is to write `return a - b`.
This can overflow when `a` and `b` have very different signs --- for example, `INT_MAX - (-1)` overflows to a negative number.
The idiom `(a > b) - (a < b)` is safe and always returns exactly -1, 0, or 1.
:::

## Try It: Odds and Ends Starter

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <errno.h>

/* sort integers, but put 1979 first (Video Killed the Radio Star year!) */
int compare_ints(const void *a, const void *b) {
    int ia = *(const int *)a;
    int ib = *(const int *)b;
    if (ia == 1979 && ib == 1979) return 0;
    if (ia == 1979) return -1;
    if (ib == 1979) return 1;
    return (ia > ib) - (ia < ib);
}

void goodbye(void) {
    printf("atexit: Hasta la vista!\n");
}

int main(void) {
    atexit(goodbye);

    /* function pointer */
    int (*cmp)(const void *, const void *) = compare_ints;
    int x = 10, y = 20;
    printf("compare(10, 20) = %d\n", cmp(&x, &y));

    /* qsort: Video Killed the Radio Star (1979) should sort first */
    int years[] = {1987, 1983, 1979, 1985, 1983};
    int n = sizeof(years) / sizeof(years[0]);
    qsort(years, n, sizeof(int), compare_ints);

    printf("Sorted: ");
    for (int i = 0; i < n; i++) {
        printf("%d ", years[i]);
    }
    printf("\n");

    /* pointer ownership: strdup allocates, you must free */
    char *copy = strdup("Master of Puppets");   /* Metallica, 1986 */
    printf("strdup: '%s'\n", copy);
    free(copy);

    /* errno and perror */
    FILE *f = fopen("/tmp/no_such_dir/no_such_file.txt", "r");
    if (f == NULL) {
        perror("fopen");   /* prints something like: fopen: No such file or directory */
    }

    /* goto cleanup pattern */
    printf("goto cleanup demo:\n");
    char *buf = malloc(100);
    if (buf == NULL) return 1;

    char *msg = malloc(50);
    if (msg == NULL) goto free_buf;

    snprintf(buf, 100, "Resource 1 OK");
    snprintf(msg,  50, "Resource 2 OK");
    printf("  %s, %s\n", buf, msg);

    free(msg);
free_buf:
    free(buf);

    return 0;
}
```

## Key Points

- Java has `System.exit(code)`; C has `exit(code)` from `<stdlib.h>`. Both terminate the process from anywhere.
- `exit` runs `atexit` handlers and then flushes `stdio` streams before terminating.
- In Java the garbage collector tracks ownership. In C, when you receive a pointer from a function you must determine who owns the memory and whether you need to call `free`.
- C has no exceptions. Use return codes to signal errors and check them at every level.
- Many library functions set `errno` on failure. Use `perror` or `strerror(errno)` to print a human-readable message.
- The `goto` cleanup pattern is the C idiom for releasing multiple resources in reverse order when an error occurs --- it is C's `try-finally`.
- `qsort` from `<stdlib.h>` sorts any array using a function pointer comparator --- the C equivalent of passing a `Comparator` to `Arrays.sort()`.
- The comparator receives `const void *` pointers; always cast to the correct type inside the function.
- Use `(a > b) - (a < b)` for safe integer comparison --- `return a - b` can overflow.

# Conclusion

You have covered a lot of ground --- from `printf` format specifiers all the way to file descriptors and pointer ownership.
Here are the key takeaways:

- **Java's syntax came from C.** Curly braces, semicolons, `if`/`for`/`while`, `switch` --- all of that is C.
- **`printf` and `scanf` replace `System.out` and `Scanner`.** Format specifiers must match argument types. `scanf` needs `&` for scalar variables.
- **C types are explicit.** No `String` class, no generics, no automatic boxing. You have basic types, `typedef`, arrays, and `struct`.
- **Control flow is nearly identical to Java** except there are no enhanced for loops, no iterators, and `goto` is an accepted idiom for cleanup.
- **Pointers hold memory addresses.** Use `&` to get an address, `*` to follow one, and `->` to access struct fields through a pointer. Every Java object reference is secretly a pointer.
- **All function arguments are pass-by-value.** To modify a caller's variable, pass a pointer to it. Java does the same thing --- object references are pointers passed by value.
- **Know where your memory lives.** Global variables last the whole program, local variables live on the stack, and `malloc` memory lives on the heap until you `free` it. Java's GC does this for you; in C it is your job.
- **Strings are `char` arrays** terminated by `'\0'`. You manage buffer sizes manually.
- **`stdio` provides buffered I/O** through `FILE *` pointers. Low-level I/O uses file descriptors (plain integers) and system calls like `read`, `write`, and `open`.
- **C has no exceptions.** Use return codes and `errno` for errors, and the `goto` cleanup pattern to release resources in reverse order.
- **Function pointers replace lambda-style callbacks.** `qsort` is the classic example --- pass a comparison function to sort any type, just like passing a `Comparator` to `Arrays.sort()`.
- **Always ask "who owns this pointer?"** Java's GC answered that question for you. In C, the answer comes from documentation, convention, and careful reading of the code.

Es un mundo nuevo, but you had the Java foundation to build on.
The syntax felt familiar; the idioms are just a little different.
Write small programs, compile them with `cc -Wall -Wextra -pedantic`, and listen to the warnings --- they are your best amigo.

Buena suerte --- you have got this.
