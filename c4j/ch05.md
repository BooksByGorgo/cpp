# Control Flow

\index{control flow}

Control flow in C will feel very familiar if you are coming from Java.
The `if`, `while`, `for`, and `switch` statements look almost identical.
Most of the syntax is the same, and the concepts transfer directly.

A few differences are worth knowing upfront.
C has no enhanced `for` loop (`for (Type x : collection)` does not exist).
C's `switch` statement only works with integer constants --- you cannot `switch` on a `String` as you can in Java.
\index{C89}
\index{C99}
In C89, all variable declarations had to appear at the top of a block before any statements --- C99 relaxed this and lets you declare variables anywhere, just like Java.

The biggest conceptual difference is that C has no native `bool` type.
Conditions are just integers: `0` is false, and any nonzero value is true.
The Java compiler rejects non-boolean conditions; C silently accepts any integer.

## `if` / `else`

\index{if statement}

The `if` statement in C looks identical to Java:

```c
int score = 85;

if (score >= 90) {
    printf("Excelente!\n");
} else if (score >= 70) {
    printf("Passing\n");
} else {
    printf("Try again\n");
}
```

The condition in an `if` is an integer expression.
Zero means false, nonzero means true.
C99 added `_Bool` and the convenience header `<stdbool.h>`, which defines `bool`, `true`, and `false`:

```c
#include <stdbool.h>

bool is_champion = true;
if (is_champion) {
    printf("You are the champion!\n");
}
```

\index{stdbool.h}

Without `<stdbool.h>`, C programmers traditionally use `int` for boolean values, with `0` for false and `1` (or any nonzero value) for true.

::: {.tip}
**Trap:** Because conditions are just integers in C, assignments inside `if` compile without error --- unlike Java, which rejects them:

```c
int x = 0;
if (x = 5) {              // BUG: assigns 5 to x, then tests 5 (nonzero = true)
    printf("oops\n");     // always prints
}
```

In Java, the compiler would reject this because `x = 5` is an `int`, not a `boolean`.
In C, it compiles quietly and always runs the body.
Compile with `-Wall` to catch this.
:::

## `while` and `do-while`

\index{while loop}
\index{do-while loop}

A `while` loop tests the condition *before* executing the body.
If the condition is false from the start, the body never executes:

```c
int countdown = 5;
while (countdown > 0) {
    printf("%d... ", countdown);
    countdown--;
}
printf("Vamos!\n");
// 5... 4... 3... 2... 1... Vamos!
```

A `do-while` loop tests *after* the body, guaranteeing at least one iteration.
This is useful when you need to perform an action before you can check whether to continue:

```c
#include <stdio.h>

int main(void) {
    int choice;
    do {
        printf("1) Rock  2) Paper  3) Scissors  0) Quit\n");
        printf("Enter choice: ");
        scanf("%d", &choice);
        printf("You picked %d\n", choice);
    } while (choice != 0);

    printf("Adios!\n");
    return 0;
}
```

The semicolon after `while (choice != 0)` is required --- forgetting it is a syntax error.

::: {.tip}
**Tip:** Use `do-while` when the loop body must execute at least once.
Menu loops and input validation loops are classic use cases.
If you find yourself duplicating code before a `while` loop just to set up the first test, a `do-while` is probably cleaner.
:::

## `break` and `continue`

\index{break}
\index{continue}

`break` and `continue` work the same as in Java.
`break` exits the nearest enclosing loop (or `switch`) immediately.
`continue` skips the rest of the current iteration and jumps to the next one.

```c
#include <stdio.h>

int main(void) {
    /* break example: stop at the first multiple of 7 */
    for (int i = 1; i <= 20; i++) {
        if (i % 7 == 0) {
            printf("Found it: %d\n", i);
            break;
        }
    }

    /* continue example: skip odd numbers */
    for (int i = 0; i < 10; i++) {
        if (i % 2 != 0)
            continue;
        printf("%d ", i);
    }
    printf("\n");
    // 0 2 4 6 8

    return 0;
}
```

`break` and `continue` only affect the innermost loop.
If you have nested loops and need to break out of an outer loop, you use a flag variable or, in some cases, `goto` (discussed later in this chapter).
Java has labeled `break` and `continue` for this purpose --- C does not.

## `for` Loops

\index{for loop}

The `for` loop has the same structure as in Java:

```c
for (init; condition; update) {
    /* body */
}
```

Here is a classic example iterating over an array:

```c
int scores[] = {90, 84, 77, 95, 88};
int n = sizeof(scores) / sizeof(scores[0]);

for (int i = 0; i < n; i++) {
    printf("Score %d: %d\n", i + 1, scores[i]);
}
```

\index{for loop!C89 vs C99}
C99 allows you to declare the loop variable inside the `for` statement, just like Java.
In C89, you had to declare it before the loop:

```c
/* C89 style */
int i;
for (i = 0; i < n; i++) {
    printf("%d\n", scores[i]);
}

/* C99 style --- preferred */
for (int i = 0; i < n; i++) {
    printf("%d\n", scores[i]);
}
```

::: {.tip}
**Tip:** C has no enhanced `for` loop.
Java's `for (int x : scores)` does not exist in C.
You always iterate with an index or a pointer.
The `sizeof(arr) / sizeof(arr[0])` idiom gives you the element count of a stack-allocated array.
This is why C functions that take arrays almost always take a separate `size` parameter --- a pointer does not carry size information.
:::

You can iterate over an array with a pointer instead of an index.
This is idiomatic C and worth getting comfortable with:

```c
int nums[] = {10, 20, 30, 40, 50};
int *end = nums + sizeof(nums) / sizeof(nums[0]);

for (int *p = nums; p < end; p++) {
    printf("%d ", *p);
}
printf("\n");
// 10 20 30 40 50
```

Any part of the `for` header can be omitted.
Omitting all three creates an infinite loop:

```c
for (;;) {
    /* runs forever --- use break to exit */
}
```

## `switch` Statements

\index{switch statement}
\index{switch statement!default}

A `switch` statement selects among multiple cases based on an integer expression.
The syntax looks like Java:

```c
#include <stdio.h>

int main(void) {
    int day = 5;

    switch (day) {
    case 1:
        printf("Monday --- Total eclipse of the heart\n");
        break;
    case 5:
        printf("Friday --- Let's go!\n");
        break;
    case 6:
    case 7:
        printf("Weekend\n");
        break;
    default:
        printf("Day %d\n", day);
        break;
    }

    return 0;
}
```

Each `case` must be an integer constant expression.
This is where C and Java differ most.
In Java (since Java 7), you can `switch` on a `String`:

```java
// Java --- works fine
switch (command) {
    case "quit": System.exit(0);
    case "help": printHelp();
}
```

In C, this does not compile.
You can only switch on integer types (`int`, `char`, `enum`, etc.):

```c
/* C --- only integer constants allowed */
switch (command[0]) {
case 'q':  exit(0);    break;
case 'h':  print_help(); break;
}
```

::: {.tip}
**Trap:** C's `switch` only accepts integer constants as case labels.
No strings, no floats, no variables.
If you need to dispatch on a string, use a chain of `if`/`else if` with `strcmp`.
:::

\index{switch statement!fall-through}
**Fall-through** is the most important thing to understand about `switch` in C.
If you forget a `break`, execution falls through to the next case.
This is sometimes intentional:

```c
char grade = 'B';

switch (grade) {
case 'A':
case 'B':
case 'C':
    printf("Passing\n");
    break;
case 'D':
case 'F':
    printf("Not passing\n");
    break;
default:
    printf("Invalid grade\n");
    break;
}
```

Here, cases `'A'`, `'B'`, and `'C'` all fall through to the same `printf`.
This is deliberate and a common pattern.
But accidental fall-through is a frequent bug:

```c
switch (x) {
case 1:
    printf("one\n");
    /* oops, forgot break --- falls into case 2 */
case 2:
    printf("two\n");
    break;
}
```

If `x` is `1`, this prints both `"one"` and `"two"`.

::: {.tip}
**Trap:** Every `case` should end with `break` unless you intentionally want fall-through.
When you do use intentional fall-through, add a comment like `/* fall through */` so the next reader knows it is deliberate.
Some compilers recognize this comment and suppress warnings.
:::

## `goto`

\index{goto}

In Java, `goto` is a reserved keyword but has no function --- the language does not support it.
In C, `goto` has a legitimate and widely used role: the **cleanup pattern**.
When a function acquires multiple resources (files, memory, locks) and something goes wrong partway through, `goto` provides a clean way to release everything in the correct order.

Here is a brief example:

```c
#include <stdio.h>
#include <stdlib.h>

int process(const char *path) {
    int status = -1;

    FILE *f = fopen(path, "r");
    if (!f) return -1;

    char *buf = malloc(1024);
    if (!buf) goto close_file;

    /* ... do work with f and buf ... */
    status = 0;

    free(buf);
close_file:
    fclose(f);
    return status;
}
```

If `malloc` fails, control jumps to `close_file`, which closes the file that was already opened.
Without `goto`, you would need deeply nested `if` statements or duplicated cleanup code.
The `goto` cleanup pattern is used extensively in production C code, including the Linux kernel.

::: {.tip}
**Tip:** The `goto` cleanup pattern is covered in detail in the Odds and Ends chapter.
For now, just know that `goto` in C is not the taboo it is in Java.
When used strictly for forward jumps to cleanup labels at the end of a function, it makes resource management clearer, not messier.
:::

`goto` has two restrictions: you can only jump within the same function, and you cannot jump over a variable declaration that has an initializer (in C99+).

## Try It: Control Flow Starter

```c
#include <stdio.h>

int main(void) {
    /* if / else */
    int score = 83;
    if (score >= 90) {
        printf("A --- excelente!\n");
    } else if (score >= 80) {
        printf("B --- muy bien\n");
    } else if (score >= 70) {
        printf("C --- passing\n");
    } else {
        printf("Not passing\n");
    }

    /* while */
    int n = 1;
    while (n <= 5) {
        printf("%d ", n);
        n++;
    }
    printf("\n");

    /* do-while: repeat until valid input */
    int guess;
    do {
        printf("Guess (1-10): ");
        scanf("%d", &guess);
    } while (guess < 1 || guess > 10);
    printf("You guessed %d\n", guess);

    /* for with break and continue */
    printf("Even numbers up to 20: ");
    for (int i = 1; i <= 100; i++) {
        if (i > 20)
            break;
        if (i % 2 != 0)
            continue;
        printf("%d ", i);
    }
    printf("\n");

    /* switch on a char */
    char grade = 'B';
    printf("Grade %c: ", grade);
    switch (grade) {
    case 'A':  printf("Perfect\n");      break;
    case 'B':  printf("Good work\n");    break;
    case 'C':  printf("Passing\n");      break;
    default:   printf("See advisor\n");  break;
    }

    return 0;
}
```

## Key Points

- C's control flow statements (`if`, `while`, `do-while`, `for`, `switch`) look almost identical to Java's.
- C uses integers for boolean conditions: `0` is false, nonzero is true. Unlike Java, C does not require conditions to be `bool`. Include `<stdbool.h>` for `bool`, `true`, and `false` (C99+).
- `break` exits the nearest loop or `switch`. `continue` skips to the next iteration. C does not have Java's labeled `break`/`continue`.
- C has no enhanced `for` loop. There is no `for (Type x : collection)`. Use index or pointer iteration.
- C's `switch` cases must be integer constants. You cannot switch on strings (unlike Java 7+). Watch for accidental fall-through.
- `goto` is legal and useful in C for the cleanup pattern --- forward jumps to release resources at the end of a function.
- In C89, variables had to be declared at the top of a block. C99 allows declarations anywhere (like Java).
