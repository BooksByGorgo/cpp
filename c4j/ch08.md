
# Allocating Memory

In Java, memory management is mostly invisible.
You write `new ArrayList<>()`, the JVM allocates space on the heap, and the garbage collector reclaims it when nothing refers to it anymore.
You almost never have to think about where a variable lives or how long it lasts.

C offers no such luxury.
There is no garbage collector.
There is no JVM.
Memory management is entirely your responsibility, and understanding where variables live --- and how long they last --- is fundamental to writing correct C programs.

## Global Variables

\index{global variable}

A **global variable** is declared outside of any function.
It is created when the program starts and exists until the program exits.
Every function in the file can see and modify it:

```c
#include <stdio.h>

int high_score = 0;   // global — lives for the entire program

void update_score(int points) {
    if (points > high_score)
        high_score = points;
}

int main(void) {
    update_score(3000);
    update_score(1500);
    printf("High score: %d\n", high_score);  // 3000
    return 0;
}
```

Global variables are initialized to zero automatically if you do not provide an initial value.

::: {.tip}
**Tip:** Use global variables sparingly.
When every function can read and write the same variable, bugs become harder to track down.
Prefer passing data through function parameters.
:::

## Static Global Variables

\index{static!global variable}

Marking a global variable `static` keeps its lifetime --- the entire program --- but limits its visibility to the file it is declared in:

```c
static int cache_hits = 0;   // only this .c file can see it
```

Without `static`, any other `.c` file can reach a global by declaring it `extern`.
With `static`, the variable is invisible outside its own file, so two files can each have their own `static int cache_hits` without clashing.
The closest Java equivalent is a `private static` field: program lifetime, visibility limited to the class.
If a global variable is only used inside one file, make it `static`.

::: {.tip}
**Wut:** `static` means two different things in C --- and neither matches Java's `static`, which means "belongs to the class, not an instance."
On a global variable it does not change lifetime (globals already live for the whole program) --- it hides the variable from other files.
On a local variable it does not change visibility --- it extends the lifetime, as you will see in Static Local Variables below.
:::

## Local Variables

\index{local variable}
\index{stack}

A **local variable** is declared inside a function or block.
It is created when the function is called and destroyed when the function returns.
Local variables live on the **stack** --- a region of memory that grows and shrinks automatically as functions are called and return.
You do not need to free stack memory; the runtime reclaims it automatically when the function exits.

```c
void play_song(void) {
    char title[] = "Maniac";   // local — gone when play_song() returns
    printf("Now playing: %s\n", title);
}
// title no longer exists here
```

In Java, local primitive variables also live on the stack.
What is different in C is that you can take the address of a local variable and pass it around --- which means you can accidentally hold onto a pointer to memory that has already been reclaimed.

::: {.tip}
**Trap:** Never return a pointer to a local variable.
The stack memory is reclaimed when the function returns, and the pointer becomes a **dangling pointer** --- it points to memory that no longer belongs to you:

```c
int *get_value(void) {
    int x = 42;
    return &x;   // BUG: x is destroyed when get_value() returns
}
```

This compiles, but using the returned pointer is undefined behavior.
:::

## Static Local Variables

\index{static local variable}
\index{static}

A **static local variable** has the scope of a local variable but the lifetime of a global.
Declare it with the `static` keyword inside a function.
It is created once when the program starts, retains its value between calls, and is only visible inside the function where it is declared:

```c
#include <stdio.h>

void count_calls(void) {
    static int count = 0;   // initialized once, persists between calls
    count++;
    printf("Called %d time(s)\n", count);
}

int main(void) {
    count_calls();   // Called 1 time(s)
    count_calls();   // Called 2 time(s)
    count_calls();   // Called 3 time(s)
    return 0;
}
```

Without `static`, `count` would be reset to `0` on every call.
\index{data segment}
With `static`, it lives in the **data segment** alongside global variables, but only `count_calls` can name it.

Java has no direct equivalent.
The closest analog is a private instance variable --- it persists as long as the object lives --- but `static` locals in C are shared across all calls to the function, not per-instance.

## Dynamic Allocation: `malloc` and `free`

\index{malloc}
\index{free}
\index{heap}
\index{stdlib.h}

Sometimes you need memory that outlives the function that created it, or memory whose size you do not know until the program is running.
For this, C provides `malloc` and `free` from `<stdlib.h>`.

`malloc` allocates a block of bytes on the **heap** and returns a pointer to it.
The heap is a pool of memory that persists until you explicitly release it:

```c
void *malloc(size_t size);
void  free(void *ptr);
```

In Java, `new int[5]` allocates an array of five integers.
In C, the equivalent is `malloc(5 * sizeof(int))`:

```c
#include <stdio.h>
#include <stdlib.h>

int main(void) {
    /* "All Night Long" — Lionel Richie (1983) */
    int *scores = malloc(5 * sizeof(int));
    if (scores == NULL) {
        printf("Allocation failed!\n");
        return 1;
    }

    for (int i = 0; i < 5; i++)
        scores[i] = (i + 1) * 100;

    for (int i = 0; i < 5; i++)
        printf("scores[%d] = %d\n", i, scores[i]);

    free(scores);   // release memory back to the system
    return 0;
}
```

\index{void pointer}
`malloc` returns a `void *` --- a generic, untyped pointer.
In C (unlike C++), a `void *` can be assigned to any pointer type without a cast.
If `malloc` cannot satisfy the request (out of memory), it returns `NULL`.
Always check for `NULL` after calling `malloc`.

::: {.tip}
**Tip:** In Java, `new` allocates memory and the garbage collector frees it automatically.
In C, there is no garbage collector.
If you call `malloc`, you **must** call `free` when you are done with the memory.
If you forget, you have a **memory leak** --- the memory is never returned to the system.
If you call `free` twice on the same pointer, you get undefined behavior.
If you use a pointer after freeing it, you get undefined behavior.
Memory management in C is entirely your responsibility.
:::

### `calloc`: Allocate and Zero

\index{calloc}

`calloc` is a variant of `malloc` that allocates memory and initializes every byte to zero:

```c
void *calloc(size_t count, size_t size);
```

```c
int *nums = calloc(5, sizeof(int));   // 5 ints, all initialized to 0
```

`calloc` also checks whether `count * size` would overflow before allocating.
`malloc(count * size)` silently wraps around on overflow, and you end up with a far smaller buffer than you asked for.

::: {.tip}
**Tip:** Reach for `calloc` whenever you want zero-initialized memory.
On Linux and other systems with demand-paged virtual memory, `calloc` can skip the explicit zeroing for large allocations because the kernel hands out fresh, already-zero pages.
This can be measurably faster than `malloc` followed by `memset`.
:::

### `realloc`: Resize an Allocation

\index{realloc}

`realloc` resizes a previously allocated block of memory:

```c
void *realloc(void *ptr, size_t size);
```

It may move the allocation to a new address if the existing block cannot grow in place.
The contents up to the old size are preserved.

::: {.tip}
**Trap:** Never assign the result of `realloc` directly back to the same pointer.
If `realloc` fails, it returns `NULL` while leaving the original allocation untouched.
Assigning `NULL` back to your pointer loses the only reference to the original block --- an instant memory leak.
Use a temporary pointer instead:

```c
int *tmp = realloc(scores, 10 * sizeof(int));
if (tmp == NULL) {
    // handle error — scores is still valid
} else {
    scores = tmp;
}
```
:::

## Working with Raw Memory

\index{memset}
\index{memcpy}
\index{string.h}

Two functions from `<string.h>` (yeah, it's a counterintuitive name...) operate on raw bytes rather than strings.
You will encounter them constantly in C code.

`memset` fills every byte in a block of memory with the same value.
It is most often used to zero out a buffer:

```c
void *memset(void *s, int c, size_t n);
```

```c
int buf[10];
memset(buf, 0, sizeof(buf));   // set all bytes to 0
```

`memcpy` copies `n` bytes from a source address to a destination address.
Unlike `strcpy`, it does not stop at a null byte --- you specify exactly how many bytes to copy:

```c
void *memcpy(void *dest, const void *src, size_t n);
```

```c
int src[]  = {10, 20, 30};
int dest[3];
memcpy(dest, src, sizeof(src));   // copy all 12 bytes (3 ints × 4 bytes)
```

Java programmers may miss having `System.arraycopy` for primitive arrays.
`memcpy` is the C equivalent when you know the regions do not overlap.

::: {.tip}
\index{memmove}
**Trap:** `memcpy` requires that source and destination do not overlap.
If they might overlap --- for example, shifting elements within the same array --- use `memmove` instead.
`memmove` handles overlapping regions correctly:

```c
void *memmove(void *dest, const void *src, size_t n);
```
:::

## Where Variables Live: A Summary

| Kind | Where | Lifetime | Example |
|:---|:---|:---|:---|
| Global | Data segment | Entire program | `int count = 0;` (outside functions) |
| Static global | Data segment | Entire program | `static int n = 0;` (outside functions) |
| Local | Stack | Until function returns | `int x = 5;` (inside a function) |
| Static local | Data segment | Entire program | `static int n = 0;` (inside a function) |
| Dynamic | Heap | Until you call `free` | `int *p = malloc(...)` |

## Try It: Memory Lifetimes

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

int call_count = 0;   // global — lives for the whole program

void track(const char *song) {
    static int plays = 0;   // static local — persists between calls
    plays++;
    call_count++;
    printf("[play %d] %s\n", plays, song);
}

int main(void) {
    /* "Flashdance... What a Feeling" — Irene Cara (1983) */
    track("Flashdance... What a Feeling");
    track("Maniac");
    track("Running with the Night");
    printf("Total calls: %d\n", call_count);

    /* Dynamic allocation */
    int n = 4;
    int *years = malloc(n * sizeof(int));
    if (years == NULL) return 1;

    years[0] = 1982;
    years[1] = 1983;
    years[2] = 1984;
    years[3] = 1985;

    /* Zero out and refill using memset + loop */
    memset(years, 0, n * sizeof(int));
    for (int i = 0; i < n; i++)
        years[i] = 1980 + i;

    for (int i = 0; i < n; i++)
        printf("years[%d] = %d\n", i, years[i]);

    free(years);
    return 0;
}
```

## Key Points

- Global variables are visible to all functions in the file and live for the entire program.
- A `static` global keeps the same lifetime but is visible only in its own file.
- Local variables live on the stack and are destroyed when their function returns.
- Static local variables have the scope of a local but the lifetime of a global.
- `malloc` allocates memory on the heap --- you must call `free` when done.
- `calloc` allocates and zeroes memory; `realloc` resizes an allocation.
- Always check that `malloc`/`calloc`/`realloc` did not return `NULL`.
- `memcpy` copies bytes between non-overlapping regions; use `memmove` for overlapping regions.
- `memset` fills a block of memory with a byte value.
- There is no garbage collector in C --- memory management is entirely your responsibility.
